# 招聘岗位初筛与候选人履历核查标准执行手册

## 1. 业务背景与角色定位
- **使用者角色**：招聘 HR / 用人部门业务面试官
- **触发场景**：收到候选人简历文本或表格，需要对照岗位 JD（职位描述）进行合规初筛时
- **业务价值**：自动核验硬性资格门槛，过滤履历断层风险，提炼针对性业务深挖问题

## 2. 前置输入契约 (Input Contract)
在开始分析前，必须确认用户已输入以下两项信息：
- **材料 1**：目标岗位 JD 说明书（必须包含：学历硬门槛、工作年限、核心专业技能要求）
- **材料 2**：候选人履历文本（已脱敏姓名、手机号等个人敏感隐私信息）

## 3. 分步标准作业流程 (SOP Execution Steps)
请严格按以下四步顺序逐步比对：
1. **第一步（硬性门槛核验）**：核对候选人学历、专业背景、最低工作年限。若不满足且无例外说明，直接标记为【不达标】。
2. **第二步（核心技能匹配度评分）**：逐项比对 JD 中的 3~5 项核心业务技能，提取候选人履历中的对应项目佐证。
3. **第三步（履历连续性与风险预警）**：
   - 检查工作履历是否存在超过 6 个月的空窗期；
   - 检查平均每段工作时间是否低于 1 年（频繁跳槽预警）。
4. **第四步（面试深度提问清单生成）**：基于候选人最出彩的项目或表述含糊的关键成果，生成 3 道可证伪的追问问题。

## 4. 业务红线与人在回路门禁 (Guardrails & HITL)
- **绝对禁止就业歧视**：严禁将年龄、性别、婚育状态、地域或民族作为初筛扣分理由；
- **强制暂停门禁 (HITL)**：
  - 遇到关键资质存疑（如学历认证异常、项目时间存在重叠矛盾）；
  - 核心技能完全匹配但薪资期望超出职级上限 30% 以上；
  - 必须暂停自动流转，提报 HR 负责人人工裁决是否发起背调。

## 5. 标准输出格式契约 (Output Format)
输出必须严格遵循以下结构化 Markdown：

### 一、 初筛结论 (PASS / PENDING / REJECT)
- **综合匹配度得分**：[85 / 100]
- **硬性门槛结论**：[符合 / 不符合]
- **核心亮点**：[用 2 句话概括最匹配的优势]
- **主要风险点**：[例如：近 3 年跳槽 2 次，空窗 4 个月]

### 二、 核心技能对比表
| JD 关键技能要求 | 候选人履历佐证 | 匹配等级 (完全满足 / 部分满足 / 未提及) |
| :---: | :---: | :---: |
| 熟悉 AI Agent 工作流编排 | 主导过客服 Agent 实施项目，有真实产出 | 完全满足 |

### 三、 建议业务复试提问清单 (3 题)
1. [针对项目的追问 1]
2. [针对空窗期或职责边界的追问 2]
3. [针对核心技术的实战考核题 3]
