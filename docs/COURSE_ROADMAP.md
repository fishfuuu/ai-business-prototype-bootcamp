## 1. 课程定位

课程目标不是培养程序员，也不是直接开发复杂 AI Agent，而是让运营主管能够：

1. 使用 Claude Code 从零创造自己想要的业务系统页面。
2. 用自然语言和参考截图持续修改系统。
3. 使用 Skills 提高需求分析、页面设计、调试和验证的稳定性。
4. 掌握少量必要的工程化习惯，防止项目越改越乱。
5. 使用 Codex 独立审查 Claude Code 的成果。
6. 判断页面中哪些环节适合普通功能、AI 功能或 AI Agent。
7. 完成一个带简单 AI 能力的业务系统 Demo。
8. 将经过验证的业务方法沉淀为可复用 Skill。

课程主线：

```text
从零创造系统
→ 做成自己想要的样子
→ 学会稳定控制 Agent
→ 跑通真实业务流程
→ 找到 AI 融入位置
→ 沉淀业务方法
```

## 3. 工具分工

### Claude Code

- 需求理解
- 页面制作
- 修改和调试
- 自测
- 项目说明

### Codex

- 从第 7 课开始重点使用
- 独立验收
- 代码和范围审查
- AI 功能输入、输出和人工确认审查

### 固定协作流程

```text
Claude Code 实现
→ Claude Code 自测
→ Codex 独立审查
→ Claude Code 修复经确认的问题
→ 主管最终验收
```

说明：第 1–6 课以 Claude Code 为主；第 7 课起系统引入 Codex 页面验收；第 8 课建立双 Agent 审查分工。

## 7. 每课详细路线

### 第 1 课：从零创造自己的业务系统

**与执行版关系：** 学员操作以 `docs/LESSON_01_GUIDE.md` 为准；本节保留教师视角与原稿目标。

#### 核心目标

第一节课结束时，学员需要产生明确感受：这个系统是按照我的业务想法创造出来的。  
不讲 Skill、Git、前端框架、数据库或 AI Agent。

#### 课堂内容

1. 描述想要的系统（名称、使用者、问题、首页信息、首要操作）。
2. 让 Claude Code 提出第一版结构（不先改代码）。
3. 学员选择和修改方案。
4. Claude Code 制作：系统名称、侧栏入口、首页、模拟数据。
5. 连续修改至少三次。

#### 使用工具或 Skill

- Claude Code  
- 本课不使用 Skill

#### 工程化内容

1. 第一版只使用模拟数据。  
2. 先完成可运行版本，不追求完整系统。

#### 课堂成果

- 从培训底座创建的系统雏形  
- 系统名称与菜单入口  
- 可运行首页  
- 至少一个核心信息区  
- 至少三次学员主动修改

#### 课后作业

增加一个自己每天真正想看的模块或信息块。

#### 通过标准

学员能够说明：

- 系统为什么这样设计  
- 哪些内容来自自己的业务判断  
- 下一步最想增加什么  

（与 `LESSON_01_GUIDE.md` 完成标准一致：新业务页面、侧栏入口、模拟数据、可操作交互、typecheck/build 通过。）

---

### 第 2 课：用参考图做出像样的企业页面

#### 核心目标

学会使用参考图、现有系统和草图控制页面效果，而不是只说“做得好看一点”。

#### 课堂内容

- 准备脱敏参考截图  
- 让 Claude Code 分析信息层级与取舍  
- 使用计划中的 `frontend-design` 完成页面调整  
- 对照并遵守项目 `DESIGN.md`

#### 使用工具或 Skill

- Claude Code  
- `frontend-design`（计划使用，正式授课前需完成名称、来源和版本验证）

#### 工程化内容

- `DESIGN.md` 是长期规则，不是一次提示词  
- 风格、间距、状态色、禁止效果

#### 课堂成果

- 经参考图优化的页面  
- 简单设计取舍说明

#### 课后作业

选一个熟悉系统页面，制作运营版本并记录保留/删除/增加及理由。

#### 通过标准

页面已转化为自己的业务系统，而不是简单照抄截图。

---

### 第 3 课：让 Agent 帮助自己想清楚需求

#### 核心目标

从“大概想法”走到“Agent 可以稳定执行”。

#### 课堂内容

- 用 `grill-me`（计划使用）逐问澄清需求  
- 形成简化业务功能卡（名称、使用者、问题、内容、操作、规则、范围、验收）

#### 使用工具或 Skill

- Claude Code  
- `grill-me`（计划使用，正式授课前需完成名称、来源和版本验证）

#### 工程化内容

1. 需求必须有明确使用者  
2. 功能必须解决具体问题  
3. 范围包含“做什么”和“不做什么”  
4. 完成可通过页面操作验证

#### 课堂成果

一份可交给 Claude Code 实现的业务功能卡。

#### 课后作业

选真实业务功能，完成需求梳理。

#### 通过标准

未参与讨论的人只看功能卡也能基本理解要做什么。

---

### 第 4 课：把大需求拆成连续的小成功

#### 核心目标

避免一次修改过多导致跑偏、难定位、失去控制。

#### 课堂内容

- 将大需求拆为 3–5 个可独立验证步骤  
- 使用 `incremental-implementation`（计划使用）产出计划  
- 每步：实现 → 验证 → 再继续

#### 使用工具或 Skill

- Claude Code  
- `incremental-implementation`（计划使用，正式授课前需完成名称、来源和版本验证）

#### 工程化内容

```text
需求 → 拆分 → 确认计划 → 实现一步 → 验证一步 → 保存一步
```

#### 课堂成果

由三至五个步骤完成的业务功能。

#### 课后作业

拆解下一功能，只实现第一步并验证。

#### 通过标准

每一步都能独立说明目标和完成结果。

---

### 第 5 课：建立不会轻易失控的项目

#### 核心目标

理解最少但必要的工程纪律。本课不新增 Skill。

#### 课堂内容

六条规则：一次一目标、改前确认范围、不擅自换框架、不擅自加依赖、改后验证、稳定后再继续。  
介绍 `CLAUDE.md`、`DESIGN.md`，以及计划中的 Codex 规则文件；建立“检查点 / 稳定版本 / 共享交付”的概念（GitHub 对学员为进阶，不强制）。

#### 使用工具或 Skill

- Claude Code  
- 本课无新增 Skill

#### 工程化内容

- 固定完成报告：改了什么、验证了什么、未验证什么  
- 稳定版本保存后再改

#### 课堂成果

- 对项目规则的理解  
- 一次完整修改与验证记录  
- 一个可回退的稳定状态（ZIP 或本地备份/进阶者可用 Git）

#### 课后作业

尝试一种明显不同的页面方案，决定保留或回退并说明理由。

#### 通过标准

学员能解释如何避免 Agent 越改越乱。

---

### 第 6 课：学会定位和修复问题

#### 核心目标

不再害怕错误，也不让 Agent 盲目尝试修改。

#### 课堂内容

- 使用问题报告卡  
- 使用 `diagnosing-bugs`（计划使用）按复现→证据→根因→最小修复→再验证

#### 使用工具或 Skill

- Claude Code  
- `diagnosing-bugs`（计划使用，正式授课前需完成名称、来源和版本验证）

#### 工程化内容

- 没有复现不直接改  
- 没有根因不连续试错  
- 修复不等于顺便重构

#### 课堂成果

成功定位并修复一个真实页面问题。

#### 课后作业

提交问题报告与修复前后证据。

#### 通过标准

能清楚描述问题，而不是只说“页面坏了”。

---

### 第 7 课：让 Agent 实际操作页面完成验收

#### 核心目标

代码写完不代表功能完成，必须真实操作页面。

#### 课堂内容

- 选择一条完整业务流程  
- Claude Code 用 `webapp-testing`（计划使用）自测  
- Codex 用 `playwright-interactive`（计划使用）独立验证同一流程

#### 使用工具或 Skill

- Claude Code：`webapp-testing`（计划使用，正式授课前需完成名称、来源和版本验证）  
- Codex：`playwright-interactive`（计划使用，正式授课前需完成名称、来源和版本验证）

#### 工程化内容

验收证据：步骤、预期、实际、截图、失败项、未验证项。

#### 课堂成果

Claude Code 与 Codex 分别完成的页面验收记录。

#### 课后作业

找同事在无口头说明下使用 Demo，记录两个主要问题。

#### 通过标准

至少一条真实业务流程通过页面操作验证。

---

### 第 8 课：Claude Code 开发，Codex 独立审查

#### 核心目标

建立明确双 Agent 分工，而不是两个 Agent 同时随意修改。

#### 课堂内容

- Claude Code 实现完整动作并自测报告  
- Codex 用 `code-review-and-quality`（计划使用）只审不改  
- 学员判断阻断/重要/建议，再授权修复

#### 使用工具或 Skill

- Claude Code  
- Codex：`code-review-and-quality`（计划使用，正式授课前需完成名称、来源和版本验证）

#### 工程化内容

```text
Claude Code：实现和自测
Codex：质疑和独立审查
运营主管：最终业务判断
```

#### 课堂成果

实现 → 自测 → 独立审查 → 判断 → 修复 → 最终验收 的一轮闭环。

#### 课后作业

让 Codex 审查现有 Demo，选两个真正重要问题交给 Claude Code 修复。

#### 通过标准

学员不会机械接受所有 Agent 建议。

---

### 第 9 课：判断系统中哪些位置适合加入 AI

#### 核心目标

理解普通功能、AI 功能和 AI Agent 的区别。**本课不实现复杂 Agent。**

#### 课堂内容

- 区分三类能力  
- 逐页分析现有 Demo  
- 建立 AI 机会卡并选出优先场景

#### 使用工具或 Skill

- Claude Code  
- 本课以分析方法为主，无强制新 Skill

#### 工程化内容

每个 AI 功能必须明确：输入、输出、不发送内容、结构化方式、失败处理、人工确认、禁止动作。

#### 课堂成果

- 三个 AI 机会  
- 一个优先实现目标  
- 一份完整 AI 机会卡

#### 课后作业

准备示例输入、理想输出、错误输出、人工修改示例、确认规则。

#### 通过标准

选中场景输入明确、输出可检查、错误可人工纠正。

---

### 第 10 课：加入第一个 AI 功能并沉淀业务 Skill

#### 核心目标

完成从普通业务系统到带 AI 能力 Demo 的第一次升级。

#### 课堂内容

- 实现可人工确认的 AI 草稿生成流程  
- 使用 `skill-creator`（计划使用）沉淀业务 Skill  
- 完成 IT 工程化交接清单与结业演示

#### 使用工具或 Skill

- Claude Code  
- `skill-creator`（计划使用，正式授课前需完成名称、来源和版本验证）

#### 工程化内容

- Prompt 是系统资产  
- AI 输入受控、输出结构化  
- 人工确认是正式工作流  
- Demo 验证价值；IT 负责正式数据、权限、安全、部署

#### 课堂成果

- 带 AI 能力的业务系统 Demo  
- 一个业务 Skill  
- AI 功能验收记录  
- IT 工程化交接清单

#### 课后作业 / 结业

按结业演示清单完成 10 分钟演示。

#### 通过标准

见第 9 节课程成果；AI 功能可演示且标明模拟/未连真实服务。

## 8. 固定课堂结构

每周建议 90 分钟：

```text
10 分钟：展示本课可以完成的成果
15 分钟：教师演示本课方法或 Skill
45 分钟：学员在自己的项目中实际操作
10 分钟：运行验证或 Codex 审查
10 分钟：保存成果并布置作业
```

原则：

- 理论讲解不超过 25 分钟  
- 每节课至少一半时间由学员亲自操作  
- 每节课必须产生肉眼可见变化  
- 作业 30–45 分钟，只提交一个明确成果  

**具体单节课可按学员进度调整，但不得取消实际操作和结果验证。**

## 9. 课程成果

学员最终提交：

1. 一个从空白业务工程创造出来的系统 Demo。  
2. 至少三个相互关联的业务页面。  
3. 至少一条完整业务操作流程。  
4. 一个可人工确认的 AI 功能。  
5. 一份业务功能说明。  
6. 一份页面验收记录。  
7. 一次 Claude Code 开发、Codex 审查记录。  
8. 一个自定义业务 Skill。  
9. 一份 IT 工程化交接清单。  
10. **一个可交付的业务系统 Demo，可通过标准 ZIP 包、本地项目目录或独立私有 GitHub 仓库提交。**

```text
是否敢于从零创造系统
是否能把业务问题转化为页面
是否能稳定控制 Claude Code
是否能使用 Skills 提高执行质量
是否具备最基本的工程纪律
是否能使用 Codex 独立验收
是否能判断 AI 应该放在哪里
是否能把业务经验沉淀为 Skill
```
