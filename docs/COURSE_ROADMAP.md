## 1. 课程定位与终局目标

### 核心定位

课程目标不是培养专业的 Vue/TypeScript 程序员，而是借助 Coding Agent（Claude Code / Codex），将运营主管培养为“超级业务产品经理（Super Business PM）”。

主管不需要去搞底层的生产服务器运维或复杂并发代码，而是要掌握：
1. **高保真原型控盘能力**：在 2 小时内用自然语言 + AI 跑出可运行、可点击、带模拟数据的高保真原型系统。
2. **需求与数据契约表达能力**：将口头需求标准化为《业务功能卡》、数据契约与明确的输入/输出边界。
3. **工程纪律与防崩救回能力**：掌握 Git 存档、版本恢复、`CLAUDE.md` 护栏与五层 Bug 诊断力，防止项目越改越乱。
4. **证据驱动的验收与审查能力**：基于四类客观证据（视觉、行为、工程、范围）完成自动化验收，并基于 Commit/Diff 引导 Codex 进行独立代码审查。
5. **AI 场景裁决与 IT 交接能力**：准确判断普通功能、AI 辅助与 AI Agent 边界（坚持 HITL 人在回路确认），在结业时输出让 IT 部门直接可落地的《IT 原型交接包》。

---

### 训练营支持的三类业务原型

训练营全课程（特别在第 3、5、6、7、8 课）持续贯穿支持三类典型业务原型，学员可根据自己部门的真实业务场景自由选择：
1. **A. 监控与决策型**：适合经营分析、异常监控、投产分析、履约预警（看指标 -> 看异常 -> 下钻明细 -> 做出决策）。
2. **B. 任务与流程型**：适合预算申请、退货处理、工单派发、单据审批（创建记录 -> 处理任务 -> 状态流转 -> 推进下一步）。
3. **C. 操作工具型**：适合文案生成、规则计算、数据整理、格式转换（输入 -> 规则处理 -> 结果输出 -> 人工确认/复制/导出）。

## 3. 工具分工与角色契约

### 1. Claude Code（主要实施者）
- 需求理解与方案复述
- 页面与组件创建
- 交互逻辑修改与增量实现
- 本地调试与自测验证 (`verify-project.ps1`)

### 2. Codex（独立审查者）
- 从第 8 课开始正式引入（基于 `AGENTS.md` 规范）
- 审查稳定基线 Commit 到 Candidate Commit 的 Diff
- 检查隐患、逻辑越界与未授权的范围修改
- 提供独立审查意见（并非最终决策者）

### 3. 主管（最终裁决者 / 人在回路盖章官）
- 掌控 Workflow 推进阶段
- 行使 Keep / Omit / Remove / Modify 裁决权
- 对 Codex 审查意见做出四个决定：接受、拒绝、延期、超出本次范围
- 签署人在回路授权，完成最终业务验收

```text
Claude Code 增量实现 -> Candidate Commit -> Codex 独立审查 Diff -> 主管裁决盖章 -> Claude 修复新 Commit
```

## 6. 每课详细路线

### 第 1 课：从业务问题创建第一个系统页面
* **定位**：零基础学员建立三类业务原型分类认知、AI Agent 人机协作认知与数据安全红线。
* **主要内容**：
  1. 工具预检：确认工程底座环境正常、依赖已完备。
  2. 选择“A. 监控与决策型 / B. 任务与流程型 / C. 操作工具型”原型方向并输入业务上下文。
  3. **初始化 `docs/PROJECT_STATE.md`**：记录系统名称、使用者、原型类型、核心业务问题及敏感级别。
  4. 遵照模拟数据红线，在 Workflow 人在回路门禁授权下生成首个包含侧栏菜单与 Mock 数据信息的系统雏形。
* **执行文档**：[LESSON_01_GUIDE.md](LESSON_01_GUIDE.md) 与 [LESSON_01_TEACHER_PLAN.md](LESSON_01_TEACHER_PLAN.md)。

---

### 第 2 课：用参考图与设计规则做出像样的企业页面
* **定位**：根据业务目的选择最契合的信息结构与参考图，完成标准化视觉美化，并掌握基础 Git 存档操作。
* **课堂时间分配 (标准课堂 90 分钟，学员实操 50 分钟)**：
  - **Task 1：提取结构与基线存档 (15 分钟)**：检查 `git status`；必要时 `git init`；提交第一课成果与 `PROJECT_STATE.md`（基线提交）；分析参考图信息层级。
  - **Task 2：规范映射 (15 分钟)**：结合 `DESIGN.md` 设计规范，映射 Token 与组件，禁止继承参考图杂乱颜色。
  - **Task 3：视觉裁决与修改 (10 分钟)**：主管下达 Keep / Omit / Remove / Modify 取舍指令，授权 Agent 使用 `frontend-design` 重构。
  - **Task 4：对比验证与成果存档 (10 分钟)**：运行验证；查看 `git diff` 确认范围；`git add` & `git commit` 保存成果版本；运行 `git log --oneline` 查看历史。
* **Git 教学边界**：只教 `git status`, `git init`, `git add`, `git commit`, `git log --oneline`, `git diff` 6 个本地命令。不教 GitHub 分支、PR、Merge 或 Rebase。

---

### 第 3 课：让 Agent 帮助自己想清楚需求
* **定位**：把口头模糊需求标准化为可被 Agent 稳定执行的规范要求，完成数据契约与验收标准前置。
* **主要内容**：
  1. 使用 `grill-me` 与 Agent 进行 3–5 轮澄清对话，产出《业务功能卡》。
  2. **轻量数据契约卡**：明确字段名称、业务含义、数据类型、是否必填、数据来源（Mock/未来API）、示例值、校验规则、敏感等级。
  3. **三类原型契约扩展**：
     - *监控决策型*：增加指标口径、时间范围、对比基准、异常阈值、下钻维度。
     - *任务流程型*：增加角色、业务状态、允许动作、状态迁移规则、驳回/撤销。
     - *操作工具型*：增加输入结构、校验规则、处理逻辑、输出结构、失败状态。
  4. **验收标准前置**：在需求卡中写明客观验收步骤与预置期望。

---

### 第 4 课：把大需求拆成连续的小成功
* **定位**：掌握不同类型业务原型的增量拆解与开发节奏，树立“数据接口意识”。
* **主要内容**：
  1. 将《业务功能卡》拆解为 3–5 个连续小步骤。
  2. **数据接口意识**：明确“页面不是数据源，真实数据未来由 API 提供”。坚持使用 Mock 数据，在 Vue 页面中显式实现 4 种页面状态：`Loading`（正在获取）、`Empty`（没有数据）、`Success`（正常显示）、`Error`（获取失败）。
  3. **固定增量流程**：定义数据结构 -> 编写空壳 UI -> 连通数据与交互 -> 执行 L3 验收步 -> `git commit` 保存一步。

---

### 第 5 课：建立不会轻易失控的项目
* **定位**：建立文件结构心理地图、项目安全护栏与 Git 恢复能力。
* **三类原型分支护栏**：
  - *监控决策型*：锁定指标计算逻辑与数据源文件，防止 Agent 修改全局 Store。
  - *任务流程型*：锁定状态机定义与权限配置文件，防止 Agent 绕过状态校验。
  - *操作工具型*：锁定规则处理函数与解析库，防止 Agent 随意替换核心算法。
* **核心内容**：
  1. 识别 Vue 3 项目 3 个核心盒子（页面 `pages/`、组件 `components/`、导航 `router/`）。
  2. **引入 `CLAUDE.md` 项目护栏**：明确未经授权不得安装新依赖、不得修改环境变量/密钥、不得更换框架、不得将 Token 写入代码、不得提交敏数据。
  3. **版本权威与恢复**：Git Commit 是正式存档与恢复手段（`git log`, `git diff`, `git checkout/restore`）；教师提供的 `Checkpoint` 脚本仅作为学员无法完成 Git 恢复时的紧急保底工具。（注：`AGENTS.md` 留待第 8 课引入）。

---

### 第 6 课：学会定位和修复问题
* **定位**：面对 Bug 或 AI 改错逻辑时的标准化五层排错方法论与回归验证。
* **三类原型 Bug 诊断案例分支**：
  - *监控决策型*：指标计算错误、筛选器联动失效、趋势图数据失真。
  - *任务流程型*：状态无法迁移、非法角色能够提交、驳回后数据丢包。
  - *操作工具型*：输入格式校验穿透、算法处理报错、输出拷贝格式损坏。
* **核心内容**：
  1. **五层诊断卡**：
     - ① 页面与样式层（布局错位、颜色错误）
     - ② 组件与状态层（点击无反应、数据不同步）
     - ③ 路由与页面层（页面打不开、白屏）
     - ④ 数据与接口层（无数据、字段不一致、 Mock 报错）
     - ⑤ 环境与依赖层（启动失败、构建报错）
  2. 观察窗口：页面预览、浏览器 Console、PowerShell 终端。
  3. 执行 `diagnosing-bugs` 流程：复现现象 -> 确定层级与堆栈 -> 提出最小修复方案 -> 重新执行 L3 验收标准做回归测试。拒绝盲目重构或连续试错。

---

### 第 7 课：让 Agent 实际操作页面完成验收
* **定位**：使用自动化测试工具验证真实前端交互与流程连通性，生成客观证据链。
* **三类原型自动化验收模板**：
  - *监控决策型*：自动切换筛选条件 -> 断言指标数值变化 -> 点击下钻 -> 验证明细表格。
  - *任务流程型*：自动填写申请 -> 提交 -> 切换审批角色 -> 执行同意/驳回 -> 验证状态字段更新。
  - *操作工具型*：自动输入测试文本/文件 -> 点击处理 -> 断言 Loading 状态 -> 验证结构化输出 -> 触发复制/确认。
* **核心内容**：
  1. 将第 3 课定义的验收标准转化为 `webapp-testing` / Playwright 自动化脚本。
  2. **产出四类验收证据链**：
     - 视觉证据：前后对比截图
     - 行为证据：DOM 操作与测试记录
     - 工程证据：`verify-project.ps1` (Typecheck & Build) Clean 证明
     - 范围证据：`git diff` 改动清单

---

### 第 8 课：Claude Code 开发，Codex 独立审查
* **定位**：建立双 Agent 协作规范与独立审查机制。
* **三类原型 Codex 审查重点**：
  - *监控决策型*：重点审查计算口径是否有硬编码伪造、指标联动是否存在内存泄露。
  - *任务流程型*：重点审查状态迁移逻辑是否存在越权漏洞、驳回逻辑是否清理了历史状态。
  - *操作工具型*：重点审查边缘输入校验是否完备、失败兜底是否完整。
* **核心内容**：
  1. **引入 `AGENTS.md` 审查规范**：明确 Codex 的审查规则。
  2. **基于 Commit/Diff 的审查流程**：
     - Claude Code 实现功能并自测过关，提交为 Candidate Commit (`git commit -m "feat: candidate implementation"`)。
     - Codex 独立审查上一个稳定 Commit 到 Candidate Commit 的 Diff，按阻断/重要/建议分类。
     - 主管行使最终裁决权，做 4 种决定：接受、拒绝、延期、超出本次范围。
     - Claude Code 仅修复主管裁决接受的问题，并重新提交新 Commit。

### 第 9 课：业务 Agent 场景判断与产品设计
* **定位**：理清 AI 能力在三类原型流程中的最佳落脚点，建立 AI 安全边界与 HITL。
* **主要内容**：
  1. **三类原型 AI 场景落脚点**：
     - *监控决策型*：异常数据总结、归因建议草稿、下钻分析提示。
     - *任务流程型*：表单智能分类、风险审批建议、驳回原因草稿。
     - *操作工具型*：文本生成/改写、复杂规则解析、转换结果智能校验。
  2. **AI 安全边界与 HITL 门禁**：
     - 输入边界：明确允许和禁传给 AI 的敏感字段。
     - 输出格式：强制采用 JSON 结构化草稿返回。
     - 失败兜底：显示生成状态，失败时友好降级。
     - 人类确认（HITL）：AI 生成内容标注显眼标识，未经主管人工点击“确认/采纳”前，绝对禁止直接写入底层核心数据。

### 第 10 课：落地有限 AI 功能与 IT 交接
* **定位**：最小 AI 闭环演示、可选 Skill 扩展与 IT 原型交接包输出。
* **主要内容**：
  1. **落地一个最小 AI 闭环**：实现一个有限输入 -> AI 处理 -> 结构化草稿返回 -> 主管人工确认/编辑 -> 确认保存（带失败兜底与 3-5 个测试用例）。
  2. **[可选扩展] 封装业务 Skill**：Skill 是加速工具，不占用必修 90 分钟。学有余力的学员可使用 `skill-creator` 将已验证稳定的提示词和步骤封装为 Skill。
  3. **输出《IT 原型交接包》**：包含业务目标、用户角色、页面与流程、数据契约字段、AI 输入输出契约、HITL 确认点、安全与权限要求、四类验收证据链与当前未实现清单。交付 IT 部门开发落地。
