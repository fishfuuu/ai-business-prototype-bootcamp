## 1. 课程定位与终局目标

### 核心定位

课程目标不是培养专业的 Vue/TypeScript 程序员，而是借助 Coding Agent（Claude Code / Codex），将运营主管培养为“超级业务产品经理（Super Business PM）”。

主管不需要去搞底层的生产服务器运维或复杂并发代码，而是要掌握：
1. **高保真原型控盘能力**：在 2 小时内用自然语言 + AI 跑出可运行、可点击、带模拟数据的高保真原型系统。
2. **需求精细化表达能力**：将模糊的业务口头需求标准化为《业务功能卡》与输入/输出边界。
3. **AI 场景裁决能力**：准确判断业务流程中哪些环节放普通功能、哪些放 AI 辅助、哪些放 Agent 自动化。
4. **IT 开发无缝对接能力**：在结业时不仅产出原型，更自动生成让 IT 部门大加赞赏的《IT 开发对接说明书 (PRD)》，彻底打通业务与技术落地的最后一公里。

### 训练营支持的三类业务原型

训练营全课程统一支持三类典型业务原型，学员可根据自己部门的真实业务场景自由选择：
1. **A. 监控与决策型**：适合经营分析、异常监控、投产分析、履约预警（看指标 -> 看异常 -> 下钻明细 -> 做出决策）。
2. **B. 任务与流程型**：适合预算申请、退货处理、工单派发、单据审批（创建记录 -> 处理任务 -> 状态流转 -> 推进下一步）。
3. **C. 操作工具型**：适合文案生成、规则计算、数据整理、格式转换（输入 -> 规则处理 -> 结果输出 -> 人工确认/复制/导出）。

三类原型共享同一套：人机协作门禁、需求澄清、增量开发、工程验证与 AI 场景判断方法。Agent 可以在主管下达的已授权范围内组织多步行动与调用 Tools，并依据验证结果调整下一步。

### 课程主线：
```text
从业务问题出发
→ 选择原型类型并搭建雏形 (第 1 课)
→ 根据业务目的选择信息结构与参考图美化 (第 2 课)
→ 澄清需求与增量开发 (第 3-4 课)
→ 工程防护与故障定位 (第 5-6 课)
→ 自动化验收与双 Agent 审计 (第 7-8 课)
→ 融入 AI 能力与交付 IT 说明书 (第 9-10 课)
```

## 3. 工具分工与角色契约

### 1. Claude Code（核心开发助手）
- 需求理解与方案复述
- 页面与组件创建
- 交互逻辑修改与调优
- 运行工程自测与本地调试

### 2. Codex（独立审查专家）
- 从第 7 课开始重点引入
- 独立页面与功能验收
- 代码质量与工程规范审计
- 发现隐藏 Bug 与越界修改

### 3. 主管（最高 CEO / 人在回路盖章官）
- 掌控 Workflow 推进阶段
- 行使 Keep / Omit / Modify 裁决权
- 在人在回路确认门禁下达授权
- 做出最终业务验收

```text
Claude Code 方案与实现 -> 运行 verify 脚本自测 -> Codex 独立审查 -> 主管人在回路盖章验收
```

### 双轨交付

**教师和维护者**
- 使用私有 GitHub 课程母仓库
- 通过分支、PR 和标签维护稳定版本

- 默认可使用标准 ZIP 学员包
- 不强制安装 Git 或注册 GitHub
- 首次使用需运行 `npm ci` 安装依赖，双击 `start-project.bat` 在 `http://127.0.0.1:8888` 本地试衣镜预览
- GitHub 协作作为进阶工程化能力，不是第一课前置条件

## 6. 每课详细路线

### 第 1 课：从业务问题创建第一个系统页面
* **定位**：零基础学员建立三类业务原型分类认知与 AI Agent 人机协作认知。
* **主要内容**：选择“A. 监控与决策型 / B. 任务与流程型 / C. 操作工具型”原型方向并输入业务上下文，体验从 LLM 推理到 Tools 读取 `CLAUDE.md`，在 Workflow 人在回路门禁授权下生成首个包含侧栏菜单与 Mock 数据信息的系统雏形。
* **执行文档**：[LESSON_01_GUIDE.md](LESSON_01_GUIDE.md) 与 [LESSON_01_TEACHER_PLAN.md](LESSON_01_TEACHER_PLAN.md)。

### 第 2 课：用参考图与设计规则做出像样的企业页面
* **定位**：根据业务目的（监控与决策页、任务与流程工作台、操作工具与助手页）选择最契合的信息结构与参考图，对第 1 课生成的原型进行标准化视觉美化。
* **主要内容**：
  1. 根据业务目的提供脱敏参考截图或示范图卡（监控与决策页 `ref-monitor-decision.png`、任务与流程工作台 `ref-task-workflow.png`、操作工具与助手页 `ref-operation-tool.png`），进行多模态视觉结构提取；
  2. 结合 `DESIGN.md` 设计系统规则，禁止继承参考图杂乱颜色，强制 100% 映射变量；
  3. 主管下达 Keep / Omit from Reference / Remove from Current Page / Modify 取舍指令，授权 Agent 重构页面；
  4. 试衣镜预览与 1 次人在回路视觉微调闭环。

### 第 3 课：让 Agent 帮助自己想清楚需求
* **定位**：把口头模糊需求标准化为可被 Agent 稳定执行的规范要求。
* **主要内容**：使用 `grill-me` 与 Agent 进行 3–5 轮澄清对话，自动产出《业务功能卡》。针对流程型增加发起角色、处理角色、当前状态、允许动作与状态转换条件；针对工具型增加输入、处理规则、输出与人工确认。

### 第 4 课：把大需求拆成连续的小成功
* **定位**：掌握不同类型业务原型的增量拆解与开发节奏。
* **主要内容**：将《业务功能卡》拆解为 3–5 个连续的小步骤（监控型：筛选 -> 指标/异常 -> 明细 -> 决策动作；流程型：列表 -> 表单/详情 -> 处理动作 -> 状态更新；工具型：输入 -> 参数 -> 执行 -> 结果 -> 确认/导出），每完成一步进行一次确认与验证。

### 第 5 课：建立不会轻易失控的项目
* **定位**：建立文件结构心理地图与工程防崩能力。
* **主要内容**：
  1. 识别 Vue 3 项目 3 个核心盒子（页面 `pages/`、组件 `components/`、导航 `router/`）；
  2. 掌握 `save-checkpoint.ps1` 与 `reset-checkpoint.ps1` 脚本，代码改崩时秒级恢复安全快照。

### 第 6 课：学会定位和修复问题
* **定位**：面对 Bug 或 AI 改错逻辑时的标准化排错方法论。
* **主要内容**：按照 `diagnosing-bugs` 流程：复现现象 -> 查看日志与堆栈 -> 确定最小修复方案 -> 验证修复结果，拒绝盲目重构或随机试错。

### 第 7 课：让 Agent 实际操作页面完成验收
* **定位**：使用自动化测试工具验证真实前端交互与流程连通性。
* **主要内容**：运行 `webapp-testing` 自动化脚本，测试涵盖表单填写、记录提交、处理动作执行、状态变化与工具输入输出断言，产出包含截图与状态报告的验收证据链。

### 第 8 课：Claude Code 开发，Codex 独立审查
* **定位**：建立双 Agent 协作与审查防线。
* **主要内容**：引入 `AGENTS.md` 独立审计规范。Claude Code 负责代码实现，Codex 负责审查代码隐患与逻辑越界，主管根据审查报告做终极裁决。

### 第 9 课：业务 Agent 场景判断与产品设计
* **定位**：理清 AI 能力在三类原型流程中的最佳落脚点。
* **主要内容**：对监控型设计异常总结与原因建议，对流程型设计分类、风险识别与处理建议，对工具型设计生成、转换与结果审核，制定包含“触发条件、Input/Output、人工二次确认”的 Agent 规则矩阵。

### 第 10 课：落地第一个 AI 功能并沉淀业务 Skill 与 IT 对接
* **定位**：成果结业、Skill 沉淀与 IT 开发对接交付。
* **主要内容**：
  1. 跑通原型中首个可点击的真 AI 场景 Demo；
  2. 使用 `skill-creator` 将经过验证的业务逻辑沉淀为可复用 Skill；
  3. **自动导出《IT 开发对接说明书 (PRD)》**（包含页面结构图、模拟数据 Schema、AI 触发条件与失败兜底策略），交付 IT 部门开发落地。
