# 课堂运营指南（TEACHING_OPERATIONS_GUIDE）

本指南规定课程课堂运营规则：课前预检、课堂节奏、教师/助教分工、缺课处理、Mock 数据责任、证据与验收规则、安全边界。课程参数以 `docs/COURSE_ROADMAP.md` 为权威，术语以 `GLOSSARY.md` 为权威，教案结构以 `docs/LESSON_TEMPLATE.md` 为权威。

## 1. 课前预检

L1 前安排 30–45 分钟环境预检，确认：

- npm 与项目依赖可启动（`npm run dev` 或 `start-project.bat`）
- 浏览器可打开本地试衣镜（127.0.0.1）
- Claude Code 可启动并加载本课所需 Skill
- Mock 数据模板就绪且为虚构内容
- 教师真实调用环境（仓库外受控环境）可用；密钥不进入仓库、课程材料或学员包
- 每课学员包（ZIP 或起点 tag）已按 `docs/LESSON_TEMPLATE.md` 第 21 节核对

预检中发现的问题记录到 `docs/COURSE_DELIVERY_STATUS.md` 已知问题清单。

## 2. 课堂节奏

- 每节 90 分钟为硬上限与初始预算，不是固定时刻表；各段可按课合并、重排或删减，总时长不得超过 90 分钟。
- 暂停提问点作为覆盖性教学手段，不设固定数量与固定位置，教师按课堂节奏与概念负荷决定。
- 每课必须覆盖：目标对齐、概念讲解、教师演示、学员实操、成果验收；coverage functions 可合并、重排或省略，但不得取消实操与结果验证。
- 真实时长须经逐课试讲校准，不得伪造精确时间数据。

## 3. 教师/助教分工

- 教师：负责主线演示（教师统一工作台）与概念讲解（四步概念公式）。
- 助教：
  - 环境问题接管：课堂环境阻塞超过 3 分钟由助教接管，学员继续跟教师主线，不阻塞课堂节奏；
  - 个别辅导：巡视中对卡点学员做一对一辅导；
  - Mock 数据检查：检查学员 Mock 数据无真实敏感信息。
- 助教接管后记录问题到 `docs/COURSE_DELIVERY_STATUS.md` 已知问题清单。

## 4. 缺课处理

- 缺课者跟随教师标准案例补齐 20–30 分钟补课包。
- 通过最小证据检查后，方可恢复个人原型主线。
- 补课包内容与最小证据检查按 `docs/LESSON_TEMPLATE.md` 9b 节 pass-through 执行，本指南不新定义。

## 5. Mock 数据责任链

1. 主管：定义字段、含义、枚举、范围和流程规则，验证业务合理性。
2. 课程方：提供模板与安全规则。
3. Agent：起草明确标记的合成数据。
4. 教师/助教：检查确认无真实敏感数据。

边界：
- 学员全程使用 Mock / 已脱敏数据，不配置真实 API Key。
- 教师真实模型/API 调用完全在仓库外受控教师环境；本仓库、课程材料与学员包只允许 Mock / 脱敏产物。
- 教师密钥不得进入仓库、课程材料或学员包。
- 真实数据进入 AI 前必须完成脱敏；未脱敏真实数据不得进入提示词或仓库。

## 6. 证据与验收规则

- 四类证据卡：视觉截图、行为日志、工程检查、变更范围；验收以可复核证据为准。
- 三类成果分离，不得混称或互相替代：
  - 课堂内可见成果（每课课堂结束时可见）；
  - 课间微任务（10–15 分钟，两课之间）；
  - 每周完整成果（30–45 分钟，每周第二节课后只提交一个）。
- 每课停止条件按本课 acceptance rubric 与证据协议通过，不引用遗留脚本作为停止条件。
- 独立审查按上下文隔离规则执行（L8 起），审查者只读不修改代码。

## 7. 安全边界

- 不冒充未实现能力：自动化验证脚本等待实现教学资产必须标注"待实现教学资产，当前不作为课堂通过条件"。
- 降级状态必须可见：Mock 与降级结果在界面上明确标记来源，不假装真实数据。
- 未脱敏数据不得进入 AI：发现真实数据/Token/内部敏感信息时立即停止并报告，不继续传播。
- 文字规则不冒充运行时硬控制：指导性约束、工作流门禁、运行时硬控制三层分别描述。
