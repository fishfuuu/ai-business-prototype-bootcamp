# 第六课学员操作指南 — 学会定位和修复问题：五层诊断卡、diagnosing-bugs Skill 与有界排错 Loop

> 💡 **本课的核心思想只有一句话：**  
> **排错前先存档，不盲猜、先断言；日志脱敏写报告，两轮不通安全熔断。**

---

## 一、 本课背景、底层原理与学习目标

### 1.1 业务背景与真实痛点
在原型开发与迭代过程中，最常见的挫败感来自于：**页面突然点不动了、数据显示为空，或者弹出了报错白屏**。此时，缺乏工程训练的学员往往会陷入三种极端：
1. **凭感觉盲猜**：在聊天窗口给 AI 发一句“页面坏了你看看”，导致 AI 开始天马行空地乱猜乱改。
2. **盲目深挖底层**：AI 为了修一个简单的界面显示问题，擅自修改了 Vue 响应式核心逻辑或 Node 依赖包，导致原本正常的模块全部报废。
3. **控制台恐慌与数据外泄**：遇到报错时被 DevTools 密密麻麻的红字吓住，直接将包含 Authorization Header 或密钥的完整抓包文本粘贴给 AI。

### 1.2 宏观受控闭环与排错流程
本课将引入 Matt Pocock 的 `diagnosing-bugs` 4 阶段排错范式与“五层诊断卡”，结合预置故障包 `course-fixtures/lesson-06-buggy-fixture/`，将 Bug 修复纳入一条**“排错前存档 ➔ 建反馈闭环 ➔ 事实脱敏落盘报告 ➔ 契约二分隔离 ➔ 2 轮安全熔断”**的受控闭环中：
1. **无痛检查点存档 (Checkpoint before Debug)**：在排错前先下发 `git commit -m "checkpoint: before lesson 6 debug"`。
   - *存档与熔断一句话口诀*：`“进战场前存 Save Point (Checkpoint Commit)，打不过时只清扫本场坏试错 (git restore)，历史装备毫发无损。”`
2. **建立反馈闭环与前置隐私防线 (Build Loop & Privacy Guardrail)**：改代码前必须先有明确的 PASS/FAIL 测试脚本或控制台断言。`⚠️ 绝对禁止直接粘贴 DevTools Network 抓包与环境 Token`，所有 Log 统一脱敏为 `<REDACTED>`。
3. **诊断报告落盘与 2 轮安全熔断 (Debug Report & Circuit Breaker)**：将五层诊断结论落盘写入 `docs/LESSON_06_DEBUG_REPORT.md`。若 Agent 尝试 2 轮修复仍未 PASS，自动执行 `git restore .` 安全恢复至 Checkpoint 状态并生成 `.patch` 呈报主管。

### 1.3 核心学习目标
完成本课实操后，你将能够：
1. 掌握在排错前下发 Checkpoint 无痛存档，并唤醒 `.claude/skills/diagnosing-bugs/SKILL.md` 建立物理 PASS/FAIL 反馈闭环。
2. 掌握使用“五层诊断卡”口语化标签查找问题，并将诊断结论物理落盘写入 `docs/LESSON_06_DEBUG_REPORT.md`。
3. 掌握“2 轮硬熔断机制”，在 Agent 盲改跑偏时一键执行 `git restore .` 安全回滚至 Checkpoint 状态，防范项目崩盘。

## 二、 💡 本课核心工程概念卡 (Core Concepts)

### 核心概念 1：Five-Layer Diagnostic Map (五层诊断卡 / 口语化物理排错分层)
- **硬核工程定义**：将 Web 应用排错物理拆解为环境层、数据源层、组件状态层、日志层与契约断言层五层排查的诊断拓扑。
- **底层运作机制与口语化标签**：
  - **Layer 1 环境层** ➔ `[物理服务] 网页跑不起来`
  - **Layer 2 数据源层** ➔ `[种子数据] 没数据或拿到了 null 空值`
  - **Layer 3 状态层** ➔ `[组件状态] 数据变了，但界面没跟着动`
  - **Layer 4 日志层** ➔ `[报错日志] 控制台第一行红字报错`
  - **Layer 5 契约层** ➔ `[契约断言] 名字写错了，界面配不上契约`
- **具象业务比喻**：**汽车故障五级诊断仪** 🚗。依次检查电池电压、汽油品质、仪表盘状态、故障代码与安全行驶标准。
- **IT 沟通场景**：“我们通过五层诊断卡定位到了数据源层与组件状态层的绑定断裂，并非底层框架故障。”

### 核心概念 2：Fact-Anchored Feedback Loop & Debug Report (事实锚定与诊断报告落盘)
- **硬核工程定义**：在修改任何代码前，必须先建立确切可重复执行的 PASS/FAIL 物理验证信号，并将诊断结论落盘写入 `LESSON_06_DEBUG_REPORT.md` 的排错范式。
- **底层运作机制**：唤醒 `diagnosing-bugs` Skill，先捕获 Console/Terminal 真实 Log 并脱敏敏感信息 (`<REDACTED>`)，写好断言脚本与诊断报告落盘后再下发修补指令。
- **具象业务比喻**：**医生开处方前的验血报告与病例归档** 🩺。没拿到验血与 CT 视觉证据并填写病例表前，绝不盲目开药开刀。
- **IT 沟通场景**：“我们在修改前先建立了自动化反馈闭环，并将五层诊断结论落盘生成了 DEBUG_REPORT 审计报告。”

### 核心概念 3：Bounded Debugging Loop & Checkpoint Breaker (无痛存档与 2 轮硬熔断)
- **硬核工程定义**：在排错前先下发 Checkpoint 存档，限定 Agent 排错仅在 `prototype-contract.d.ts` 契约层，且设置最多 2 轮修补上限、失败安全回滚至 Checkpoint 状态的物理门禁。
- **底层运作机制**：排错前 `git commit` 留存稳定点；计数器记录自修轮次；第 2 轮未 PASS 则强行阻断并触发 `git restore .` 安全恢复 Checkpoint 状态，打上 `step-6-blocked.patch` 提交主管裁决。
- **具象业务比喻**：**单机游戏 Boss 战前的 Save Point 与跳闸保鲜开关** 🎮⚡。进战场前先存个档，哪怕战斗失败也只损失本场尝试，历史通关进度稳如泰山。
- **IT 沟通场景**：“项目设置了排错前 Checkpoint 存档与 2 轮硬熔断机制，一旦超过 2 轮自修未 PASS 即安全回滚至 Checkpoint，避免代码越改越崩。”

### Task 1: 装载故障包、排错前无痛存档并建立 PASS/FAIL 反馈闭环

#### ⚡ 极速操作步骤
1. 装载预置故障包 `course-fixtures/lesson-06-buggy-fixture/`。
2. 打开 CLI 窗口，下发排错前无痛存档指令：

4. `⚠️ 隐私防线`：检查对话框输入，确保未直接粘贴 DevTools Network 抓包或环境 Token。

#### 💡 独立自学原理解析
> **为什么不用担心 `git restore .` 熔断抹杀代码？**  
> 许多学员害怕 `git restore .` 熔断命令，是因为担心回滚会把自己过去写的代码全部抹杀。在排错前先存一个 Checkpoint 检查点，能让回滚动作只扫除后续试错过程中产生的坏代码，确保历史合法成果 100% 安全。

### Task 3: 契约修补与 2 轮硬熔断演练

#### ⚡ 极速操作步骤
1. **下发最小化修补指令**：
   ```text
   同意执行契约层最小化修补
   ```
2. **运行反馈闭环验证**：
   运行 PowerShell 校验脚本：

3. **演练 2 轮硬熔断降级**：
   若修复第 2 轮后仍然报错 `FAIL`，下发熔断指令：

#### 💡 独立自学原理解析
> **2 轮硬熔断与 Checkpoint 的双重保护机制**  
> 2 轮熔断切断了 AI 在错误路径上的盲目试错；Checkpoint 存档确保了 `git restore .` 能够精准只清扫坏尝试。两者结合，构成了无痛、受控、百分百安全的极客排错工作流。

## 五、 💡 常见概念误区与正确理解 (Mindset Transformation)

| 常见误区 (Misconception) | 正确硬核理解 (Correct Engineering Reality) | 如何纠偏与护栏防护 (Remedy & Guardrails) |
| :--- | :--- | :--- |
| **误区 1：“遇到 Bug 就把报错截图或 Network 原始抓包贴给 AI”** | 含有 Token 或 Auth Header 的原始抓包外泄存在严重安全风险，且无验证信号的修改是盲改。 | 执行“前置隐私防线”，所有日志脱敏 `<REDACTED>`，先建立 PASS/FAIL 验证信号。 |
| **误区 2：“控制台全是红字，肯定是我把系统底层全部搞砸了”** | 控制台长堆栈是框架内部的链式抛错，主管只需提取第一行 Error Message 交给 AI 处理。 | 执行“控制台解焦虑”，第一行取事实，长堆栈留给 AI。 |
| **误区 3：“执行 `git restore .` 熔断会把我之前写的代码全抹掉”** | 在排错前下发 `git commit` Checkpoint 存档后，回滚只清除坏修补，历史代码毫发无损。 | 执行“排错前无痛存档”，先存 Checkpoint 档再下发修复指令。 |
| **误区 4：“排错完了只要界面能出来就行，不需要留存书面记录”** | 缺乏排错记录会导致第 7 课自动化验收无法溯源故障审计源。 | 执行“诊断报告落盘”，强制落盘生成 `docs/LESSON_06_DEBUG_REPORT.md`。 |

### 阶段 2：课后自学拓展思考题 (Self-Study Extension)
4. **[原理思考题]** 简述为什么“Checkpoint 存档 + 诊断报告落盘 + 2 轮硬熔断”组合是防范 AI 排错死循环的终极保险？
   - **自学提示**：Checkpoint 存档消除了回滚的抹杀恐惧；诊断报告落盘建立了审计追踪；2 轮硬熔断切断了盲目试错，确保代码库永远退回到上一个百分百可工作的稳定 Commit 点。
