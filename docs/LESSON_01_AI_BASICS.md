# 第一课基础知识：Claude为什么可以真正制作系统页面

欢迎阅读第一课基础概念参考！在这一课中，你将发现 Claude 不仅能聊天，还能真正帮你修改项目、运行代码、做出一个企业系统页面。

---

## 1. 先看完整答案

一句话记住 Agent 的工作原理：

> **Claude Code 是一个以 LLM 为大脑、以 Tools 为手脚、通过 ReAct 持续调整、在 Workflow 中接受人工控制的 Agent。**

```text
+-----------------------------------------------------------------------+
|                              Workflow                                 |
| (需求 -> 方案 -> 主管确认[人工门禁] -> 执行 -> 验证 -> 检查 -> 调整)    |
|                                                                       |
|   +---------------------------------------------------------------+   |
|   |                      Claude Code Agent                        |   |
|   |                                                               |   |
|   |   +-------------------+              +--------------------+   |   |
|   |   |   LLM (大脑)      |              |   Tools (手脚)     |   |   |   |
|   |   | 理解需求、生成方案 |              | 读取/修改/运行/检查 |   |   |   |
|   |   +---------+---------+              +---------+----------+   |   |
|   |             |                                  |              |   |
|   |             +----------------+-----------------+              |   |
|   |                              |                                |   |
|   |                    ReAct 循环 (行动 -> 观察 -> 调整)          |   |
|   +---------------------------------------------------------------+   |
+-----------------------------------------------------------------------+
```

---

## 2. LLM：理解和生成的大脑

### 一句话理解
LLM（大语言模型）是 AI 的“大脑”，负责理解你输入的自然语言，并生成文字回复、页面规划或代码方案。

### 简单生活比喻
LLM 就像一位博学睿智的“军师”。你描述业务困境，他能立刻听懂并为你开出治理药方，但他自己手里没有铲子，无法替你下地干活。

### 刚才在页面制作中你看到了什么
当你在 Task 1 中输入你的业务需求时，Claude 立刻用自己的话复述了你的痛点，并提出了一个包含 KPI 卡片和数据表格的页面设计方案。**在这个阶段，只有 LLM 在工作，项目文件没有任何改变。**

* **LLM 能做什么**：理解业务场景、澄清概念、设计结构、生成代码片段。
* **LLM 不能保证什么**：不能直接读取你本地的最新文件，也不能保证生成的代码运行起来 100% 毫无错误。
* **常见误解**：以为只要会和 LLM 聊天，系统就自动做好了。其实聊天阶段只是方案设计。
* **记忆问题**：Claude 刚才生成方案时，修改你电脑上的项目了吗？（答案：没有，此时仅有 LLM 大脑在推理）。

---

## 3. Tools：Agent 的手和眼睛

### 一句话理解
Tools（工具）是 Agent 的“手和眼睛”，让 LLM 能够走出聊天框，去读取真实文件、修改代码和运行命令。

### 简单生活比喻
如果 LLM 是军师，Tools 就是军师手里的“望远镜”和“地图笔”。有了工具，军师才能看清阵地上的真实地形，并在地图上标出进攻路线。

### 刚才在页面制作中你看到了什么
在 Task 2 中，Claude 并没有凭空猜测，而是主动读取了项目中的 `CLAUDE.md`、`DESIGN.md` 和 `docs/COMPONENT_CATALOG.md`。

本课中你看到的 4 类核心 Tools：
1. **读取文件**：查看你的项目规则、设计规范与已有组件。
2. **修改文件**：在确定方案后，将代码写入真实的 `.vue` 或 `.ts` 文件中。
3. **运行命令**：在后台启动开发服务器或运行 `verify-student-project.ps1` 校验脚本。
4. **检查结果**：查看终端返回的构建日志或报错提示。

* **记忆问题**：为什么 Claude 读取项目文件后给出的方案比第一次更可靠？（答案：因为 Tools 让它看到了真实的系统组件与设计规范）。

## 4. Agent：围绕目标组织多步行动

### 一句话理解
Agent（智能体）是在 LLM 大脑的基础上，配备了 Tools 手脚和明确目标后，能够**自动把大目标拆解为多步连续行动**的执行者。

### 简单生活比喻
Agent 就像一位懂规矩的“项目经理”。你给他一个目标（如“做个订单预警台”），他会先看规则，再写代码，最后跑测试，不需要你一步步下达“先开文件、再写第 5 行”的微观指令。

### 刚才在页面制作中你看到了什么
在 Task 3 中，当你明确批准后，Claude 连续完成了“创建新页面 -> 配置路由 -> 写入侧边栏 -> 运行类型检查”一整套动作。

| 模式 | 表现形式 |
| --- | --- |
| **普通 LLM** | “我建议你创建一个订单超时预警页面，具体代码如下……” |
| **Agent 执行** | “我已读取规范，正在为您创建 `OrderWarningPage.vue`，并添加侧边栏菜单入口。” |

* **常见误解**：Agent 是完全自主、不需要人管的系统。（纠正：Agent 必须在主管设定的边界和 Workflow 中工作）。

## 5. ReAct：行动、观察、再调整

### 一句话理解
ReAct（Reason + Act，推理与行动循环）是 Agent 的工作方式：**先思考行动，再观察结果，根据结果继续调整**。

```text
行动 (Act) -> 观察结果 (Observe) -> 思考调整 (Reason) -> 再次行动 (Act)
```

### 简单生活比喻
就像教徒弟炒菜。师傅尝了一口觉得咸了（观察），告诉徒弟加点水（思考），徒弟加水重新微煮（行动），直到味道正合适。

### 刚才在页面制作中你看到了什么
在 Task 4 中，当你指出“表格里的状态标签不够清晰”时，Claude 先复述了理解，修改了代码，然后在浏览器中展示最新效果，并运行脚本验证。**第一次生成不完美非常正常，通过 ReAct 循环就能不断逼近完美。**

* **常见误解**：ReAct 是要求 AI 展显复杂的内部思考过程，或者不断盲目重试。（纠正：ReAct 是“基于真实反馈的理性微调”）。

---

## 6. Workflow：规定顺序和确认点

### 一句话理解
Workflow（工作流）是主管制定的规则与顺序，**规定 Agent 必须按什么步骤推进，以及在哪些关键节点必须等主管确认**。

### 简单生活比喻
Workflow 就像工厂的“标准生产流水线”与“质检闸口”。工人（Agent）干活再快，到了关键卡口也必须由质检员（主管）盖章才能放行。

### 为什么 Agent 必须在 Workflow 中工作？
如果没有 Workflow 限制，Agent 可能会：
* 未经确认就直接修改核心代码；
* 贪大求全引入不可控的第三方库；
* 验证失败了却宣布“已完成”。

**第一课的黄金 Workflow**：
```text
需求 (Task 1) -> 方案 (Task 2) -> 主管确认[确认门禁] -> Agent 执行 (Task 3) -> 验证与 ReAct 微调 (Task 4) -> 主管最终验收
```

## 7. 五个概念如何一起工作

| 页面制作动作 | 对应 AI 概念 | 谁在主导 |
| --- | --- | --- |
| 学员口述业务问题与 5 项输入 | 为 LLM 提供上下文 | 学员（主管） |
| Claude 生成第一版页面方案 | **LLM** (大语言模型) | AI 大脑 |
| Claude 读取 `CLAUDE.md` 与组件库 | **Tools** (工具) | AI 手脚 |
| 主管审核方案并明确下达实施授权 | **Workflow** (人工确认门禁) | 学员（主管） |
| Claude 连续完成页面、路由与侧边栏创建 | **Agent** (智能体) | AI 连续执行 |
| 运行验证、观察效果、自然语言微调 | **ReAct** (行动-观察-调整) | 人机协作微调 |
| 检查系统是否真正解决了业务问题 | **Human in the loop** (人在回路) | 学员最终裁决 |

---

## 8. 常见误解与澄清

1. **误解：Agent 是另一个神秘的全新模型。**
   * *事实*：Agent 是“LLM 大脑 + Tools 工具 + Workflow 规则”的组合体。
2. **误解：第一次生成的页面不够完美，说明 Agent 失败了。**
   * *事实*：软件开发天然需要迭代，利用 ReAct 循环进行 2-3 轮微调是正常且高效的闭环。
3. **误解：自动化构建成功，就代表系统功能一定是对的。**
   * *事实*：构建成功只代表代码没有语法错误，只有主管才能判断系统是否真正解决了业务痛点。
