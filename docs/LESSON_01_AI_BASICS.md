## 2. LLM：理解和生成的大脑

### 一句话理解
LLM（大语言模型）是 AI 的“大脑”，负责理解你输入的自然语言，并生成文字回复、页面规划或代码方案。

### 简单生活比喻
LLM 就像一位博学睿智的“军师”。你描述业务困境，他能立刻听懂并为你开出治理药方，但他自己手里没有铲子，无法替你下地干活。

### 刚才在页面制作中你看到了什么
当你在 Task 1 中输入你的业务需求时，Claude 立刻用自己的话复述了你的痛点，并提出了一个包含 KPI 卡片和数据表格的页面设计方案。**在这个阶段，只有 LLM 在工作，项目文件没有任何改变。**

* **LLM 能做什么**：理解业务场景、澄清概念、设计结构、生成代码片段。
* **LLM 不能保证什么**：不能直接读取你本地的最新文件，也不能保证生成的代码运行起来 100% 毫无错误。
* **记忆问题**：Claude 刚才生成方案时，修改你电脑上的项目了吗？（答案：没有，此时仅有 LLM 大脑在推理）。

## 3. 感知与规则（眼睛/耳朵）：Prompt、CLAUDE.md 与 Context

### 一句话理解
如果说 LLM 是大脑，那么**你的 Prompt（指令）与 `CLAUDE.md`（项目校规）就是 AI 的“眼睛和耳朵”**，而 **Context（上下文）则是它的“短期记忆对讲机”**。

### 简单生活比喻
* **Prompt（耳朵）**：你现场对 AI 喊出的口令，让它听懂你当下的业务需求。
* **`CLAUDE.md`（眼睛）**：这个工程的“员工手册 / 校规”。AI 戴上眼睛看懂校规后，就知道不能用原生 CSS 乱写、必须遵守企业已有的设计规范与组件库。
* **Context（对讲机记录）**：AI 的“短期工作记忆”。对讲机聊天记录太长时前面的会被挤掉——这就是为什么必须把重要的规矩写进 `CLAUDE.md` 长期保存，而不是每次都重复口述。

> ⚠️ **跨课程概念厘清（CLAUDE.md vs AGENTS.md）**：
> * **`CLAUDE.md`（本课）**：是给开发助手 Claude 准备的项目校规。
> * **`AGENTS.md`（第 7–8 课）**：到了双 Agent 协作阶段，我们将给独立评审专家 Codex 准备它的专属审查手册。

## 4. Tools：Agent 的手和眼睛

### 一句话理解
Tools（工具）是 Agent 的“手和脚”，让 LLM 能够走出聊天框，去翻开真实文件、写入修改代码和运行终端命令。

### 简单生活比喻
如果 LLM 是军师，Prompt 和 `CLAUDE.md` 是望远镜，那么 Tools 就是军师手里的“工兵铲”。有了工兵铲，军师才能在阵地上真正挖出战壕。

### 刚才在页面制作中你看到了什么
在 Task 2 中，Claude 并没有凭空猜测，而是主动使用 Tools 读取了项目中的 `CLAUDE.md`、`DESIGN.md` 和 `docs/COMPONENT_CATALOG.md`。

本课中你看到的 4 类核心 Tools：
1. **读取文件**：查看你的项目规则、设计规范与已有组件。
2. **修改文件**：在确定方案后，将代码写入真实的 `.vue` 或 `.ts` 文件中。
3. **运行命令**：在后台启动开发服务器或运行 `verify-student-project.ps1` 校验脚本。
4. **检查结果**：查看终端返回的构建日志或报错提示。

## 5. Agent：围绕目标组织多步行动

### 一句话理解
Agent（智能体）是在 LLM 大脑的基础上，配备了 Tools 手脚、规则感知和明确目标后，能够**自动把大目标拆解为多步连续行动**的执行者。

> ⚠️ **跨课程概念厘清（施工队 Agent vs 家政机器人 Agent）**：
> * **Claude Code（本课）**：是帮你**盖房屋的“施工队 Agent”**（Coding Agent），专门负责把你的需求做成前端系统页面。
> * **第 9 课设计的 Agent**：是未来入住房屋、**帮你在系统中处理具体业务的“家政机器人 Agent”**（Business Agent，如智能催单助手）。

### 刚才在页面制作中你看到了什么
在 Task 3 中，当你明确批准后，Claude 连续完成了“创建新页面 -> 配置路由 -> 写入侧边栏 -> 运行类型检查”一整套动作。

| 模式 | 表现形式 |
| --- | --- |
| **普通 LLM** | “我建议你创建一个订单超时预警页面，具体代码如下……” |
| **Agent 执行** | “我已读取规范，正在为您创建 `OrderWarningPage.vue`，并添加侧边栏菜单入口。” |

## 6. ReAct：行动、观察、再调整

### 一句话理解
ReAct（Reason + Act，推理与行动循环）是 Agent 的工作方式：**行动 -> 观察结果 -> 思考调整**。第一次生成不完美非常正常，通过 ReAct 就能不断逼近满意效果。

### 刚才在页面制作中你看到了什么
在 Task 4 中，当你指出“表格里的状态标签不够清晰”时，你在 **`http://127.0.0.1:8888`（本地试衣镜）** 中观察渲染效果，发起了 1 轮 ReAct 微调。AI 复述理解 -> 修正代码 -> 试衣镜显示新效果 -> 运行脚本校验。

---

## 7. Workflow 与人在回路（Human-in-the-Loop）

### 一句话理解
Workflow（工作流）是主管制定的规则与顺序，而 **人在回路（Human-in-the-Loop）** 就是**主管在关键门禁盖章授权**，确保 AI 干活再快，最高控制权也永远握在主管手里。

**第一课的黄金 Workflow**：
```text
需求 (Task 1) -> 方案 (Task 2) -> 人在回路[主管盖章] -> Agent 执行 (Task 3) -> 试衣镜观察与 ReAct 微调 (Task 4) -> 主管最终验收
```

---

## 8. 演戏道具：Mock Data（模拟数据）

### 一句话理解
**Mock Data（模拟数据）是原型阶段的“演戏道具”**。在第一课中，我们用假数据快速把业务流程和界面搭出来验证，等验证通过后再交给 IT 部门对接真实数据库。

---

## 9. 常见误解与澄清

1. **误解：Agent 是另一个神秘的全新模型。**
   * *事实*：Agent 是“LLM 大脑 + 规则眼睛 + Tools 手脚 + Workflow 规则”的组合体。
2. **误解：第一课做出的页面已经直接连上了公司真实数据库。**
   * *事实*：当前页面使用的是 Mock Data（演戏道具），目的是零风险快速验证页面布局与业务跟进流程。
3. **误解：聊太久 AI 突然忘了规则是系统损坏了。**
   * *事实*：这是 Context（短期记忆对讲机）容量满了。把关键规则写进 `CLAUDE.md`（眼睛校规）就能长久保持记忆。
