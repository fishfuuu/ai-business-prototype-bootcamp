## 一、课程目标

课程目标不是培养程序员，也不是直接开发复杂 AI Agent，而是让运营主管成为“超级业务 PM”，能够：

1. 使用 Claude Code 从零创造自己想要的业务系统页面。
2. 用自然语言和参考截图持续修改系统。
3. 使用 Skills 提高需求分析、页面设计、调试和验证的稳定性。
4. 掌握必要的工程纪律与防崩救回习惯（Git 存档、`CLAUDE.md` 护栏、五层 Bug 诊断）。
5. 使用 Codex 独立审查 Claude Code 的代码与逻辑。
6. 准确判断页面中哪些环节适合普通功能、AI 功能或 AI Agent（保持 HITL 人在回路确认）。
7. 完成一个带简单 AI 能力的业务系统 Demo。
8. 将经过验证的成果整理为《IT 原型交接包》，交付 IT 部门开发落地。

课程主线：

```Plain Text
从零创造系统 (第1课)
→ 做成自己想要的样子 (第2课)
→ 想清需求与数据契约 (第3课)
→ 小步增量实现 (第4课)
→ 工程防护与失控恢复 (第5课)
→ 五层防崩排错 (第6课)
→ 四类证据自动验收 (第7课)
→ 基于 Commit 双 Agent 审查 (第8课)
→ AI 场景判断与安全边界 (第9课)
→ 落地有限 AI 闭环与 IT 交接 (第10课)
```

---

## 二、课程工具与角色契约

### Claude Code（主要实施者）
- 理解业务需求
- 从零创建页面
- 根据截图调整页面
- 实现业务功能与增量修改
- 定位和修复问题
- 运行工程自测与启动项目

### Codex（独立审查者）
- 从第 8 课开始引入（基于 `AGENTS.md` 规范）
- 检查 Claude Code 是否误解需求
- 检查是否超出修改范围
- 审查 Candidate Commit 到稳定基线 Commit 的 Diff
- 提出独立审查意见（阻断/重要/建议）

### 运营主管（最终裁决者 / 人在回路盖章官）
- 掌控 Workflow 推进阶段
- 行使 Keep / Omit / Remove / Modify 裁决权
- 对 Codex 审查意见做 4 种决定：接受、拒绝、延期、超出本次范围
- 行使人在回路盖章授权与最终业务验收

固定协作方式：

```Plain Text
Claude Code 增量实现
→ 自测与 Candidate Commit
→ Codex 独立审查 Diff
→ 主管裁决盖章
→ Claude Code 在新 Commit 中修复
→ 运营主管最终验收
```

## 三、课程使用的 Skills

第一期不安装大量 Skills，只选择最直接相关的能力。

课程只需要：
- 固定已经验证过的 Skill 版本
- 记录来源仓库和版本
- 提供中文使用说明
- 补充必要的企业数据安全规则

特别说明：Skill 属于加速工具，不是课程成立的前提。第 10 课的 Skill 封装作为可选拓展。

## 四、第一课的“从零开始”定义

第一课从零开始创造业务系统，但不从零搭技术环境。

### 学员从零决定的内容
- 系统名称
- 系统解决的问题
- 目标使用者
- 原型类型（A. 监控与决策型 / B. 任务与流程型 / C. 操作工具型）
- 菜单结构与首页内容
- 核心指标与业务字段

### 提前准备的技术底座
```Plain Text
可直接运行的空白前端工程
基础路由与通用组件库
模拟数据能力与一键启动入口
`docs/PROJECT_STATE.md` 模版
Claude Code 项目护栏 (`CLAUDE.md`)
```

课程原则：
> 从零创造业务系统，但不让学员把时间消耗在安装环境和解决依赖问题上。遵照模拟数据红线，绝对不连接生产环境。

## 六、详细课程内容

## 第1课：从业务问题创建第一个系统页面

### 核心目标
第一节课结束时，学员不仅能够做出按自己业务想法创造出的系统页面，还能理解并复述 LLM、Tools、Agent 在系统制作中的作用，并建立数据安全红线。

### 课堂步骤
1. 工具预检：确认工程底座与脚本正常。
2. 描述想要的系统：确定名称、使用者、原型类型（A/B/C）与要解决的核心问题。
3. **初始化 `docs/PROJECT_STATE.md`**：记录系统基本定义与数据敏感级别。
4. 让 Claude Code 提出第一版结构（菜单、首页层级、模拟数据）。
5. 学员选择和修改方案，连续修改三次。

### 工程化内容
1. **建立项目状态**：初始化 `docs/PROJECT_STATE.md`。
2. **模拟数据红线**：第一版只使用模拟数据，不连接生产环境，不包含敏感明细。
3. **先跑通再完善**：先完成可运行版本，不追求完整系统。

### 课堂成果
- 一个从空白工程创建出来的系统雏形
- 初始化完成的 `docs/PROJECT_STATE.md`

---

## 第2课：用参考图做出像样的企业页面

### 核心目标
让学员学会使用参考图、现有系统和草图控制页面效果，并掌握基础 Git 存档与恢复习惯。

### 课堂步骤 (标准课堂 90 分钟，学员实操 50 分钟)
- **Task 1：提取结构与基线存档 (15 分钟)**：检查 `git status`；必要时 `git init`；提交第一课成果与 `PROJECT_STATE.md`（基线提交）；分析参考图信息层级。
- **Task 2：规范映射 (15 分钟)**：结合 `DESIGN.md` 设计规范，映射 Token 与组件，禁止继承参考图杂乱颜色。
- **Task 3：视觉裁决与修改 (10 分钟)**：下达 Keep / Omit / Remove / Modify 指令，使用 `frontend-design` 完成重构。
- **Task 4：对比验证与成果存档 (10 分钟)**：运行验证；查看 `git diff` 确认范围；`git add` & `git commit` 保存成果版本；运行 `git log --oneline` 查看历史。

### 工程化内容
1. 引入 `DESIGN.md` 页面设计规则。
2. 引入 Git 基础（游戏存档比喻），只教：`status, init, add, commit, log, diff` 6 个命令。

---

## 第3课：让 Agent 帮助自己想清楚需求

### 核心目标
让学员从“我有一个大概想法”，走到“Agent 可以稳定执行”，完成数据契约与验收标准前置。

### 课堂内容
使用 `grill-me` 进行追问，形成分类型的《业务功能卡》与《数据契约卡》。

### 工程化内容
1. **轻量数据契约卡**：明确字段名称、业务含义、数据类型、是否必填、数据来源、示例值、校验规则、敏感等级。
   - *监控决策型*：增加指标口径、对比基准、异常阈值。
   - *任务流程型*：增加角色、业务状态、允许动作、状态迁移。
   - *操作工具型*：增加输入校验、处理规则、输出结构、失败状态。
2. **验收标准前置**：在需求卡中明确定义客观验收场景。

---

## 第4课：把大需求拆成连续的小成功

### 核心目标
将大需求拆成连续小步骤，建立“数据接口意识”，避免 Agent 修改跑偏。

### 工程化内容
1. **数据接口意识**：明确“页面不是数据源，数据未来由 API 提供”。坚持 Mock 数据，显式实现 4 种页面状态：`Loading`（正在获取）、`Empty`（没有数据）、`Success`（正常显示）、`Error`（获取失败）。
2. **步步推进流程**：定义数据结构 -> 画空壳页面 -> 连通交互 -> 执行 L3 验收步 -> `git commit` 保存一步。

---

## 第5课：建立不会轻易失控的项目

### 核心目标
让学员理解 Vue 项目心理地图、项目护栏与 Git 恢复能力。

### 课堂内容
1. 识别 Vue 3 项目 3 个盒子（页面 `pages/`、组件 `components/`、导航 `router/`）。
2. **引入 `CLAUDE.md` 项目护栏**：规定未经确认不安装依赖、不改密钥、不换框架、不出库 Token。
3. **三类原型分支护栏**：锁定 Store / 状态机 / 算法核心逻辑。
4. **版本权威与恢复**：Git Commit 是正式存档与恢复手段；`Checkpoint` 脚本仅作为学员无法完成 Git 恢复时的紧急保底工具。（注：`AGENTS.md` 在第 8 课引入）。

---

## 第6课：学会定位和修复问题

### 核心目标
标准化五层排错方法论与回归验证，避免盲目试错。

### 工程化内容
1. **五层诊断卡**：
   - ① 页面与样式层
   - ② 组件与状态层
   - ③ 路由与页面层
   - ④ 数据与接口层
   - ⑤ 环境与依赖层
2. 针对三类原型提供典型 Bug 诊断案例。
3. 按照复现 -> 定位层级 -> 最小修复 -> 重新执行 L3 验收标准做回归测试。

---

## 第7课：让 Agent 实际操作页面完成验收

### 核心目标
使用 Playwright / `webapp-testing` 自动化测试页面，生成四类客观证据链。

### 工程化内容
1. 将第 3 课定义的验收标准转化为自动化测试。
2. **四类验收证据链**：
   - 视觉证据：前后对比截图
   - 行为证据：操作结果与断言记录
   - 工程证据：`verify-project.ps1` Clean 证明
   - 范围证据：`git diff` 改动清单

---

## 第8课：Claude Code 开发，Codex 独立审查

### 核心目标
建立基于 Commit/Diff 的双 Agent 独立审查机制。

### 工程化内容
1. **引入 `AGENTS.md` 审查规范**：明确 Codex 审查标准。
2. **职责与流程**：
   - Claude Code：主要实施者，提交 Candidate Commit。
   - Codex：独立审查者，审查稳定基线到 Candidate Commit 的 Diff，提供独立意见。
   - 运营主管：最终裁决者，行使 4 种裁决决定（接受、拒绝、延期、超出范围）。

---

## 第9课：判断系统中哪些位置适合加入 AI

### 核心目标
理解普通功能、AI 功能与 AI Agent 边界，确立 AI 安全红线与 HITL。

### 工程化内容
1. 针对三类原型设计 AI 场景落脚点。
2. **AI 安全边界与 HITL**：
   - 输入隐私：敏感字段严禁发送 AI。
   - 结构化输出：强制要求返回 JSON 草稿。
   - 人类确认（HITL）：AI 生成内容标注显眼标识，未经主管确认，禁止直接写库或触发生产动作。

---

## 第10课：落地有限 AI 功能与 IT 交接

### 核心目标
落地最小 AI 闭环、可选 Skill 扩展与 《IT 原型交接包》 输出。

### 课堂成果
1. **落地最小 AI 闭环**：实现一个有限输入 -> AI 处理 -> 结构化草稿 -> 人工确认 -> 降级兜底的真实交互。
2. **[可选扩展] 封装业务 Skill**：Skill 是加速工具，不占用必修 90 分钟。学员可选用 `skill-creator` 封装提示词。
3. **交付《IT 原型交接包》**：整理业务目标、页面流程、数据契约、AI 确认点、四类证据链及未实现清单，交付 IT 部门。
