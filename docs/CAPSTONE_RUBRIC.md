# 结业评价量表（CAPSTONE_RUBRIC）

本量表用于评价 L10《产品决策与开发启动包》的结业交付，评价的是主管的决策与判断能力，不是代码质量或工程能力；本量表不是生产系统验收标准。

评分等级（1–4 分）：

| 分数 | 等级 | 含义 |
| --- | --- | --- |
| 1 | Emerging | 尚未形成该能力，需要显著辅导 |
| 2 | Developing | 部分形成，仍依赖提示与模板 |
| 3 | Competent | 独立完成，判断依据充分 |
| 4 | Extending | 能迁移到新场景并指导他人 |

## 维度 1：业务问题定义与边界划定（25%）

评价点：能否清晰定义部门业务问题、确定性与概率性切割、停止条件。

- **1 Emerging**：只能复述他人描述的问题，无法独立划定边界或停止条件。
- **2 Developing**：能描述问题，但边界与停止条件不完整或依赖提示。
- **3 Competent**：独立定义核心业务问题、明确确定性与概率性功能切割、写出可执行的停止条件。
- **4 Extending**：能把定义迁移到未讲授的新业务场景，并预判边界风险。

## 维度 2：原型制作与 Agent 协作（25%）

评价点：能否使用 Agent 制作受控原型、选择合适的协作模式、执行 HITL 确认。

- **1 Emerging**：无法独立驱动 Agent，或不理解受控边界。
- **2 Developing**：能驱动 Agent 完成步骤，但协作模式选择与 HITL 确认依赖提示。
- **3 Competent**：独立使用 Agent 完成受控原型，按业务信号选择六种协作模式之一，并在关键动作执行 HITL 确认。
- **4 Extending**：能说明协作模式选型理由并指导他人复用。

## 维度 3：证据与验收能力（20%）

评价点：能否产出四类证据、执行独立审查、基于证据作判断。

- **1 Emerging**：交付无证据或仅口头声称完成。
- **2 Developing**：能产出部分证据，但不会基于证据作判断。
- **3 Competent**：产出四类证据（视觉/行为/工程/范围），执行独立审查并依据证据作出 Keep/Reject/Rework 判断。
- **4 Extending**：能抽验关键证据并发现证据盲区。

## 维度 4：数据安全与边界意识（15%）

评价点：Mock/脱敏/密钥边界、降级可见、不冒充能力。

- **1 Emerging**：无法识别真实数据风险或降级来源。
- **2 Developing**：知道规则但执行不完整（如漏标降级来源）。
- **3 Competent**：全程使用 Mock/脱敏数据，降级状态明确标记，不冒充未实现能力。
- **4 Extending**：能主动补证敏感边界并阻止他人误用。

## 维度 5：IT 交接与产品决策（15%）

评价点：《产品决策与开发启动包》质量、非生产就绪声明、生产就绪缺口清单。

- **1 Emerging**：交付包不完整或缺少非生产就绪声明。
- **2 Developing**：交付包基本完整，但缺口清单不具体。
- **3 Competent**：交付包包含功能卡、TS 数据契约、四类证据链与原型源码，明确非生产就绪声明与生产就绪缺口清单。
- **4 Extending**：交付包可直接支撑 IT 启动正式设计与开发，缺口与后续门禁清晰。

## 总分计算与通过标准

总分 = 维度1×25% + 维度2×25% + 维度3×20% + 维度4×15% + 维度5×15%。

- 通过标准：总分 ≥ 3.0（Competent 基准），且单项不低于 2.0。
- 任一单项低于 2.0 时，该维度须返工补证后重新评价。
- 评价结果记录到 `docs/COURSE_DELIVERY_STATUS.md` 或验收记录，注明评价人与评价日期。

## 明确声明

- 本量表评价的是主管的决策与判断能力，不是代码质量或工程能力。
- 本量表不是生产系统验收标准；课程全部产物为非生产就绪原型。
- 评价不得由 AI 自动评分主管的真实业务判断或风险责任。
