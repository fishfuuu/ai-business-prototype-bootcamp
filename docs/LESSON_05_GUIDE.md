# 第五课学员指南 (V2 闭环版)：建立不会轻易失控的项目

欢迎来到第五课！在前四课中，我们完成了界面搭建、视觉规则（`DESIGN.md`）、需求契约（`grill-me`）与增量切片实施（`incremental-implementation`）。本节课我们将解决项目开发中最令人头疼的崩溃点——**“Agent 擅自安装未知依赖、改坏全局配置、或在长对话后产生幻觉失控”**。本课的核心思想只有一句话：

> **用工程护栏 (`CLAUDE.md`) 死死约束 AI 的越界行为，用三分记忆与基线存档保障项目永不失控。**

你将学习如何配置项目最高工程规约 `CLAUDE.md`，建立 **三分记忆模型（工作记忆、外部长期记忆、版本证据）**，体验 **【解药 1：环境脱幻与独立工具箱】**，并掌握类似于单机游戏 S/L (Save & Load) 存档的基线还原机制，确保无论开发多么复杂的业务原型，项目都能稳如磐石。

完成本课学习后，你将能够：
1. **对比与阐述** 缺乏工程约束时 AI 乱装依赖、越界修改配置的失控风险，以及使用 `CLAUDE.md` 工程护栏的防御优势。
2. **区分与应用** **三分记忆模型**（工作记忆：聊天窗口；外部长期记忆：`PROJECT_STATE.md` 与实施计划；版本证据：Git 节点）。
3. **理解与激活** **【解药 1：环境脱幻与独立工具箱】**，通过工程探查脚本防止 Agent 凭空臆测包版本与文件路径。

6. **执行** **项目安全巡检与基线存档**，更新 `docs/PROJECT_STATE.md` 并完成 Git 稳定 Commit。

## 1. 核心概念与护栏机制

### 1.1 项目最高工程规约 (`CLAUDE.md`)
`CLAUDE.md` 是项目根目录下的最高行为规范文件，AI 在每次对话前都会强制读取该文件。它包含：
- **包管理器规约**：锁定 `npm` / `pnpm`，严禁 Agent 擅自安装未授权的第三方库。
- **框架与构建隔离**：锁定 Vue 3 + Element Plus，禁止擅自引入其他 UI 库。
- **安全防错红线**：严禁删除配置文件、严禁修改敏感环境变量。

### 1.2 三分记忆模型 (Three-Layer Memory Model)
- **第一层：工作记忆 (Working Memory)**：主 Agent 的聊天窗口上下文。特点：短期、随会话结束而清空、满溢时产生幻觉。
- **第二层：外部长期记忆 (External Long-Term Memory)**：落盘在工程中的持久化 Markdown 文件（如 `docs/PROJECT_STATE.md`、`docs/BUSINESS_FEATURE_CARD.md` 与实施计划）。特点：跨会话继承、不受 Token 爆炸影响。
- **第三层：版本证据 (Version Evidence)**：Git Commit 节点。特点：物理可追溯、支持一键撤销与基线还原。

### 1.3 解药 1：环境脱幻与独立工具箱 (Environment Un-hallucination)
在修改代码或安装依赖前，强制要求 Agent **先读取工程实际文件与依赖版本**，严禁凭借凭空假设进行编写。项目提供独立的校验工具箱（如 `verify-project.ps1`），帮助 Agent 进行静默环境核对。

### 1.4 单机游戏 S/L 存档还原机制 (Save & Load Baseline)
类似于单机游戏中的存档与读档：
- **存档 (Save)**：每次通过三层验收后，立即执行 Git Commit，在 `docs/PROJECT_STATE.md` 中记录基线 SHA。
- **读档 (Load)**：当 Agent 在某次尝试中改坏工程或产生幻觉时，下发指令要求 Agent **放弃错误尝试，恢复至最近的稳定 Commit**，重新从干净基线开工。

### 任务 1：使用 `/init` 指令生成并落盘项目最高规约 `CLAUDE.md` (Harness 建立阶段)

**操作步骤**：

**步骤 1：在 CLI 中下发官方内置指令 `/init`**

*(Agent 会自动探查当前工程的 package.json、vite.config.ts 与文件结构，在项目根目录自动生成 CLAUDE.md 初稿)*

```text
2. 严禁擅自 install 未在需求卡中确认的第三方 npm 包；
3. 严禁修改 vite.config.ts 与基础路由配置；
4. 每次修改代码前必须主动读取相关文件，禁止凭空臆测上下文。
```

### 任务 3：工程巡检、更新 PROJECT_STATE.md 与稳定 Commit (Verify & Commit 阶段)

**操作指令**：
1. 运行项目全量巡检：
   `powershell -ExecutionPolicy Bypass -File .\scripts\verify-student-project.ps1`
2. 确认输出 `[PASS]`，更新 `docs/PROJECT_STATE.md`：
   - 将 **L05 课程状态** 改为 `PASS`；
   - 记录最新基线 Commit SHA。
3. 执行 Git 稳定提交：
```bash
git status
git add -- CLAUDE.md
git add -- docs/PROJECT_STATE.md
git commit -m "feat: setup CLAUDE.md project harness and verify clean baseline"
```

## 3. 学员课后记忆卡与退场测试 (Exit Ticket & Misconceptions)

### ✍️ 学员概念互动填空 (Interactive Concept Fill-in-the-Blanks)
1. **最高工程规约**：根目录下的 **`CLAUDE.md`** 是 Agent 每次对话前强制读取的最高规范，用于锁定包管理器、框架规约与安全防错红线。
2. **三分记忆模型**：聊天窗口属于 **工作记忆**（随会话结束而清空）；`PROJECT_STATE.md` 属于 **外部长期记忆**（跨会话继承）；Git Commit 节点属于 **版本证据**（物理可追溯）。
3. **环境脱幻 (解药 1)**：在修改代码前，要求 Agent **先读取工程实际文件与依赖版本**，严禁凭借凭空假设进行编写。
4. **S/L 存档还原**：当 Agent 产生幻觉或改坏配置时，应下发指令要求其 **放弃错误尝试并还原回最近的稳定 Git Commit 基线**。

### 💡 常见概念误区与正确理解 (Misconceptions vs. Correct Engineering Reality)

| 常见误区 (Misconception) | 正确硬核理解 (Correct Engineering Reality) | 如何纠偏与护栏防护 (Remedy & Guardrails) |
| :--- | :--- | :--- |
| **误区 1：“让 AI 自由选择安装流行的第三方库效率更高”** | 擅自安装未知依赖容易导致版本冲突、打包体积膨胀甚至引入恶意代码，生产环境物理禁止。 | 在 `CLAUDE.md` 中写入依赖禁令，触发护栏物理拦截未授权 install。 |
| **误区 2：“以为在聊天窗口里说过的规则 AI 永远记得”** | 聊天窗口属于工作记忆，随着对话变长（Context 满溢），前面的规则会被自动挤出蒸发。 | 将项目规约写入 `CLAUDE.md`，将业务事实写入 `PROJECT_STATE.md` 外部长期记忆。 |
| **误区 3：“项目改坏了就不断发指令让 AI 尝试修复”** | 在污染的错代码上继续修复会导致错误叠加，如同在流沙上建塔。 | 运用 S/L 存档机制，一键放弃错误尝试，还原回最近的稳定 Git Commit 基线。 |
| **误区 4：“CLAUDE.md 是给程序员看的说明文档”** | `CLAUDE.md` 是专门写给 AI Agent 看的系统级 Prompt 护栏，具有最高优先级的指令效力。 | 项目起手即配置 `CLAUDE.md`，死死约束 Agent 修改边界。 |

### 🎯 退场测试题 (Exit Ticket)

* **问题 1**：为什么不能把项目规约只保存在聊天窗口里，而必须落盘到 `CLAUDE.md`？
* **参考答案**：
  - 聊天窗口属于“工作记忆”，会随对话变长或新开会话而蒸发丢失；落盘到 `CLAUDE.md` 属于物理工程护栏，Agent 每次对话前都会强制读取，能够跨会话保持最高约束力。
* **问题 2**：当 Agent 产生严重幻觉或改坏工程配置时，最正确的处理动作是什么？
* **参考答案**：
  - 运用 S/L 存档机制，立即下发指令要求 Agent“放弃当前错误尝试，恢复至最近的稳定 Git Commit”，重新从干净基线开工，绝不在污染的代码上叠加修改。
