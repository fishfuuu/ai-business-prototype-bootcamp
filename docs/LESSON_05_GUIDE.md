# 第五课学员操作指南 — 建立不会轻易失控的项目：工程 Harness 护栏与记忆机制

> 💡 **本课的核心思想只有一句话：**  
> **不要信任 AI 的短期口头承诺，用 `CLAUDE.md` 物理护栏与磁盘记忆锁定 Agent 的所有行为红线。**

---

## 一、 本课背景、底层原理与学习目标

### 1.1 业务背景与真实痛点
在跨会话或多人协同的 AI 开发中，最让人头疼的问题是：**AI 经常产生“幻觉”或“遗忘”**。例如，对话进行了 30 轮后，AI 突然忘记了团队统一使用 `npm` 的规定，擅自使用了 `yarn` 或 `pnpm` 安装第三方包；或者在修改代码时擅自改动了未授权的系统核心路由，导致工程环境被搞崩。

### 1.2 宏观安全治理与记忆流转闭环
本课的核心工程机制，是将项目安全红线与会话记忆治理纳入一条**“物理挂载 ➔ 规范拦截 ➔ 盘存留痕 ➔ 上下文提纯 ➔ 断点恢复”**的受控闭环中：
1. **物理挂载与规范拦截**：根目录下的 `CLAUDE.md` 护栏在每轮对话开端自动物理挂载至 Prompt 顶部，拦截越界文件修改与非法包管理器指令。
2. **磁盘盘存与进度留痕**：通过 `IMPLEMENTATION_PLAN.md` 物理文件将 Step 状态与 SHA 记录持久化存在本地磁盘，脱离对聊天窗口短期记忆的依赖。
3. **上下文提纯与断点恢复**：通过 `/compact` 指令定期清理压缩过期对话 Token；在重新开机或断电后，直接读取磁盘状态机文件 1 秒无缝恢复开发断点。

### 1.3 核心学习目标
完成本课实操后，你将能够：
1. 掌握使用原生 `/init` 命令行指令，秒级生成并配置项目专属的 `CLAUDE.md` 护栏。
2. 掌握使用 `/compact` 清理提纯短期上下文，结合 `CLAUDE.md` 彻底消除 AI 幻觉与规则遗忘。
3. 掌握断电/重新开机场景下的 S/L 存读档状态恢复机制 (`State Restore`)。

## 二、 💡 本课核心工程概念卡 (Core Concepts)

### 核心概念 1：Engineering Harness (工程鞍具 / 物理护栏)
- **硬核工程定义**：为了约束 AI Agent 行为边界而建立的物理配置文件、自动化校验脚本与权限防火墙组合。
- **底层运作机制**：在 Agent 发起系统调用或修改代码前，强制读取 Harness 规则，违规指令直接被防火墙拦截。
- **具象业务比喻**：**赛马的鞍具与缰绳** 🏇。给野马戴上鞍具和缰绳，骑手（主管）才能精准把控方向，确保 AI 奔跑时不脱轨。
- **IT 沟通场景**：“我们为项目部署了工程 Harness 护栏，物理锁定了包管理器与编码规则，确保 AI 生成的代码安全可控。”

### 核心概念 2：三分记忆模型 (3-Layer Memory Architecture)
- **硬核工程定义**：将 AI Agent 的记忆划分为“长期物理记忆 (`CLAUDE.md`)”、“中期进度记忆 (`IMPLEMENTATION_PLAN.md`)”与“短期对话缓存 (Context Buffer)”的三层解耦架构。
- **底层运作机制**：长期规则在每轮对话开始时物理挂载在 Prompt 顶部；中期进度通过磁盘文件防丢；短期缓存随对话增长定期使用 `/compact` 提纯。
- **具象业务比喻**：**公司章程(长期) + 盘点账本(中期) + 电话临时记事本(短期)** 📝。
- **IT 沟通场景**：“项目建立了三分记忆模型，有效防止了 AI 随着对话轮数增多而产生 Token 溢出与规则遗忘。”

### 核心概念 3：S/L 存读档状态恢复机制 (State Save / Load Restore)
- **硬核工程定义**：通过读取磁盘上持久化的状态机文件，无缝重建 LLM 上下文注意力锚点并恢复断点任务的机制。
- **底层运作机制**：在中断对话或重新开机后重新唤醒 Agent，下发恢复指令，Agent 会直接从磁盘读取 `current_waiting_step` 恢复上下文。
- **具象业务比喻**：**单机游戏的 S/L 存档与读档** 🎮。随时保存当前通关进度，关机重开后 1 秒载入最新关卡。
- **IT 沟通场景**：“我们支持 S/L 存读档状态恢复，跨会话开发时 1 秒无缝接续上一次的实施进度。”

## 四、 🛠️ 课堂实操与自学导引任务清单

### Task 1: 使用原生 `/init` 指令生成基础护栏

#### ⚡ 极速操作步骤
1. 打开 Claude Code CLI 窗口，输入原生初始化指令：
   ```text
   /init
   ```
2. AI 将自动扫描当前项目目录，并在根目录下生成基础的 `CLAUDE.md` 文件。

#### 💡 独立自学原理解析
> **原生 `/init` 指令的物理本质**  
> `/init` 是 Claude Code CLI 的内置原生 Slash Command。运行后，AI 会自动扫描工程中的 `package.json`、`tsconfig.json` 等文件，分析项目架构并自动生成 `CLAUDE.md` 框架。这避免了手动从头编写配置文件的繁琐。

---

### Task 2: 补充 4 大防错红线并盖章落盘

#### ⚡ 极速操作步骤
1. 检查生成的 `CLAUDE.md`，要求 AI 补充以下 4 大物理防错红线：
   - 规则 1：**包管理器硬约束**：强制统一使用 `npm`，绝对禁止混用 `yarn` 或 `pnpm`。
   - 规则 2：**边界控制**：禁止修改未在 `allowed_files` 许可范围内的任何文件。
   - 规则 3：**代码规范**：优先使用 Early Return（早期返回），消除深层嵌套。
   - 规则 4：**异常捕获**：强制进行边界条件检查与 Error Handling。
2. 在聊天窗口下发盖章落盘口令：
   ```text
   同意保存 CLAUDE.md 项目护栏配置
   ```
3. 打开工程根目录下的 [`CLAUDE.md`](file:///d:/AILearning/CLAUDE.md)，确认 4 大红线已成功落盘。

#### 🔍 护栏配置结构预览
```markdown
# 项目工程护栏 (CLAUDE.md)

## 构建与测试命令
- 构建：npm run build
- 类型检查：npm run typecheck

## 4 大防错红线
1. [包管理器禁令] 强制统一使用 npm，绝对禁止使用 yarn / pnpm。
2. [范围禁令] 修改代码前必须对照 IMPLEMENTATION_PLAN 中的 allowed_files。
```

### Task 3: 上下文提纯与 S/L 存读档演练

#### ⚡ 极速操作步骤
1. **测试 Harness 防护效果**：向 AI 提问：
   ```text
   我们可以用 yarn 安装一个新包吗？
   ```
   *预期回答*：AI 引用 `CLAUDE.md` 规则拒绝，并提示“根据项目 Harness 规定，禁止使用 yarn，必须统一使用 npm”。
2. **上下文提纯 (Compact)**：在 CLI 中输入：
   ```text
   /compact
   ```
   清理短期对话缓存，提纯核心上下文。
3. **S/L 存读档还原 (State Restore)**：关闭 CLI 窗口并重新打开，下发自然口令：
   ```text
   请读取 IMPLEMENTATION_PLAN 恢复当前 Step 状态
   ```
   *预期效果*：AI 在 1 秒内读取磁盘中期记忆，精准汇报“已恢复进度：当前处于 Step 2 READY 状态”。

#### 💡 独立自学原理解析
> **为什么对话多了 AI 会变傻（幻觉）？**  
> LLM 的上下文窗口 (Context Window) 是有限的。当对话达到数万 Token 时，注意力机制被分散，AI 就会忘记第 1 轮对话里订立的规则。使用 `/compact` 可以压缩清理过期对话，而 `CLAUDE.md` 作为磁盘硬文件，在每一轮对话开始时都会被物理重新挂载，保证 AI 永不遗忘红线。

## 五、 💡 常见概念误区与正确理解 (Mindset Transformation)

| 常见误区 (Misconception) | 正确硬核理解 (Correct Engineering Reality) | 如何纠偏与护栏防护 (Remedy & Guardrails) |
| :--- | :--- | :--- |
| **误区 1：“把所有业务规则粘贴在聊天框里，AI 就绝对不会忘”** | 聊天框是短期记忆（Context Buffer），随着对话轮数增多必然面临 Token 溢出与注意力衰减（AI 幻觉）。 | 实行“三分记忆模型”，把长期红线写进 `CLAUDE.md`，中期计划写进 `IMPLEMENTATION_PLAN.md`。 |
| **误区 2：“`CLAUDE.md` 需要手动一行行从头撰写”** | 官方原生 `/init` 指令会自动一键扫描目录架构并生成初稿，学员只需补充 4 大防错红线。 | 在 CLI 中输入 `/init` 自动生成初稿框架，消除配置文件的恐惧感。 |
| **误区 3：“中断对话或断电后，只能重头向 AI 重新解释背景”** | 实施计划与配置均保存在本地磁盘物理文件中，恢复会话只需要 1 秒读取磁盘状态。 | 下发 `请读取 IMPLEMENTATION_PLAN 恢复当前 Step 状态`，一秒完成 S/L 存读档恢复。 |
