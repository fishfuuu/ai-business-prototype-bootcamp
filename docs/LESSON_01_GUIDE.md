欢迎开始第一课！在这节课中，你不仅会做出一个真正可以在浏览器中交互的企业系统页面，还将亲身体验并理解 AI Agent 是如何工作的。

## 0. 这节课解决什么问题

### 核心问题
> **Claude 为什么不只是聊天，还可以帮助你真正完成一个业务页面？**

下课时，你不仅拥有属于自己的系统雏形，还能清晰说明 **LLM、Tools、Agent、ReAct、Workflow**，以及 **Prompt (现场要求)、CLAUDE.md (长期规则)、Context (短期记忆)、Mock Data (演戏道具)、127.0.0.1 (本地试衣镜) 和 Human-in-the-Loop (人在回路盖章)** 是如何协同工作的。

```text
+-----------------------------------------------------------------------------------+
|                                 Workflow 框架                                     |
|  (需求 -> 方案 -> 人在回路[主管盖章] -> Agent执行 -> 验证 -> 试衣镜预览 -> 微调)   |
|                                                                                   |
|    +-------------------------------------------------------------------------+    |
|    |                            Claude Code Agent                            |    |
|    |                                                                         |    |
|    |   +------------------+     +-------------------+    +---------------+   |    |
|    |   |    LLM (大脑)    |     |  规则/Context(眼睛)|    |  Tools (手脚) |   |    |
|    |   | 理解需求、推理方案|     | Prompt/CLAUDE.md  |    | 读取/修改/运行|   |    |
|    |   +--------+---------+     +---------+---------+    +-------+-------+   |    |
|    |            |                         |                      |           |    |
|    |            +-------------------------+----------------------+           |    |
|    |                                      |                                  |    |
|    |      ReAct 循环 (行动 -> 观察工具返回或验证结果 -> 根据结果调整 -> 再次行动)|
|    +-------------------------------------------------------------------------+    |
|                                                                                   |
|    数据支撑：Mock Data (演戏道具)           展示窗口：127.0.0.1 (本地试衣镜)       |
+-----------------------------------------------------------------------------------+
```

一句话记住 Agent 的工作原理：
> **Claude Code 是一个以 LLM 为大脑、以 Prompt 和 CLAUDE.md 为眼睛/耳朵（现场要求与长期规则）、以 Tools 为手脚，能够在已授权范围内组织多步行动、调用 Tools，并依据工具返回或验证结果进行 ReAct 调整，同时在 Workflow（业务阶段顺序与人在回路盖章卡口）中接受主管控制的执行者。**

## 2. Task 1：LLM 理解你的业务需求 (15 分钟)

### 💡 知识卡：LLM (大脑)、Context (短期记忆)、角色区分与 Mock Data (演戏道具)
* **LLM（大语言模型）** 是 AI 的“大脑”。它负责理解你的业务语言并生成页面方案。**在这一步，我们不主动调用新的文件读取或修改 Tools，重点观察 LLM 对业务输入的理解与方案生成能力。**
* 此时你的输入存放在 **Context（当前对话的短期记忆对讲机）** 中。
* ⚠️ **角色澄清**：你在下面输入的“主要使用者”是**你要创建的系统的目标使用者**；**你自己才是控制 Claude Code 的最高主管！**
* 💡 **演戏道具说明**：第一版页面只使用 **Mock Data（模拟数据演戏道具）**，数据写在前端代码中，不接生产数据库。如果想要更多测试数据，直接告诉 Claude `请在页面中再增加两条模拟数据` 即可。

### 💡 请先判断你要制作的是哪一类业务原型：

```text
[ ] A. 监控与决策型：适合经营分析、异常监控、投产分析、履约预警 (看指标 -> 看异常 -> 看明细 -> 决策)
[ ] B. 任务与流程型：适合预算申请、退货处理、工单派发、单据审批 (创建记录 -> 处理任务 -> 状态流转 -> 推进下一步)
[ ] C. 操作工具型：适合文案生成、规则计算、数据整理、格式转换 (输入内容 -> 规则处理 -> 输出结果 -> 确认/复制/导出)
```

**不同原型的思考重点与简短示例**：

* **A. 监控与决策型**：
  - **思考**：要看什么指标？发现什么异常？看完后做出什么判断或决策？
  - **示例**：保留异常指标、风险明细和筛选条件；暂不制作复杂趋势图；主要操作为“查看异常详情”或“发送催单提醒”。
* **B. 任务与流程型**：
  - **思考**：谁发起？谁处理？记录有哪些状态？用户能执行什么动作？动作完成后状态如何变化？
  - **示例**：保留待办记录、当前状态和负责人；暂不实现真实跨部门通知；主要操作为“同意”“退回”或“推进下一步”。
* **C. 操作工具型**：
  - **思考**：用户输入什么？系统执行什么处理？输出什么结果？结果是否需要人工确认、修改、复制或导出？
  - **示例**：保留输入区、处理参数和结果预览；暂不接入真实 AI 服务或批量文件；主要操作为“生成”“确认”“复制”或“导出”。

### 请准备好以下 5 项业务输入：
1. **系统名称**：（例如：供应商履约预警台 / 预算申请审批流 / 活动文案生成小工具）
2. **原型类型与主要使用者**：（例如：A. 监控与决策型 / B. 任务与流程型 / C. 操作工具型；使用者：运营主管）
3. **具体业务问题**：（例如：无法实时跟进退货审批状态与跨部门派单）
4. **页面最重要的内容**：（例如：监控型看指标异常、流程型看待办任务列表与当前状态、工具型看输入与输出区）
5. **进入页面第一个操作**：（例如：筛选记录、点击“同意/驳回”审批按钮、或点击“生成”按钮）

### 复制并发送给 Claude Code：

```text
我要创建一个【系统名称】。

原型类型属于【监控与决策型 / 任务与流程型 / 操作工具型】，主要使用者是【角色】。

他们现在的问题是【具体业务问题】。

页面最重要的是看到【关键指标与异常 / 待办任务与当前状态 / 输入要求与输出结果】。

使用者进入页面后首先要执行【操作】。

第一版只使用模拟数据（Mock Data），不接真实接口。

请先不要读取项目文件，也不要修改任何代码。
请用你自己的话复述我对需求的理解，并提出第一版页面的初步模块规划方案。
```

### 🚩 本步检查 (Checklist)
- [ ] Claude Code 用自己的话复述了你的业务需求。
- [ ] Claude 提出了页面模块规划，但**没有读取项目，也没有修改任何代码**。

### 🧠 本步记忆复述
* **问**：Claude 刚才生成方案时，修改你电脑上的项目了吗？
* **答**：没有。Claude 此时没有执行本轮文件修改，只输出了需求理解和页面方案。

## 3. Task 2：Tools 让 Claude 戴上眼睛看项目 (10 分钟)

### 💡 知识卡：Prompt (现场要求)、CLAUDE.md (长期规则) 与 Tools (手脚能力)
* **Prompt 是现场指令（听觉）**，告诉 AI 当前的具体任务；**`CLAUDE.md` 是长期项目规则（视觉/校规）**，规定了代码风格与结构规范。
* **Tools（工具机制）** 是 Agent 的“手和脚”。它既能帮你在后台翻看文件，也能帮你在终端敲键盘运行验证脚本。

🔍 **查阅项目通用组件库**：你可以在项目根目录中查看权威文档 [docs/COMPONENT_CATALOG.md](./COMPONENT_CATALOG.md)，了解项目内置可直接复用的通用组件。

### 复制并发送给 Claude Code（只读指令）：

```text
现在，请戴上眼睛，使用 Tools 读取项目中的真实文件：
- CLAUDE.md
- DESIGN.md
- docs/COMPONENT_CATALOG.md
- src/router/index.ts
- src/components/layout/AppSidebar.vue

请根据读取到的项目规则与组件库，向我说明：
1. 本项目已有的设计规范与可复用组件
2. 准备修改或新增的文件列表
3. 针对第一版页面的结构修订建议
4. 本次明确不做的内容

在得到我明确许可前，请绝对不要修改或创建任何文件。
```

### 🚩 本步检查 (Checklist)
- [ ] Claude 调用 Tools 读取了 `CLAUDE.md` 等配置文件。
- [ ] Claude 列出了准备修改的文件，但**尚未开始修改**。

## 4. Task 3：Workflow 顺序与人在回路盖章 (15 分钟)

### 💡 知识卡：Workflow (流程顺序与门禁) 与 Human-in-the-Loop (人在回路盖章)
* **Workflow** 规定了软件研发的先后顺序：`需求 -> 方案 -> 人在回路授权 -> 修改代码 -> 运行验证`。
* **Human-in-the-Loop (人在回路)**：你是系统的最高 CEO。在 Agent 执行修改前，必须由你下达明确指令（“同意方案，请开始修改代码”），Agent 才能动手。

### 复制并发送给 Claude Code（主管裁决与授权模板）：

```text
针对你的方案，我的裁决如下：

1. 必须保留：
【填写所选原型必须保留的业务内容】

2. 本轮暂不实现：
【填写第一版明确不做的内容】

3. 主要操作调整为：
【填写使用者最重要的操作】

4. 业务范围保护：
不得擅自改变已确认的字段含义、状态规则、处理逻辑或页面范围。

请复述你理解的修改范围，并列出准备新增或修改的页面、路由与侧边栏文件。

在我明确回复“同意方案，请开始修改代码”前，不要修改任何文件。
```

当 Claude 复述完并等待授权时，发送最终授权口令：
`同意方案，请开始修改代码`

### 🚩 本步检查 (Checklist)
- [ ] 页面符合学员选择的原型类型。
- [ ] Claude 只修改了确认范围内的文件。
- [ ] 页面、路由与侧边栏在 `http://127.0.0.1:8888` 试衣镜中可正常访问使用。
- [ ] `verify-student-project.ps1` 验证脚本运行通过。

## 5. Task 4：ReAct 循环与 1 次人在回路微调闭环 (10 分钟)

### 💡 知识卡：ReAct 循环 (行动 -> 观察工具返回或验证结果 -> 根据结果调整 -> 再次行动)
* **ReAct** 是 Agent 的能力循环：`行动 -> 观察工具返回或验证结果 -> 根据结果调整 -> 再次行动`。无论是运行脚本提示验证成功或失败，还是看到浏览器页面渲染效果，都是 Agent 观察的依据。

### 找到你所选原型的微调改善点：
请在本地试衣镜中观察页面，找到一个与你所选原型最相关、最影响使用者理解或操作的改善点：

* **A. 监控与决策型**：异常状态不醒目；关键指标层级不清楚；决策按钮不容易发现。
* **B. 任务与流程型**：当前状态不清楚；下一步动作不明确；待办与已处理记录难以区分。
* **C. 操作工具型**：输入要求不清楚；执行按钮不突出；输出结果缺少确认、复制或导出入口。

### 复制并发送给 Claude Code（通用微调模板）：

```text
我在本地试衣镜中发现以下问题：

【描述一个最影响理解或操作的问题】

请先复述你理解的修改范围。
不要改变其他业务内容。
在我确认后，只修改这一项并重新运行验证。
```

确认 Claude 复述无误后，发送：`同意方案，请开始修改代码`。

## 6. 完成标准

### 对应三类原型的完成标准：

#### 监控与决策型完成页面：
- [ ] 包含一个关键信息或异常展示区域；
- [ ] 包含一个可执行的决策动作。

#### 任务与流程型完成页面：
- [ ] 包含一个任务或记录区域；
- [ ] 包含一个清晰的当前状态；
- [ ] 包含一个处理动作。

#### 操作工具型完成页面：
- [ ] 包含一个输入区域；
- [ ] 包含一个执行动作；
- [ ] 包含一个结果展示区域。

#### 三类原型共同完成要求：
- [ ] 页面可在 `http://127.0.0.1:8888` 试衣镜正常打开；
- [ ] 侧边栏专属业务菜单入口可用；
- [ ] 基于虚构模拟数据呈现；
- [ ] 至少包含一个可点击的交互动作；
- [ ] 运行 `powershell -ExecutionPolicy Bypass -File .\scripts\verify-student-project.ps1` 提示 `[PASS]`；
- [ ] 至少完成 1 次人在回路的 ReAct 微调闭环。

## 7. 验证与保存成果

完成修改后，请进行以下 4 项验证与成果保存：

1. **运行验证脚本**：在 PowerShell 终端运行 `powershell -ExecutionPolicy Bypass -File .\scripts\verify-student-project.ps1`，确保提示 `[PASS]`。
2. **本地试衣镜效果核对**：刷新浏览器 `http://127.0.0.1:8888`，确认页面样式正常、侧栏导航可点击且无报错红字。
3. **交互验证**：实际点击一次页面中的操作按钮，确认出现预期的反馈结果。
4. **截屏保存**：截取包含浏览器页面和 PowerShell `[PASS]` 结果的画面，作为本课成果留存。

## 8. 第一课记忆卡

请在课后填好这份概念记忆卡，确保你能用自己的话向他人复述：

* **LLM (大脑)**：理解业务需求并规划页面方案的大语言模型。
* **Tools (手脚)**：读取项目规则文件、创建修改代码、运行终端验证脚本的具体工具能力。
* **Agent (执行者)**：获得目标和工具后，能在主管下达的已授权范围内连续完成多步工作的智能体。
* **Workflow (框架与门禁)**：按“需求 -> 方案 -> 人在回路授权 -> 修改代码 -> 运行验证”顺序推进，并设有人在回路确认门禁的业务流程。
* **Mock Data (演戏道具)**：写在前端代码中的模拟业务数据，用于快速验证视觉与交互，无需连接真实后端。
* **验证脚本 (检验员)**：运行 `verify-student-project.ps1` 自动检查语法和文件结构，确保项目没有被改崩。

## 9. 常见问题与安全救援

### 常见问题与解决办法
1. **端口被占用或浏览器打不开**：
   - 检查 `start-project.bat` 是否还在运行；若端口冲突，关闭窗口重新双击启动。
2. **验证脚本提示语法错误**：
   - 将终端红字直接复制给 Claude：`验证脚本报错，请修复该语法错误`，授权 Claude 进行 ReAct 修复。

### 🚨 核心安全救援指令
如果 Claude 在你未回复“同意方案，请开始修改代码”之前就擅自修改了文件，或者改动超出了你的裁决范围，**请立即发送以下救援指令**：

```text
请立即停止继续修改。
先列出刚才修改的文件和具体内容，不要再改动。
等待我确认是否仅撤销本轮未经授权的修改。
然后按照Task要求先输出需求理解和页面规划。
```
