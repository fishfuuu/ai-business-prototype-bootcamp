# 第一课学员操作指南 — 从业务问题创建第一个系统页面：Tools 沙箱与 127.0.0.1 试衣镜

> 💡 **本课的核心思想只有一句话：**  
> **不要用键盘瞎敲代码，先搭建一个安全的试衣镜与模拟数据环境。**

---

## 一、 本课背景、底层原理与学习目标

### 1.1 业务背景与真实痛点
非技术主管在尝试使用 AI 进行业务原型开发时，往往第一步就卡在“环境搭建与代码失控”上。有人直接在聊天框里粘贴数页需求，让 AI 输出无法运行的孤立代码片段；有人在缺乏隔离的环境中运行 AI 指令，担心 AI 误删本地敏感文件或搞崩现有配置。

### 1.2 宏观受控闭环
本课的核心工程机制，是将业务原型的创建纳入一条**“问题解构 ➔ 本地试衣镜渲染 ➔ 沙箱工具鉴权 ➔ 模拟数据隔离 ➔ 状态追踪”**的受控闭环中：
1. **本地试衣镜与安全沙箱**：通过本地 Vite 页面（`http://127.0.0.1:5173/`）作为肉眼可见的“试衣镜”，结合命令行 `Tools 权限沙箱`，物理隔离外网与敏感系统操作。
2. **模拟数据红线**：严禁在原型开发初期连接真实数据库或生产 API，统一采用静态前端 Mock 数据。
3. **全局状态物理盘点**：每一次迭代与变更，均物理记录在磁盘根目录的 [`docs/PROJECT_STATE.md`](file:///d:/AILearning/docs/PROJECT_STATE.md) 状态清单中。

### 1.3 核心学习目标
完成本课实操后，你将能够：
1. 掌握使用 CLI 工具与 ReAct 单步自修模式，在 15 分钟内搭建并运行第一个高保真前端系统。
2. 理解 `Tools 权限沙箱` 的物理防护原理，掌握安全的本地试衣镜调试方法。
3. 掌握使用 [`docs/PROJECT_STATE.md`](file:///d:/AILearning/docs/PROJECT_STATE.md) 追踪并更新原型工程状态。

## 二、 💡 本课核心工程概念卡 (Core Concepts)

### 核心概念 1：Tools 权限沙箱与 127.0.0.1 试衣镜
- **硬核工程定义**：LLM 客户端与本地操作系统之间建立的指令隔离屏障，以及基于本地回环地址（127.0.0.1）的实时 DOM 渲染界面。
- **底层运作机制**：AI 在执行文件读写或终端命令前，必须匹配预设的白名单工具权限；浏览器通过 Vite HMR 热重载机制秒级刷新 DOM。
- **具象业务比喻**：**商场的服装试衣镜与防盗安全门** 🪞。试衣镜只用于穿搭预览（DOM 渲染），安全门防止未经授权把未付费商品带出商场（沙箱权限）。
- **IT 沟通场景**：“我们基于 127.0.0.1 本地回环与 Tools 沙箱搭建了高保真原型试衣镜，确保开发过程不污染线上环境。”

### 核心概念 2：模拟数据防错红线 (Mock Data Guardrails)
- **硬核工程定义**：在原型开发阶段物理禁止调用任何真实后端 API 或数据库，仅允许使用前端 JSON/TypeScript 模拟对象。
- **底层运作机制**：前端组件直接绑定本地 Mock 数据源，消除因为后端接口报错、网络延迟或权限失效导致的调试挂起。
- **具象业务比喻**：**房屋样板间的塑料假电视** 📺。外观 100% 真实展示视觉布局，但不需要接通真实电视信号。
- **IT 沟通场景**：“原型阶段严格遵循模拟数据防错红线，优先验证交互与业务逻辑，降低对接成本。”

### 核心概念 3：工程状态机与磁盘盘点 (`PROJECT_STATE.md`)
- **硬核工程定义**：在项目根目录维护的纯文本 Markdown 文件，用于记录原型系统的模块就绪度、复选框状态与技术债务。
- **底层运作机制**：AI 在每次完成页面修改后，必须增量修改 `PROJECT_STATE.md` 的状态标记，作为跨会话的记忆载体。
- **具象业务比喻**：**施工现场的进场施工进度牌** 📋。向所有工头（讲师与主管）物理展示当前打地基、装水电的进度。
- **IT 沟通场景**：“项目状态收扣在 `PROJECT_STATE.md` 中，随时可审计原型模块的完成度。”

## 四、 🛠️ 课堂实操与自学导引任务清单

### Task 0: 启动本地试衣镜与环境检查

#### ⚡ 极速操作步骤
1. 打开 VS Code 终端，启动本地开发服务：
   ```powershell
   npm run dev
   ```
2. 打开浏览器访问 `http://localhost:5173/`，确认看见训练营初始原型试衣镜大盘。

#### 💡 独立自学原理解析
> **为什么必须在 127.0.0.1 试衣镜中预览？**  
> 纯文本的代码不是最终产品，主管眼睛看到并能用鼠标点击的才是真实原型。启动本地 Vite 服务后，代码的每一次保存都会瞬间反应在浏览器中。

---

### Task 1: 唤醒 AI 助手创建首个业务原型页面

#### ⚡ 极速操作步骤
1. 在 Claude Code CLI 中下发页面创建指令：
   ```text
   请在 src/views/ 目录下创建一个新的工单看板页面 WorkOrderBoard.vue，包含列表与简单筛选。
   ```
2. 观察终端输出，AI 通过 `Tools 权限沙箱` 自动创建并修改受控文件。

#### 🔍 代码 Before vs After 视觉对比
```diff
+ <!-- src/views/WorkOrderBoard.vue -->
+ <template>
+   <div class="work-order-board">
+     <h2>工单处理看板</h2>
+     <!-- 静态 Mock 数据列表渲染 -->
+   </div>
+ </template>
```

#### 💡 独立自学原理解析
> **ReAct 范式的单步自修物理过程**  
> 当 AI 发现语法错误或缺少导入时，会在 Tools 沙箱约束下自动重新读取文件并修复，直到页面成功编译，无需人类手动改代码。

---

### Task 2: 绑定静态 Mock 数据源并验证交互

#### ⚡ 极速操作步骤
1. 检查页面上展示的数据是否均来自前端 Mock 数据源。
2. 在浏览器中点击页面上的筛选与排序按钮，确认无报错日志。

#### 💡 独立自学原理解析
> **为什么原型阶段坚决拒绝生产数据库？**  
> 连接生产数据库会导致开发速度下降 90%，且存在物理破坏线上数据的巨大风险。使用 Mock 数据可以极速验证业务流程与界面体验。

---

### Task 3: 磁盘状态盘点与 `PROJECT_STATE.md` 更新

#### ⚡ 极速操作步骤
1. 打开 [`docs/PROJECT_STATE.md`](file:///d:/AILearning/docs/PROJECT_STATE.md)，检查模块清单。
2. 要求 AI 更新进度：
   ```text
   请更新 docs/PROJECT_STATE.md，将工单看板模块标记为已创建。
   ```

## 五、 💡 常见概念误区与正确理解 (Mindset Transformation)

| 常见误区 (Misconception) | 正确硬核理解 (Correct Engineering Reality) | 如何纠偏与护栏防护 (Remedy & Guardrails) |
| :--- | :--- | :--- |
| **误区 1：“用 AI 编程就是在大模型网页聊天框里聊天”** | 网页聊天框无法直接读写本地文件与触发 HMR 热重载，生成的文本代码无法实时验证。 | 使用 VS Code 终端与 Claude Code CLI，配合 127.0.0.1 本地试衣镜实操。 |
| **误区 2：“原型开发第一步必须先设计后端数据库表”** | 原型阶段的核心是验证业务想法与界面交互，直接连数据库会陷入复杂的配置泥潭。 | 严格执行静态 Mock 数据防错红线，物理解耦前端界面与后端接口。 |
| **误区 3：“让 AI 随意在磁盘任意位置新建或删除文件”** | 缺乏权限隔离的 AI 命令可能误删电脑上的重要文件或修改系统环境。 | 部署 `Tools 权限沙箱`，物理限制 AI 仅能在受控工程目录下进行文件读写。 |
| **误区 4：“做完功能后不需要记录项目状态”** | 不记录状态会导致下一次唤醒 AI 时，AI 忘记上一次写了哪些页面。 | 强制更新 [`docs/PROJECT_STATE.md`](file:///d:/AILearning/docs/PROJECT_STATE.md)，作为磁盘物理状态记录。 |

## 六、 ❓ 常见操作报错与 Troubleshooting 指南

| 报错/异常现象 | 物理原因 | 解决与纠偏方案 |
| :--- | :--- | :--- |
| 浏览器打开 `localhost:5173` 提示连接拒绝 | Vite 开发服务器未在终端中启动 | 在终端重新运行 `npm run dev` 并保持窗口运行。 |
| AI 提示无法写入系统敏感目录 | 触发了 Tools 权限沙箱保护 | 确认要求 AI 修改的文件是否在工程根目录 `src/` 或 `docs/` 下。 |
