# 第一课学员操作指南 — 从业务问题创建第一个系统页面：LLM、Tools、Agent 与三类业务原型

> 💡 **本课的核心思想只有一句话：**  
> **理解 LLM 大脑、Tools 手脚与 Agent 执行者的关系，行使人在回路授权，建立第一个受控原型。**

---

## 一、 本课背景、底层原理与学习目标

### 1.1 业务背景与真实痛点
非技术主管在尝试使用 AI 进行业务原型开发时，最常踩的坑就是在大模型网页聊天框中盲目复制无用代码，或者因为不清楚 AI 的能力边界，把“大模型本身”与“具备读写能力的 Agent”混为一谈。缺乏规范约束时，生成的代码既无法在本地运行，也无法精准匹配自身部门的实际业务场景。

### 1.2 宏观受控闭环
本课的核心工程机制，是将业务原型的创建纳入一条**“需求解构 ➔ 方案推演 ➔ 人在回路授权 ➔ Agent 代码生成 ➔ 验证自测 ➔ 试衣镜预览 ➔ 微调闭环”**的受控流水线中：
1. **五位一体物理分工**：明确大模型 (LLM) 作为大脑负责推理，Tools 作为手脚负责读写磁盘，Agent 作为执行者在 ReAct 循环中自动修正，Workflow 门禁负责权限拦截。
2. **人在回路授权**：每一阶段的代码生成与盘点落盘，均必须经过主管在终端输入指令盖章确认。
3. **试衣镜与磁盘状态盘点**：通过 `http://127.0.0.1:5173/` 本地试衣镜进行可视化预览，并将每一次增量成果物理记录在根目录 [`docs/PROJECT_STATE.md`](file:///d:/AILearning/docs/PROJECT_STATE.md) 文件中。

### 1.3 核心学习目标
完成本课实操后，你将能够：
1. **识别与阐述** LLM（大脑）、Tools（手脚）、Agent（执行者）、ReAct（反馈循环）与 Workflow（流程门禁）5 大核心概念及其物理区别。
2. **区分与选择** 适合自身部门的三类业务原型（A. 监控决策型 / B. 任务流程型 / C. 操作工具型）。
3. **行使人在回路 (HITL) 授权**，利用 Workflow 确认门禁精准管控 Agent 修改代码的权限。
4. **验证与交付** 包含虚构模拟数据（Mock Data）的首个可运行页面，并获得验证脚本的 `[PASS]` 结论。

## 二、 💡 本课核心工程概念卡 (Core Concepts)

### 核心概念 1：LLM (大语言模型 / 大脑)
- **硬核工程定义**：基于 Transformer 架构的海量参数概率预测与自然语言推理引擎。
- **底层运作机制**：接收 Token 输入，根据上下文注意力机制推演下一步可能产生的代码文本与解决方案，本身物理上无法直接修改磁盘文件。
- **具象业务比喻**：**建筑工程总工程师** 👨‍🔬。坐在办公室里出设计图纸和施工方案，但不亲自下工地挥水泥铲。
- **IT 沟通场景**：“LLM 负责需求理解与方案推演，实际文件读写由 Tools 接口执行。”

### 核心概念 2：Tools (工具调用 / 手脚)
- **硬核工程定义**：Agent 客户端与宿主操作系统交互的 API 函数接口与命令行白名单工具集。
- **底层运作机制**：提供 `readFile`、`writeFile`、`executeCommand` 等原子化函数，使 AI 拥有物理读写磁盘与运行终端的能力。
- **具象业务比喻**：**施工现场的重型机械与工具箱** 🚜。包括挖掘机、起重机、电钻，是真正把设计图变成建筑物的物理手脚。
- **IT 沟通场景**：“Agent 必须通过受控的 Tools 工具箱读写磁盘，Tools 的权限受物理沙箱严格限制。”

### 核心概念 3：Agent (自主循环体 / 执行者)
- **硬核工程定义**：以 LLM 为核心决策大脑，具备目标拆解、工具调用、环境感知与自我修复能力的自主循环系统。
- **底层运作机制**：将复杂目标分解为多步 Task，在每次调用 Tools 后评估执行结果，直到达成预设的目标结论。
- **具象业务比喻**：**现场施工队长** 👷‍♂️。带上施工图纸（LLM）和机械（Tools），在工地盯盘，遇到积水或砖块不够时自动调整施工顺序。
- **IT 沟通场景**：“我们使用的是 Agent 架构，它能自主感知终端报错并尝试单步修复。”

### 核心概念 4：ReAct (推理-行动闭环 / 反馈循环)
- **硬核工程定义**：Reasoning and Acting 联合范式，即“思考 (Thought) ➔ 行动 (Action) ➔ 观察 (Observation)”的三步单步闭环。
- **底层运作机制**：AI 先给出思考推演，接着调用 Tools 执行行动，然后观察终端或编译器的返回日志，若报错则重新思考调整并再次行动。
- **具象业务比喻**：**师傅修水管的看试过程** 🔧。看一眼（Thought）➔ 拧紧螺丝（Action）➔ 看是否漏水（Observation）➔ 还漏水就再换个垫圈。
- **IT 沟通场景**：“Agent 在 ReAct 闭环中完成了代码的静态编译检查与自修。”

### 核心概念 5：Workflow (流程门禁 / 安全防护)
- **硬核工程定义**：为了防止 Agent 行为跑偏而建立的前置约束条件、状态机流转控制与规则规则链。
- **底层运作机制**：在 Agent 发起物理写操作前，匹配预设规则（如 `CLAUDE.md` 或文件目录白名单），违规指令直接被系统拒绝。
- **具象业务比喻**：**工地安全监理** 👮。即使队长想拆承重墙，安全监理手持规范手册坚决予以物理拦截。
- **IT 沟通场景**：“ Workflow 流程门禁锁定了 Agent 的权限边界，确保未授权目录不会被随意动用。”

### 核心概念 6：人在回路 (HITL - Human-in-the-Loop / 授权盖章)
- **硬核工程定义**：在 Agent 自动化循环的关卡节点上强制挂起，必须等待人类操作员裁决与授权后方可继续执行的设计。
- **底层运作机制**：当 Agent 准备保存计划、写代码或提交 Commit 时，触发暂停；只有主管在终端输入授权口令后，系统才解锁下一阶段。
- **具象业务比喻**：**财务付款的双签审批与出纳 U 盾** ✍️。无论财务软件多自动化，最后出纳付款前必须由部门主管在 U 盾上按确定键。
- **IT 沟通场景**：“项目严格执行人在回路 (HITL) 授权，Agent 无法在未经许可的情况下静默修改核心代码。”

### 核心概念 7：三类业务原型分类 (Three Business Prototype Classes)
- **硬核工程定义**：根据业务交互形态与数据流转特征划分的三种标准原型范式：监控决策型、任务流程型、操作工具型。
- **底层运作机制**：
  - **A. 监控决策型**：以仪表盘、看板、指标卡为主，强调全局数据呈现。
  - **B. 任务流程型**：以工单流转、审批节点、状态机为主，强调多步骤动作。
  - **C. 操作工具型**：以表单录入、批量处理、单页计算为主，强调高效输入。
- **具象业务比喻**：**医院的三个核心科室** 🏥。监控决策型是 ICUs 监视大屏，任务流程型是转诊分诊流水线，操作工具型是化验单打印机。
- **IT 沟通场景**：“本期原型确定为 B 类‘任务流程型’工单看板，优先验证流程状态机的完整性。”

## 五、 💡 常见概念误区与正确理解 (Mindset Transformation)

| 常见误区 (Misconception) | 正确硬核理解 (Correct Engineering Reality) | 如何纠偏与护栏防护 (Remedy & Guardrails) |
| :--- | :--- | :--- |
| **误区 1：“用 AI 编程就是在大模型网页聊天框里聊天”** | 网页聊天框只有 LLM 大脑，缺乏 Tools 手脚与 ReAct 循环，无法直接读写本地文件与触发试衣镜更新。 | 使用 VS Code 终端与 Claude Code CLI，配合 127.0.0.1 本地试衣镜实操。 |
| **误区 2：“原型开发第一步必须先设计后端数据库表”** | 原型阶段的核心是验证业务想法与界面交互，直接连数据库会陷入复杂的配置泥潭。 | 严格执行静态 Mock 数据防错红线，物理解耦前端界面与后端接口。 |
| **误区 3：“让 AI 随意在磁盘任意位置新建或删除文件”** | 缺乏权限隔离的 AI 命令可能误删电脑上的重要文件或修改系统环境。 | 部署 `Tools 权限沙箱`，物理限制 AI 仅能在受控工程目录下进行文件读写。 |
| **误区 4：“做完功能后不需要记录项目状态”** | 不记录状态会导致下一次唤醒 AI 时，AI 忘记上一次写了哪些页面。 | 强制更新 [`docs/PROJECT_STATE.md`](file:///d:/AILearning/docs/PROJECT_STATE.md)，作为磁盘物理状态记录。 |

## 六、 ❓ 常见操作报错与 Troubleshooting 指南

| 报错/异常现象 | 物理原因 | 解决与纠偏方案 |
| :--- | :--- | :--- |
| 浏览器打开 `127.0.0.1:5173` 提示连接拒绝 | Vite 开发服务器未在终端中启动 | 双击 `start-dev-server.bat` 或在终端重新运行 `npm run dev` 并保持窗口运行。 |
