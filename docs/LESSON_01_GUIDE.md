# 第一课学员指南：AI Agent 基础概念与首个页面制作

欢迎开始第一课！在这节课中，你不仅会做出一个真正可以在浏览器中交互的企业系统页面，还将亲身体验并理解 AI Agent 是如何工作的。

---

## 0. 这节课解决什么问题

### 核心问题
> **Claude 为什么不只是聊天，还可以帮助你真正完成一个业务页面？**

下课时，你不仅拥有属于自己的系统雏形，还能清晰说明 **LLM、Tools、Agent、ReAct、Workflow**，以及 **Prompt (现场要求)、CLAUDE.md (长期规则)、Context (短期记忆)、Mock Data (演戏道具)、127.0.0.1 (本地试衣镜) 和 Human-in-the-Loop (人在回路盖章)** 是如何协同工作的。

```text
+-----------------------------------------------------------------------------------+
|                                 Workflow 框架                                     |
|  (需求 -> 方案 -> 人在回路[主管盖章] -> Agent执行 -> 验证 -> 试衣镜预览 -> 微调)   |
|                                                                                   |
|    +-------------------------------------------------------------------------+    |
|    |                            Claude Code Agent                            |    |
|    |                                                                         |    |
|    |   +------------------+     +-------------------+    +---------------+   |    |
|    |   |    LLM (大脑)    |     |  规则/Context(眼睛)|    |  Tools (手脚) |   |    |
|    |   | 理解需求、推理方案|     | Prompt/CLAUDE.md  |    | 读取/修改/运行|   |    |
|    |   +--------+---------+     +---------+---------+    +-------+-------+   |    |
|    |            |                         |                      |           |    |
|    |            +-------------------------+----------------------+           |    |
|    |                                      |                                  |    |
|    |      ReAct 循环 (行动 -> 查看结果 -> 根据结果调整 -> 再次行动)          |    |
|    +-------------------------------------------------------------------------+    |
|                                                                                   |
|    数据支撑：Mock Data (演戏道具)           展示窗口：127.0.0.1 (本地试衣镜)       |
+-----------------------------------------------------------------------------------+
```

一句话记住 Agent 的工作原理：
> **Claude Code 是一个以 LLM 为大脑、以 Prompt 和 CLAUDE.md 为眼睛/耳朵（现场要求与长期规则）、以 Tools 为手脚、具有自主 ReAct 动态探索能力，并在 Workflow（业务阶段顺序与人在回路盖章卡口）中接受主管控制的 Agent。**

## 1. 开始前准备与教师演示观察

💡 **学员定心丸与试衣镜**：PowerShell 终端不是程序员写代码的地方，它只是你和 Claude 沟通的“高保真对讲机”。浏览器里的 `http://127.0.0.1:8888` 就是你的**“本地试衣镜”**！你不需要编写一行专业代码，所有的文件修改与后台启动都由 Claude 自动完成！

### 启动项目（只需简单两步）：
1. **首次使用**：若提示缺少 `node_modules`，请先在 PowerShell 中运行 `npm ci` 安装依赖。
2. 双击运行 **`start-project.bat`**，并在浏览器访问本地试衣镜：`http://127.0.0.1:8888`，启动 Claude Code。

在开始操作前，请先观看教师的微型演示，并思考以下 **5 个观察问题**：

1. Claude 什么时候只是在提出方案？
2. Claude 什么时候开始读取项目长期规则？
3. 哪些步骤必须等待主管人在回路盖章确认？
4. Claude 什么时候在跑 ReAct 自主循环？
5. 看到试衣镜效果后，主管是如何再次触发 Agent 调整的？

## 2. Task 1：LLM 理解你的业务需求 (15 分钟)

### 💡 知识卡：LLM (大脑)、Context (短期记忆)、角色区分与 Mock Data (演戏道具)
* **LLM（大语言模型）** 是 AI 的“大脑”。它负责理解你的业务语言并生成页面方案。**在这一步，我们不主动调用新的文件读取或修改 Tools，仅观察 LLM 的理解和方案生成能力。**
* 此时你的输入存放在 **Context（当前对话的短期记忆对讲机）** 中。
* ⚠️ **角色澄清**：你在下面输入的“主要使用者：采购主管”是**你要创建的系统的目标使用者**；**你自己才是控制 Claude Code 的最高主管！**
* 💡 **演戏道具说明**：第一版页面只使用 **Mock Data（模拟数据演戏道具）**，数据写在前端代码中，不接生产数据库。如果想要更多测试数据，直接告诉 Claude `请在表格中再加 3 条延期订单数据` 即可。

### 请准备好以下 5 项业务输入：
1. **系统名称**：（例如：供应商履约预警工作台）
2. **主要使用者**：（例如：采购主管）
3. **具体业务问题**：（例如：无法实时发现交货延期的供应商）
4. **首页最重要信息**：（例如：延期率 Top5 供应商与即将超期的采购单）
5. **进入首页第一个操作**：（例如：筛选延期订单并点击“发送催单提醒”）

### 复制并发送给 Claude Code：

```text
我要创建一个【系统名称】。

主要使用者是【角色】。

他们现在的问题是【具体业务问题】。

首页最重要的是看到【信息、异常、任务或结果】。

使用者进入首页后首先要执行【操作】。

第一版只使用模拟数据（Mock Data），不接真实接口。

请先不要读取项目文件，也不要修改任何代码。
请用你自己的话复述我对需求的理解，并提出第一版页面的初步模块规划方案。
```

### 🚩 本步检查 (Checklist)
- [ ] Claude Code 用自己的话复述了你的业务需求。
- [ ] Claude 提出了页面模块规划，但**没有读取项目，也没有修改任何代码**。

### 🧠 本步记忆复述
* **问**：Claude 刚才生成方案时，修改你电脑上的项目了吗？
* **答**：没有。此时只有 **LLM 大脑** 在推理和生成文本方案。

## 3. Task 2：Tools 让 Claude 戴上眼睛看项目 (10 分钟)

### 💡 知识卡：Prompt (现场要求)、CLAUDE.md (长期规则) 与 Tools (手脚能力)
* **Prompt 是现场指令（听觉）**，告诉 AI 当前的具体任务；**`CLAUDE.md` 是长期项目规则（视觉/校规）**，规定了代码风格与结构规范。
* **Tools（工具机制）** 是 Agent 的“手和脚”。它既能帮你在后台翻看文件，也能帮你在终端敲键盘运行验证脚本。

> ⚠️ **跨课程概念厘清**：`CLAUDE.md`（本课）是给开发助手 Claude 准备的项目校规。到了第 7–8 课，当我们引入独立评审专家 Codex 时，我们还会给它准备专属的审查手册——`AGENTS.md`。

🔍 **查阅项目通用组件库**：你可以在项目根目录中查看权威文档 [docs/COMPONENT_CATALOG.md](./COMPONENT_CATALOG.md)，了解项目内置可直接复用的通用组件。

### 复制并发送给 Claude Code（只读指令）：

```text
现在，请戴上眼睛，使用 Tools 读取项目中的真实文件：
- CLAUDE.md
- DESIGN.md
- docs/COMPONENT_CATALOG.md
- src/router/index.ts
- src/components/layout/AppSidebar.vue

请根据读取到的项目规则与组件库，向我说明：
1. 本项目已有的设计规范与可复用组件
2. 准备修改或新增的文件列表
3. 针对第一版页面的结构修订建议
4. 本次明确不做的内容

请注意：只读取文件并输出方案，在我明确确认前不要修改任何文件。
```

### 🚩 本步检查 (Checklist)
- [ ] Claude 输出了它通过 Tools 读取到的真实项目规则与可复用组件。
- [ ] 页面规划比 Task 1 更加具体且符合项目规范。

## 4. Task 3：Workflow 顺序、人在回路与自动化裁判 (15 分钟)

### 💡 知识卡：Agent 自主性、人在回路 (Human-in-the-Loop) 与自动化裁判脚本
* **Agent（自主执行）** 拥有极强的**动态自主性**。面对目标时，它能自己拆解步骤、调用 Tools、通过 ReAct 自自我纠错，而不是死板按脚本执行的自动化程序。
* **Workflow 顺序与人在回路 (Human-in-the-Loop)** 规定了从“需求 -> 方案 -> 执行 -> 验证”的业务推进顺序。在进入代码修改前，Agent **必须暂停，等待主管人在回路盖章授权**。
* **自动化裁判脚本**：`verify-student-project.ps1` 是训练营预置的**“自动化裁判脚本”**，而不是 Claude 临时写的。每次修改完代码，Claude 都会调用这个裁判来自我检查有没有把项目改崩溃。

### 步骤 1：行使主管裁决权（发送裁决指令）
```text
针对你的方案，我的修改意见如下：
1. 保留【核心 KPI 卡片】和【明细数据表格】。
2. 删除【复杂图表】，第一版暂不需要。
3. 把表格里的跟进操作按钮命名为【发送催单提醒】。

请复述你理解的修改范围，并列出准备新增或修改的页面、路由与侧边栏文件。
在我明确回复“同意方案，请开始修改代码”前，不要修改任何文件。
```

### 步骤 2：人在回路盖章授权
当 Claude 复述范围并确认后，发送：
```text
同意方案，请开始修改代码。
```

### 观察 Agent 连续执行：
观察 Claude 终端输出：
1. 创建新页面文件 (`.vue`)；
2. 修改路由配置 (`src/router/index.ts`)；
3. 新增侧边栏入口 (`src/components/layout/AppSidebar.vue`)；
4. 运行 `verify-student-project.ps1` 自动化裁判校验。

修改完成后，打开本地试衣镜 `http://127.0.0.1:8888` 查看你的新系统！

### 🚩 本步检查 (Checklist)
- [ ] 左侧菜单栏出现了你的系统名称，点击能打开新页面。
- [ ] Claude 连续完成了文件创建、路由修改与自动化裁判校验。

## 5. Task 4：Agent 真正的 ReAct 循环与人在回路反馈 (10 分钟)

### 💡 知识卡：ReAct 循环（行动 - 观察 - 调整 - 再次行动）
```text
+-------------------------------------------------------------------------+
|                        外层：人在回路 (Human Feedback)                   |
|   主管在试衣镜预览 -> 发现业务标签不精准 -> 输入微调指令 (再次触发 Agent)  |
+------------------------------------+------------------------------------+
                                     | 触发
                                     v
+-------------------------------------------------------------------------+
|                    内层：Agent ReAct 自主循环                           |
|                                                                         |
|   1. 行动 (Act): 修改 .vue 代码                                         |
|   2. 观察 (Observe): 查看脚本验证结果或终端反馈                        |
|   3. 调整 (Reason): 思考修补方案或逻辑微调                               |
|   4. 再次行动 (Act): 重新修正代码，直到测试通过                          |
+-------------------------------------------------------------------------+
```

* **ReAct 通用循环**：**行动 (Act) -> 查看工具返回或验证结果 (Observe) -> 根据结果调整 (Reason) -> 再次行动 (Act)**。不管是验证成功、脚本报错还是浏览器渲染调整，只要是根据观察结果继续推进，都是 ReAct 循环。
* **外层人在回路反馈**：你在本地试衣镜观察效果，下达指令，**再次触发 Agent 运行其内层 ReAct 循环**。

### 完成至少 1 次高质量微调闭环：
1. 切回本地试衣镜观察页面，找到一个真实的业务改善点（如：按钮文案、状态标签或识别度）。
2. 发送微调指令：
   ```text
   请把表格里的【状态】标签修改为【严重超时】和【正常履约】。
   请使用项目现有的警示语义和 DESIGN.md 中已有的状态色，提高识别度，不新增颜色体系。
   ```
3. **观察 ReAct 与反馈**：Claude 复述范围 -> 主管确认 -> Claude 运行 ReAct 循环（改代码并自动跑校验） -> 试衣镜显示新效果。

### 🚩 本步检查 (Checklist)
- [ ] 观察到了 Agent 的 ReAct 循环过程。
- [ ] 完成了至少 1 次人在回路的试衣镜观察与微调闭环。

## 9. 常见问题与安全救援
