# 第一课学员指南：AI Agent 基础概念与首个页面制作

欢迎开始第一课！在这节课中，你不仅会做出一个真正可以在浏览器中交互的企业系统页面，还将亲身体验并理解 AI Agent 是如何工作的。

---

## 0. 这节课解决什么问题

### 核心问题
> **Claude 为什么不只是聊天，还可以帮助你真正完成一个业务页面？**

下课时，你不仅拥有属于自己的系统雏形，还能清晰说明 **LLM、Tools、Agent、ReAct、Workflow**，以及 **Prompt/CLAUDE.md (眼睛/校规)、Context (短期记忆)、Mock Data (演戏道具)、127.0.0.1 (本地试衣镜) 和 Human-in-the-Loop (人在回路盖章)** 是如何协同工作的。

```text
+-----------------------------------------------------------------------------------+
|                                 Workflow 框架                                     |
|  (需求 -> 方案 -> 人在回路[主管盖章] -> Agent执行 -> 验证 -> 试衣镜预览 -> 微调)   |
|                                                                                   |
|    +-------------------------------------------------------------------------+    |
|    |                            Claude Code Agent                            |    |
|    |                                                                         |    |
|    |   +------------------+     +-------------------+    +---------------+   |    |
|    |   |    LLM (大脑)    |     |  规则/Context(眼睛)|    |  Tools (手脚) |   |    |
|    |   | 理解需求、推理方案|     | Prompt/CLAUDE.md  |    | 读取/修改/运行|   |    |
|    |   +--------+---------+     +---------+---------+    +-------+-------+   |    |
|    |            |                         |                      |           |    |
|    |            +-------------------------+----------------------+           |    |
|    |                                      |                                  |    |
|    |                   ReAct 循环 (行动 -> 观察 -> 调整)                     |    |
|    +-------------------------------------------------------------------------+    |
|                                                                                   |
|    数据支撑：Mock Data (演戏道具)           展示窗口：127.0.0.1 (本地试衣镜)       |
+-----------------------------------------------------------------------------------+
```

一句话记住 Agent 的工作原理：
> **Claude Code 是一个以 LLM 为大脑、以 Prompt 和 CLAUDE.md 为眼睛/耳朵、以 Tools 为手脚、具有自主 ReAct 动态探索能力，并在 Workflow（业务阶段顺序与人在回路盖章卡口）中接受主管控制的 Agent。**

## 1. 开始前准备与教师演示观察

💡 **学员定心丸与试衣镜**：PowerShell 终端不是程序员写代码的地方，它只是你和 Claude 沟通的“高保真对讲机”。浏览器里的 `http://127.0.0.1:8888` 就是你的**“本地试衣镜”**！你不需要编写一行专业代码，所有的文件修改与后台启动都由 Claude 自动完成！

### 启动项目（只需简单两步）：
1. 在解压后的项目根目录打开 Windows PowerShell，或者在文件资源管理器中直接**双击 `start-project.bat`**。
2. 打开浏览器访问本地试衣镜：`http://127.0.0.1:8888`，并启动 Claude Code 准备输入指令。

在开始操作前，请先观看教师的微型演示，并思考以下 **5 个观察问题**：

1. Claude 什么时候只是在提出方案？
2. Claude 什么时候开始戴上眼睛读取项目规则？
3. 哪些步骤必须等待主管人在回路盖章确认？
4. Claude 什么时候开始连续执行多个动作？
5. 看到试衣镜效果后，Claude 是如何再次调整的？

## 2. Task 1：LLM 理解你的业务需求 (15 分钟)

### 💡 知识卡：LLM (大脑)、Context (记忆) 与 Mock Data (演戏道具)
* **LLM（大语言模型）** 是 AI 的“大脑”。它负责理解你的业务语言并生成页面方案，但在这个阶段，它**还没有读取或修改你电脑上的项目文件**。
* 此时你的输入正存放在 **Context（短期记忆对讲机）** 中。如果对话太长，前面记忆会被挤掉，所以重要规矩需要写进文件里保存。
* 💡 **演戏道具说明**：第一版页面只使用 **Mock Data（模拟数据演戏道具）**，目的是零风险快速验证页面布局与业务跟进流程，不接生产数据库。

### 请准备好以下 5 项业务输入：
1. **系统名称**：（例如：供应商履约预警工作台）
2. **主要使用者**：（例如：采购主管）
3. **具体业务问题**：（例如：无法实时发现交货延期的供应商）
4. **首页最重要信息**：（例如：延期率 Top5 供应商与即将超期的采购单）
5. **进入首页第一个操作**：（例如：筛选延期订单并点击“发送催单提醒”）

### 复制并发送给 Claude Code：

```text
我要创建一个【系统名称】。

主要使用者是【角色】。

他们现在的问题是【具体业务问题】。

首页最重要的是看到【信息、异常、任务或结果】。

使用者进入首页后首先要执行【操作】。

第一版只使用模拟数据（Mock Data），不接真实接口。

请先不要读取项目文件，也不要修改任何代码。
请用你自己的话复述我对需求的理解，并提出第一版页面的初步模块规划方案。
```

### 🚩 本步检查 (Checklist)
- [ ] Claude Code 用自己的话复述了你的业务需求。
- [ ] Claude 提出了页面模块规划，但**没有读取项目，也没有修改任何代码**。

### 🧠 本步记忆复述
* **问**：Claude 刚才生成方案时，修改你电脑上的项目了吗？
* **答**：没有。此时只有 **LLM 大脑** 在推理和生成文本方案。

## 3. Task 2：Tools 让 Claude 戴上眼睛看项目 (10 分钟)

### 💡 知识卡：眼睛 (CLAUDE.md 校规) 与 Tools (手脚)
* **Prompt (你的指令) 与 `CLAUDE.md` (项目校规) 是 AI 的“眼睛和耳朵”**。戴上眼睛看懂校规后，它才知道进门后不能用原生 CSS 乱写、必须遵循项目规范。
* **Tools（工具）** 是 Agent 的“手和脚”，让 LLM 能走出聊天框，去翻开真实文件、写入修改代码和运行命令。

> ⚠️ **跨课程概念厘清**：`CLAUDE.md`（本课）是给开发助手 Claude 准备的项目校规。到了第 7–8 课，当我们引入独立评审专家 Codex 时，我们还会给它准备专属的审查手册——`AGENTS.md`。

🔍 **操作前必看**：在给 Claude 发送指令前，请先用 30 秒点击查看图片 [component-map.png](./assets/lesson-01/component-map.png)，了解 `KpiCard`（指标卡）、`DataTable`（明细表）和 `FilterPanel`（筛选栏）的样式。

![通用组件用途速查](./assets/lesson-01/component-map.png)

### 复制并发送给 Claude Code（只读指令）：

```text
现在，请戴上眼睛，使用 Tools 读取项目中的真实文件：
- CLAUDE.md
- DESIGN.md
- docs/COMPONENT_CATALOG.md
- src/router/index.ts
- src/components/layout/AppSidebar.vue

请根据读取到的项目规则与组件库，向我说明：
1. 本项目已有的设计规范与可复用组件
2. 准备修改或新增的文件列表
3. 针对第一版页面的结构修订建议
4. 本次明确不做的内容

请注意：只读取文件并输出方案，在我明确确认前不要修改任何文件。
```

### 🚩 本步检查 (Checklist)
- [ ] Claude 输出了它通过 Tools 读取到的真实项目规则与可复用组件。
- [ ] 页面规划比 Task 1 更加具体且符合项目规范。

### 🧠 本步记忆复述
* **问**：为什么 Claude 读取 `CLAUDE.md` 后给出的方案比第一次更可靠？
* **答**：因为 **`CLAUDE.md` 像眼睛**，让它看见了项目校规与设计规范。

## 4. Task 3：Workflow 顺序与人在回路盖章授权 (25 分钟)

### 💡 知识卡：Agent 自主执行、Workflow 顺序与人在回路 (Human-in-the-Loop)
* **Agent（自主执行）** 拥有极强的**动态自主性**。面对目标时，它能自己拆解步骤、调用 Tools、通过 ReAct 自自我纠错，而不是死板按脚本执行的自动化程序。
* **Workflow（业务阶段顺序与人在回路盖章）** 规定了从“需求 -> 方案 -> 执行 -> 验证”的业务推进顺序。在进入代码修改前，Agent **必须暂停，等待主管人在回路（Human-in-the-Loop）的盖章授权**。

> ⚠️ **跨课程概念厘清（施工队 Agent vs 家政机器人 Agent）**：
> * **Claude Code（本课）**：是帮你**盖房屋的“施工队 Agent”**（Coding Agent）。
> * **第 9 课设计的 Agent**：是未来入住房屋、**帮你在系统中处理具体业务的“家政机器人 Agent”**（Business Agent，如智能催单助手）。

![标准企业页面骨架](./assets/lesson-01/page-layout.png)

> **文字说明**：标准企业页面通常由页面说明/筛选条件/主要操作、KPI 指标卡区、主要图表区和明细表格区组成。第一版最低标准：一个页面、一个核心业务信息区、一个可操作入口、Mock Data 模拟数据、可运行。

### 步骤 1：行使主管裁决权（发送裁决指令）
```text
针对你的方案，我的修改意见如下：
1. 保留【核心 KPI 卡片】和【明细数据表格】。
2. 删除【复杂图表】，第一版暂不需要。
3. 把表格里的跟进操作按钮命名为【发送催单提醒】。

请复述你理解的修改范围，并列出准备新增或修改的页面、路由与侧边栏文件。
在我明确回复“同意方案，请开始修改代码”前，不要修改任何文件。
```

### 步骤 2：人在回路盖章授权
当 Claude 复述范围并确认后，发送：
```text
同意方案，请开始修改代码。
```

### 观察 Agent 连续执行：
观察 Claude 终端输出：
1. 创建新页面文件 (`.vue`)；
2. 修改路由配置 (`src/router/index.ts`)；
3. 新增侧边栏入口 (`src/components/layout/AppSidebar.vue`)；
4. 运行 `verify-student-project.ps1` 校验。

修改完成后，打开本地试衣镜 `http://127.0.0.1:8888` 查看你的新系统！

### 🚩 本步检查 (Checklist)
- [ ] 左侧菜单栏出现了你的系统名称，点击能打开新页面。
- [ ] Claude 连续完成了文件创建、路由修改与验证。

## 5. Task 4：ReAct 检查和调整 (15 分钟)

### 💡 知识卡：你现在看到的是试衣镜与 ReAct
* **ReAct（行动-观察-调整）** 是 Agent 的动态工作循环：**行动 -> 试衣镜观察结果 -> 思考调整**。第一次生成不完美非常正常，通过 ReAct 就能不断逼近满意效果。
* 💡 **ReAct 微调心法**：AI 修改代码是基于概率推理，而不是像画图软件那样按像素编辑。如果第一轮修改把间距变大了，不要慌，在第二轮明确告诉它 `请恢复组件间距，仅修改按钮颜色` 即可。ReAct 的本质就是通过 1-2 轮反馈消除偏差。

### 完成一次高质量 ReAct 微调闭环：
1. 切回本地试衣镜观察页面，找到一个真实的业务改善点（如：按钮文案、状态标签或识别度）。
2. 发送微调指令：
   ```text
   请把表格里的【状态】标签修改为【严重超时】和【正常履约】。
   请使用项目现有的警示语义和 DESIGN.md 中已有的状态色，提高识别度，不新增颜色体系。
   ```
3. **观察 ReAct 循环**：Claude 复述本轮范围 -> 主管确认 -> Claude 修改代码 -> 试衣镜显示新效果。

### 🚩 本步检查 (Checklist)
- [ ] 完成了至少 1 次由你自己发起的 ReAct 观察与微调闭环。
- [ ] 页面效果越来越贴近你真实的业务管理习惯。

## 9. 常见问题与安全救援

* **Claude 未经确认直接改了代码**：立即发送救援指令：
  ```text
  请立即停止继续修改。
  先列出刚才修改的文件和具体内容，不要再改动。
  等待我确认是否仅撤销本轮未经授权的修改。
  然后按照 Task 1 要求先输出需求理解和页面区块规划。
  ```
* **Claude 在 LLM 阶段就读取了文件**：提醒它 `请先暂停读取文件，先根据我口述的需求输出初步概念规划`。
* **验证脚本报错**：复制报错文字发送给 Claude：`验证脚本报错了，请帮我定位并修复该问题`。
