# 第一课学员操作指南 — 从业务问题创建第一个系统页面：LLM、Tools、Agent 与三类业务原型

> 💡 **本课的核心思想只有一句话：**  
> **理解 LLM 大脑、Tools 手脚与 Agent 执行者的关系，建立第一个受控原型。**

---

## 一、 本课背景、底层原理与学习目标

### 1.1 业务背景与真实痛点
非技术主管在尝试使用 AI 进行业务原型开发时，最常踩的坑就是在网页聊天框中盲目复制无用代码，或者因为不清楚 AI 的能力边界，把“大模型模型本身”与“具备读写能力的 Agent”混为一谈。缺乏规范约束时，生成的代码既无法在本地运行，也无法精准匹配自身部门的实际业务场景。

### 1.2 宏观受控闭环
本课的核心工程机制，是将业务原型的创建纳入一条**“需求解构 ➔ 方案推演 ➔ 人在回路授权 ➔ Agent 代码生成 ➔ 验证自测 ➔ 试衣镜预览 ➔ 微调闭环”**的受控流水线中：
1. **五位一体物理分工**：明确大模型 (LLM) 作为大脑负责推理，Tools 作为手脚负责读写磁盘，Agent 作为执行者在 ReAct 循环中自动修正，Workflow 门禁负责权限拦截。
2. **三类业务原型定位**：根据部门需求精准归类为“监控决策型”、“任务流程型”或“操作工具型”原型。
3. **试衣镜与磁盘状态盘点**：通过 127.0.0.1 本地试衣镜进行可视化预览，并将每一次增量成果物理记录在根目录 [`docs/PROJECT_STATE.md`](file:///d:/AILearning/docs/PROJECT_STATE.md) 文件中。

### 1.3 核心学习目标
完成本课实操后，你将能够：
1. **识别与阐述** LLM（大脑）、Tools（手脚）、Agent（执行者）、ReAct（反馈循环）与 Workflow（流程门禁）5 大核心概念及其物理区别。
2. **区分与选择** 适合自身部门的三类业务原型（A. 监控决策型 / B. 任务流程型 / C. 操作工具型）。
3. **行使人在回路 (HITL) 授权**，利用 Workflow 确认门禁精准管控 Agent 修改代码的权限。
4. **验证与交付** 包含虚构模拟数据（Mock Data）的首个可运行页面，并获得验证脚本的 `[PASS]` 结论。

## 二、 💡 本课核心工程概念卡 (Core Concepts)

### 核心概念 1：LLM、Tools、Agent、ReAct 与 Workflow 五位一体架构
- **硬核工程定义**：现代 AI 软件工程中，由大语言模型推理引擎 (LLM)、工具调用接口 (Tools)、自主循环体 (Agent)、推理-行动闭环 (ReAct) 与规则防火墙 (Workflow) 构成的五层系统架构。
- **底层运作机制**：LLM 接收 Prompt 进行方案推演；Tools 权限沙箱执行具体文件读写与终端命令；Agent 在 ReAct (Thought -> Action -> Observation) 循环中自动自修；Workflow 门禁在关键节点拦截越界操作。
- **具象业务比喻**：**建筑工程指挥部** 🏗️。LLM 是总工程师（只出图纸），Tools 是施工机械（挖土机/起重机），Agent 是现场施工队长（盯盘自修），Workflow 是安全监理（检查施工资质）。
- **IT 沟通场景**：“我们基于 LLM + Tools 架构搭建了 Agent 原型系统，通过 Workflow 门禁拦截越界修改。”

### 核心概念 2：三类业务原型分类 (Three Business Prototype Classes)
- **硬核工程定义**：根据业务交互形态与数据流转特征，将企业级原型划分的三种标准范式：监控决策型、任务流程型、操作工具型。
- **底层运作机制**：
  - **A. 监控决策型**：以仪表盘、看板、指标卡为主，强调全局数据呈现。
  - **B. 任务流程型**：以工单流转、审批节点、状态机为主，强调多步骤动作。
  - **C. 操作工具型**：以表单录入、批量处理、单页计算为主，强调高效输入。
- **具象业务比喻**：**医院的三个核心科室** 🏥。监控决策型是 ICUs 监视大屏，任务流程型是转诊分诊流水线，操作工具型是化验单打印机。
- **IT 沟通场景**：“本期原型确定为 B 类‘任务流程型’工单看板，优先验证流程状态机的完整性。”

### 核心概念 3：人在回路 (HITL) 授权与 Tools 权限沙箱门禁
- **硬核工程定义**：在 Agent 自动化循环中强制植入人工审查盖章节点（Human-in-the-Loop），配合系统级工具沙箱进行最小权限控制的设计。
- **底层运作机制**：Agent 修改代码或调用系统终端前，物理被 Tools 防火墙拦截；必须等待主管在终端输入确认口令（如 `npm run dev` 或自然盖章指令）后方可解锁写权限。
- **具象业务比喻**：**财务付款的双签审批** ✍️。无论财务软件多自动化，付款出纳前必须由部门主管在 U 盾上按确定键。
- **IT 沟通场景**：“项目严格执行人在回路 (HITL) 授权，Agent 无法在未经许可的情况下静默修改核心配置文件。”

## 四、 🛠️ 课堂实操与自学导引任务清单

### Task 0: 启动 127.0.0.1 本地试衣镜与环境检查

#### ⚡ 极速操作步骤
1. 打开 VS Code 终端，运行本地开发服务命令：
   ```powershell
   npm run dev
   ```
2. 打开浏览器访问 `http://localhost:5173/`，确认看见训练营初始原型试衣镜大盘。

#### 💡 独立自学原理解析
> **为什么 127.0.0.1 本地试衣镜是必不可少的？**  
> 代码文本本身不是最终产品，主管眼睛看到并能用鼠标点击的才是真实原型。启动本地 Vite 服务后，代码的每一次修改都会通过 HMR 热重载瞬间反映在浏览器中。

---

### Task 1: 唤醒 Agent 助手创建首个业务原型页面

#### ⚡ 极速操作步骤
1. 在 Claude Code CLI 窗口中下发页面创建指令：
   ```text
   请在 src/views/ 目录下创建一个新的工单看板页面 WorkOrderBoard.vue，包含列表与简单筛选。
   ```
2. 观察终端输出，AI 通过 `Tools 权限沙箱` 自动创建并修改受控文件，并在 ReAct 循环中自动纠错。

#### 🔍 代码 Before vs After 视觉对比
```diff
+ <!-- src/views/WorkOrderBoard.vue -->
+ <template>
+   <div class="work-order-board">
+     <h2>工单处理看板</h2>
+     <!-- 静态 Mock 数据列表渲染 -->
+   </div>
+ </template>
```

---

### Task 2: 绑定静态 Mock 数据源与选择原型分类

#### ⚡ 极速操作步骤
1. 确认工单看板使用静态 Mock 数据源（演戏道具），严禁在原型阶段连接真实后端数据库。
2. 明确当堂交付的原型属于 **B 类（任务流程型）**，在页面顶部添加“待处理 / 处理中 / 已关单”状态筛选栏。

#### 💡 独立自学原理解析
> **为什么原型阶段严格执行 Mock Data 防错红线？**  
> 连接生产数据库会导致开发速度下降 90%，且存在物理破坏线上数据的巨大风险。使用 Mock 数据可以极速验证业务流程与界面体验。

## 五、 💡 常见概念误区与正确理解 (Mindset Transformation)

| 常见误区 (Misconception) | 正确硬核理解 (Correct Engineering Reality) | 如何纠偏与护栏防护 (Remedy & Guardrails) |
| :--- | :--- | :--- |
| **误区 1：“用 AI 编程就是在大模型网页聊天框里聊天”** | 网页聊天框只有 LLM 大脑，缺乏 Tools 手脚与 ReAct 循环，无法直接读写本地文件与触发试衣镜更新。 | 使用 VS Code 终端与 Claude Code CLI，配合 127.0.0.1 本地试衣镜实操。 |
| **误区 2：“原型开发第一步必须先设计后端数据库表”** | 原型阶段的核心是验证业务想法与界面交互，直接连数据库会陷入复杂的配置泥潭。 | 严格执行静态 Mock 数据防错红线，物理解耦前端界面与后端接口。 |
| **误区 3：“让 AI 随意在磁盘任意位置新建或删除文件”** | 缺乏权限隔离的 AI 命令可能误删电脑上的重要文件或修改系统环境。 | 部署 `Tools 权限沙箱`，物理限制 AI 仅能在受控工程目录下进行文件读写。 |
| **误区 4：“做完功能后不需要记录项目状态”** | 不记录状态会导致下一次唤醒 AI 时，AI 忘记上一次写了哪些页面。 | 强制更新 [`docs/PROJECT_STATE.md`](file:///d:/AILearning/docs/PROJECT_STATE.md)，作为磁盘物理状态记录。 |

## 六、 ❓ 常见操作报错与 Troubleshooting 指南

| 报错/异常现象 | 物理原因 | 解决与纠偏方案 |
| :--- | :--- | :--- |
| 浏览器打开 `localhost:5173` 提示连接拒绝 | Vite 开发服务器未在终端中启动 | 在终端重新运行 `npm run dev` 并保持窗口运行。 |
| AI 提示无法写入系统敏感目录 | 触发了 Tools 权限沙箱保护 | 确认要求 AI 修改的文件是否在工程根目录 `src/` 或 `docs/` 下。 |
