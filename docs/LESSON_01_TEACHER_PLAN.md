## 2. 本课定位

说明：
- **本课解决什么学习问题**：帮助业务主管破除对技术开发的恐惧，建立“用自然语言控盘 Agent 从零创造业务系统页面”的控制感。
- **为什么安排在当前阶段**：作为首门课程，重点是激发兴趣与确立业务主导权，而非教授编程语法或复杂工程结构。
- **与前一课和后一课的关系**：本课产出第一个可运行的系统页面；下一课（第 2 课）将引入参考图与设计规则（`frontend-design`）提升页面质感。

---

## 3. 核心目标

1. 能够用自然语言清晰描述一个真实具体的业务场景与核心痛点（明确系统名、角色、痛点、首要信息与首个动作）。
2. 掌握“需求表达 -> 方案裁决 -> 代码生成 -> 3 轮自然语言微调”的人机协作闭环。
3. 独立完成一次基础工程自测（`verify-student-project.ps1`），产生第一个可预览、可点击交互的模拟数据页面。

---

## 4. 可见成果

* 侧边栏新增一个专属业务菜单入口。
* 至少一个核心业务信息区（如 KPI 卡片、折线/柱状图表、任务列表、异常清单或数据表格的简单组合）。
* 经过至少 3 次学员主动微调修正的真实业务逻辑呈现。
* 一份完整记载业务思考与下一步规划的课后记录。

---

## 5. 本课明确不做

- 不讲解 Vue/React、TypeScript 代码语法。
- 不安装任何第三方框架或数据库。
- 不开发登录、权限、真实 API 接入。
- 不引入 MCP 或多 Agent 分工。

## 9. 业务场景

- **使用者**：客服主管
- **当前问题**：客服主管每天不知道哪些高价值订单即将超时，无法主动进行催发货与跟进。
- **工作场景**：每天早上打开系统，优先查看 2 小时内即将超时的订单列表，并一键触发催发货预警。
- **使用数据**：全量虚构的模拟订单数据。

---

## 10. 教师演示步骤 (5-8 分钟微型演示)

1. **输入示范 Prompt**：
   ```text
   我要创建一个【订单履约超时预警台】。主要使用者是【客服主管】。
   主要问题是【无法及时发现即将在 2 小时内超时的订单】。
   首页最重要的是看到【超时预警列表与告警订单数】。
   请先读取 CLAUDE.md 与 docs/COMPONENT_CATALOG.md，向我说明页面结构，先不要修改代码。
   ```
2. **展示方案裁决**：当 Claude 输出页面设计后，教师示范删除一个无关的“历史统计图”，保留“告警 KPI 卡 + 超时明细表”。输入：“请复述修改范围并列出准备修改的文件，在我确认前不要修改代码。”
3. **指令生成与预览**：教师明确回复“同意方案，请开始修改代码”。生成完成后刷新浏览器展示页面。
4. **演示微调闭环**：
   * 教师提出要求：“把按钮命名为【立即催发货】，并使用符合 DESIGN.md 的警示操作样式。”
   * Claude 先复述：“本轮仅修改明细表操作按钮的文案与警示操作样式，请确认。”
   * 教师明确回复同意后，Claude 实施修改。
   * 教师刷新浏览器展示结果。
5. **结束演示**：告知学员：“这就是自然语言人机协作的全过程，现在请大家用各自真实的业务问题开始操作。”

## 11. 学员实操任务

详细学员输入与操作指令，请参阅：
[LESSON_01_GUIDE.md](./LESSON_01_GUIDE.md)

教师控场重点与观察点：
* **Task 1**：防止学员输入空泛的“帮我做个智能平台”，强制要求填写 5 项具体业务要素。检查 Claude 是否复述了需求且**没有直接改文件**。
* **Task 2**：提醒学员第一版要克制，保留 1 个页面、1 个核心信息区、1 个操作入口即可。
* **Task 3**：生成代码后，确保学员在浏览器中看到真实侧边栏入口与页面。
* **Task 4**：督促学员完成 3 轮微调（如修改业务术语、调整排列顺序、遵从 DESIGN.md 样式），体验主动掌控感。

## 19. 常见问题 (Troubleshooting)

| 问题类型 | 现象 | 处理建议 / 救援提示词 |
| --- | --- | --- |
| **操作规范** | Claude 未经确认直接改了代码 | 立即发送救援指令：`请立即停止继续修改。先列出刚才修改的文件和具体内容，不要再改动。等待我确认是否仅撤销本轮未经授权的修改。然后按照 Task 1 要求先输出需求理解和页面区块规划。` |
| **范围控制** | 贪大求全，第一版生成失败或报错 | 输入：`请大幅简化方案。第一版只保留 1 个核心信息区、1 个主要明细表和 1 个模拟数据按钮。` |
| **设计规范** | 页面样式错乱或新增不一致颜色 | 输入：`请使用项目现有的警示语义和 DESIGN.md 中已有的状态色，重新调整样式，不新增颜色体系。` |
| **工程自测** | 验证脚本报错 | 检查路由与侧边栏，输入：`请运行 typecheck 检查类型错误，并根据当前项目结构确认 router/index.ts 和 AppSidebar.vue 的修改。` |
