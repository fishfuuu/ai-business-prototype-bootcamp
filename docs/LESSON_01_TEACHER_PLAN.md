## 2. 本课定位

说明：
- **本课解决什么学习问题**：帮助业务主管破除对 AI 开发的恐惧与迷信，既掌握“用自然语言控盘 Agent 从零创造业务页面”的控制感，又真正理解 **LLM、Tools、Agent、ReAct 和 Workflow** 5 个核心概念。
- **为什么安排在当前阶段**：作为首门课程，重点是激发兴趣、确立业务主导权并建立清晰的人机协作认知框架。
- **与前一课和后一课的关系**：本课建立概念认知与可运行页面；下一课（第 2 课）将引入参考图与设计规则（`frontend-design`）提升页面质感。第 9 课则深入业务 Agent 场景判断与产品设计。

---

## 3. 核心目标

1. 能够理解并用自己的话说明 **LLM、Tools、Agent、ReAct 和 Workflow** 5 个基础概念。
2. 能在 Claude Code 页面制作过程中准确识别这五个概念对应的具体实际动作。
3. 掌握“需求表达 -> 方案裁决 -> 代码生成 -> ReAct 微调”的人机协作闭环，能使用 Workflow 确认门禁有效控制 Agent。
4. 独立完成一次基础工程自测（`verify-student-project.ps1`），产生第一个可预览、可点击交互的模拟数据页面。
5. 能够结合自己创建的页面，向他人复述五个概念在系统制作中的作用。

---

## 4. 可见成果

* 一个包含 LLM、Tools、Agent、ReAct、Workflow 的清晰人机协作认知。
* 侧边栏新增一个专属业务菜单入口。
* 至少一个核心业务信息区（如 KPI 卡片、任务列表或数据表格组合）。
* 经过至少 1 次高质量 ReAct 微调修正的真实业务逻辑呈现。
* 一份填写完整的课后概念与业务复盘记录。

---

## 5. 本课明确不做

- 不讲解 Transformer、Token 计算、Vector/Embedding 或 Function Calling 协议。
- 不讲解 LangGraph、API Schema 或 Agent 框架源码。
- 不开发登录、权限、真实 API 接入。
- 不把 Agent 描述为完全自主、可脱离人工管理的系统。

## 9. 教师连续演示案与 5 次暂停点 (8-25 分钟)

教师统一使用 **“订单履约超时预警台”** 场景进行连续示范：

### 暂停点 1（8–11 分钟）：只生成方案
* **演示动作**：输入需求，要求 Claude 提出页面方案，但不读取项目、不改代码。
* **教师提问**：“大家看，Claude 现在真正修改我电脑上的项目了吗？”
* **揭示概念**：**LLM** —— 它只是大脑，在理解需求、推理方案，但手里没有工具。

### 暂停点 2（11–14 分钟）：读取项目文件
* **演示动作**：让 Claude 读取 `CLAUDE.md`、`DESIGN.md` 与组件目录。
* **教师提问**：“它为什么现在能知道咱们项目里有哪些现成组件和设计规范了？”
* **揭示概念**：**Tools** —— 这是 Agent 的眼睛和手，让它走出聊天框看见真实项目。

### 暂停点 3（14–19 分钟）：连续修改与创建
* **演示动作**：教师确认方案后下达授权，Claude 连续新建页面、配路由、加菜单。
* **教师提问**：“为什么我们没有逐条告诉它每一个技术步骤，它却能自己一步步完成？”
* **揭示概念**：**Agent** —— 配备了大脑、工具和目标后，能自动组织多步行动的执行者。

### 暂停点 4（19–22 分钟）：观察与二次微调
* **演示动作**：刷新浏览器，发现按钮样式需调整，输入微调指令后 Claude 修正并跑验证。
* **教师提问**：“为什么第一次生成不够完美没关系？我们在做一件什么事？”
* **揭示概念**：**ReAct** —— 行动、观察结果、思考调整，通过循环不断逼近满意效果。

### 暂停点 5（22–25 分钟）：回看确认门禁
* **演示动作**：展示从需求到生成的完整 Workflow，重点标注主管盖章确认卡口。
* **教师提问**：“为什么一开始不能让 Claude 随意修改，必须等我们说‘同意方案’？”
* **揭示概念**：**Workflow** —— 规定顺序与确认卡口，保证主管永远拥有最高控制权。

## 10. 学员实操与控场重点

详细学员指导请参阅：[LESSON_01_GUIDE.md](./LESSON_01_GUIDE.md)

控场教规：
1. **先观察行为，后揭示概念**：严禁前 20 分钟纯讲 PPT，概念必须在动作发生后立即出现。
2. **每次概念讲解不超过 3 分钟**：面向业务主管，语言必须生活化、通俗化。
3. **强化 Workflow 确认权**：Task 2 结尾督促学员检查 Claude 是否在等待授权，未授权绝不放行。
4. **ReAct 质量高于数量**：第一课强制完成 1 次高质量 ReAct 闭环即可，不强制 15 分钟内做满 3 轮。

## 13. 常见问题 (Troubleshooting)

| 问题类型 | 现象 | 救援提示词 / 处理建议 |
| --- | --- | --- |
| **操作规范** | Claude 未经确认直接改了代码 | 救援指令：`请立即停止继续修改。先列出刚才修改的文件和具体内容，不要再改动。等待我确认是否仅撤销本轮未经授权的修改。然后按照 Task 1 要求先输出需求理解和页面区块规划。` |
| **概念混淆** | 学员分不清 Agent 和 LLM | 教师回应：“LLM 是军师（出谋划策），Agent 是项目经理（带着工具亲自把项目做出来）。” |
| **概念混淆** | 学员误以为 Agent 可以完全自主 | 教师回应：“Agent 必须在 Workflow 中工作，必须经过主管盖章确认才能动代码。” |
| **演示故障** | 教师现场演示卡顿或网络报错 | 备用预案：使用备用预录视频或预置分支截图，继续进行暂停点提问。 |
