## 一、 课程元数据与定位

### 1.1 课程元数据
- **课程名称**：AI 业务原型开发训练营·第一课
- **主讲主题**：从业务问题创建第一个系统页面：LLM、Tools、Agent 与三类业务原型
- **授课对象**：非技术背景业务主管 / 产品经理 / 业务专家 (10–30人)
- **课时时长**：90 分钟 (极客控场 + 5 个固定 Pause Points)
- **授课模式**：18 分钟极客示范 ➔ 10 分钟概念核对 ➔ 45 分钟学员分步实操 ➔ 10 分钟验证归档
- 本课学员 Skill 名称 | 无
- **前置依赖**：无前置依赖，具备基础电脑操作能力即可。
- **教学验证状态**：PILOT_PASSED
- **课程负责人**：官方教研组

### 1.2 本课定位与背景痛点
- **在全套课程中的位置**：训练营破冰第一课，建立五位一体架构认知、人在回路授权与 127.0.0.1 本地试衣镜调试习惯。
- **解决的核心痛点**：主管在大模型网页框中盲目复制无用代码、混淆 LLM 与 Agent 能力、缺乏 Tools 权限沙箱隔离。
- **核心突破口**：解构 LLM(大脑) + Tools(手脚) + Agent(执行者) + ReAct(循环) + Workflow(门禁) 物理架构，明确三类业务原型分类，通过 ReAct 单步自修模式在 15 分钟内运行首个原型系统。

## 二、 逆向目标与四步概念卡

### 2.1 Bloom ABCD 学习目标 (100% 原始权威对齐)
完成本课后，学员将能够：
1. **[Objective 1 - Apply (3)]**：**识别与阐述** LLM（大脑）、Tools（手脚）、Agent（执行者）、ReAct（反馈循环）与 Workflow（流程门禁）5 大核心概念及其物理区别。
2. **[Objective 2 - Analyze (4)]**：**区分与选择** 适合自身部门的三类业务原型（A. 监控决策型 / B. 任务流程型 / C. 操作工具型）。
3. **[Objective 3 - Evaluate (5)]**：**行使人在回路 (HITL) 授权**，利用 Workflow 确认门禁精准管控 Agent 修改代码的权限。
4. **[Objective 4 - Create (6)]**：**验证与交付** 包含虚构模拟数据（Mock Data）的首个可运行页面，并获得验证脚本的 `[PASS]` 结论。

### 2.2 核心概念四步解析卡集 (7 大独立四步解析卡)

#### 💡 概念卡 1：LLM (大语言模型 / 大脑)
1. **硬核工程定义**：海量参数概率预测与自然语言推理引擎。
2. **底层运作机制**：推演方案与代码文本，物理上无法直接写磁盘。
3. **具象业务比喻**：**建筑工程总工程师** 👨‍🔬。
4. **IT 沟通场景**：“LLM 负责需求理解与方案推演，实际文件读写由 Tools 接口执行。”

#### 💡 概念卡 2：Tools (工具调用 / 手脚)
1. **硬核工程定义**：与宿主操作系统交互的 API 函数接口与命令行工具集。
2. **底层运作机制**：提供 `readFile`、`writeFile` 等原子化写盘与运行能力。
3. **具象业务比喻**：**施工现场的重型机械与工具箱** 🚜。
4. **IT 沟通场景**：“Agent 必须通过受控的 Tools 工具箱读写磁盘。”

#### 💡 概念卡 3：Agent (自主循环体 / 执行者)
1. **硬核工程定义**：以 LLM 为决策大脑，具备目标拆解与自我修复能力的自主实体。
2. **底层运作机制**：目标拆解为 Task，评估 Tools 结果直至达成目标。
3. **具象业务比喻**：**现场施工队长** 👷‍♂️。
4. **IT 沟通场景**：“我们使用的是 Agent 架构，它能自主感知终端报错并尝试自修。”

#### 💡 概念卡 4：ReAct (推理-行动闭环 / 反馈循环)
1. **硬核工程定义**：Reasoning and Acting 联合范式 (Thought ➔ Action ➔ Observation)。
2. **底层运作机制**：思考 ➔ 调用 Tools ➔ 观察日志 ➔ 若报错则调整再试。
3. **具象业务比喻**：**师傅修水管的看试过程** 🔧。
4. **IT 沟通场景**：“Agent 在 ReAct 闭环中完成了代码的静态检查与自修。”

#### 💡 概念卡 5：Workflow (流程门禁 / 安全防护)
1. **硬核工程定义**：防止 Agent 行为跑偏的前置约束与硬性规则防火墙。
2. **底层运作机制**：物理拦截违规写操作。
3. **具象业务比喻**：**工地安全监理** 👮。
4. **IT 沟通场景**：“Workflow 流程门禁锁定了 Agent 的权限边界。”

#### 💡 概念卡 6：人在回路 (HITL / 授权盖章)
1. **硬核工程定义**：在 Agent 自动化循环中强制植入人工审查盖章节点的设计。
2. **底层运作机制**：保存计划或写代码时挂起，等待主管输入口令解锁。
3. **具象业务比喻**：**财务付款的双签审批与出纳 U 盾** ✍️。
4. **IT 沟通场景**：“项目严格执行人在回路 (HITL) 授权，Agent 无法静默修改代码。”

#### 💡 概念卡 7：三类业务原型分类 (Three Business Prototype Classes)
1. **硬核工程定义**：监控决策型、任务流程型、操作工具型三种原型范式。
2. **底层运作机制**：A 类图表、B 类状态机工单、C 类高效表单。
3. **具象业务比喻**：**医院的三个核心科室** 🏥。
4. **IT 沟通场景**：“本期原型确定为 B 类‘任务流程型’工单看板。”
