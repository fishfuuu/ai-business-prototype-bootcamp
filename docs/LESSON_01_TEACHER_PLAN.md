## 2. 本课定位

说明：
- **解决什么学习问题**：破除对 AI 开发的玄学误区，理解 **LLM、Tools、Agent、ReAct 和 Workflow** 5 个底层硬核概念，建立三类业务原型（监控决策型、任务流程型、操作工具型）分类认知，掌握人在回路 (HITL) 授权门禁机制。
- **为什么安排在当前阶段**：作为开篇，立规矩、给信心，建立强有力的安全防护体系与人机主从秩序。
- **与前后课的关系**：衔接全过程；为第 2 课（`DESIGN.md` 视觉重构）提供可渲染的原型基底。

---

## 3. 核心目标

基于布鲁姆分类法（Bloom's Taxonomy），本课目标如下：

1. **识别与阐述** LLM（大脑）、Tools（手脚）、Agent（执行者）、ReAct（循环）与 Workflow（门禁）的底层硬核物理机制。
2. **分类与规划** 适合自身部门的业务原型类型（监控/流程/工具型）。
3. **行使与裁决** 人在回路授权（HITL），通过“同意方案，请开始修改代码”口令精准控制 Agent 修改范围。
4. **验证与交付** 首个带侧栏菜单、Mock 数据与试衣镜预览的原型，并获得 `verify-student-project.ps1` 校验 `[PASS]`。

---

## 4. 可见成果

学员独立产出：
1. 一个符合所选类型的业务原型页面（可点击、带侧栏导航、Mock 数据渲染）；
2. 包含系统名称、目标使用者、原型类型、核心业务问题及安全自查的 `docs/PROJECT_STATE.md`；
3. 一份通过 `powershell -ExecutionPolicy Bypass -File .\scripts\verify-student-project.ps1` 校验的 `[PASS]` 证据；
4. 完成至少 1 次人在回路的 ReAct 自测微调闭环。

---

## 5. 本课明确不做

- 不讲解 Transformer 数学推导、Embedding 向量或与业务无关的 API 细节。
- 不引入跨部门真实数据库、生产环境鉴权或后端真实服务。
- 不允许 Agent 在未经主管下达“同意方案，请开始修改代码”之前擅自改动代码。

## 9. 业务场景

* **演示案例**：订单履约超时预警台（属于“监控与决策型”示例）
* **核心业务痛点**：采购主管无法实时跟进延期供应商，缺乏统一的催单动作入口。
* **演戏道具**：前端硬编码的 Mock 数据。

---

## 10. 教师演示步骤 (5 个固定暂停点)

### 暂停点 1：LLM 推演方案 (Task 1 阶段)
* **教师动作**：发送 Task 1 需求文本，展示 Claude 在终端输出规划，但完全没有触发文件修改。
* **教师提问**：“大家看终端，Claude 现在写代码了吗？LLM 的物理本质是什么？”
* **硬核解析**：LLM 是基于 Token 推演的大脑，在内存里做概率推演。此时它没有任何系统写权限。

### 暂停点 2：Tools 调用观察 (Task 2 阶段)
* **教师动作**：发送 Task 2 指令，指向终端日志中的 `Read file CLAUDE.md`。
* **教师提问**：“Claude 是怎么知道我们项目的规范和组件库的？它用了什么物理能力？”
* **硬核解析**：它调用了 **Tools（手脚工具）**。Tools 是宿主程序暴露给模型调用的系统函数 API。

### 暂停点 3：Workflow 确认门禁 (Task 3 阶段)
* **教师动作**：展示 Claude 输出了修改计划，停在等待界面。讲师双手离开键盘。
* **教师提问**：“方案已经很完美了，为什么 Claude 不敢直接去改文件？”
* **硬核解析**：受到 **Workflow 人在回路 (HITL) 门禁** 约束。主管是 CEO，没有人类在 CLI 输入许可口令，Agent 被物理阻断。

### 暂停点 4：Agent 连续执行 (Task 3 执行阶段)
* **教师动作**：输入口令“同意方案，请开始修改代码”，展示 Agent 自动创建 Vue 文件、注册路由并运行 `verify-student-project.ps1`。
* **教师提问**：“Agent 与单次 Prompt 盲猜的最大区别是什么？”
* **硬核解析**：Agent 是目标驱动的执行系统，能够在授权范围内连续组织多步行动并自动调用 Tools 完成目标。

### 暂停点 5：ReAct 观察与微调 (Task 4 阶段)
* **教师动作**：打开试衣镜发现一个按钮不够醒目，发送微调指令，展示 Agent 自动修正并自测通过。
* **教师提问**：“Agent 是如何根据试衣镜与报错进行自我纠偏的？”
* **硬核解析**：这就是 **ReAct 范式 (Thought -> Action -> Observation -> Thought)**。它看着物理观察结果进行自我调整。
