## 一、 课程元数据与定位

### 1.1 课程元数据
- **课程名称**：AI 业务原型开发训练营·第一课
- **主讲主题**：从业务问题创建第一个系统页面：LLM、Tools、Agent 与三类业务原型
- **授课对象**：非技术背景业务主管 / 产品经理 / 业务专家 (10–30人)
- **课时时长**：90 分钟 (极客控场 + 5 个固定 Pause Points)
- **授课模式**：18 分钟极客示范 ➔ 10 分钟概念核对 ➔ 45 分钟学员分步实操 ➔ 10 分钟验证归档

- **教学验证状态**：PILOT_PASSED
- **课程负责人**：官方教研组

### 1.2 本课定位与背景痛点
- **在全套课程中的位置**：训练营破冰第一课，建立五位一体架构认知与 127.0.0.1 本地试衣镜调试习惯。
- **解决的核心痛点**：主管在大模型网页框中盲目复制无用代码、混淆 LLM 与 Agent 能力、缺乏 Tools 权限沙箱隔离。
- **核心突破口**：解构 LLM(大脑) + Tools(手脚) + Agent(执行者) 物理架构，明确三类业务原型分类，通过 ReAct 单步自修模式在 15 分钟内运行首个原型系统。

## 二、 逆向目标与四步概念卡

### 2.1 Bloom ABCD 学习目标 (100% 原始权威对齐)
完成本课后，学员将能够：
1. **[Objective 1 - Apply (3)]**：**识别与阐述** LLM（大脑）、Tools（手脚）、Agent（执行者）、ReAct（反馈循环）与 Workflow（流程门禁）5 大核心概念及其物理区别。
2. **[Objective 2 - Analyze (4)]**：**区分与选择** 适合自身部门的三类业务原型（A. 监控决策型 / B. 任务流程型 / C. 操作工具型）。
3. **[Objective 3 - Evaluate (5)]**：**行使人在回路 (HITL) 授权**，利用 Workflow 确认门禁精准管控 Agent 修改代码的权限。
4. **[Objective 4 - Create (6)]**：**验证与交付** 包含虚构模拟数据（Mock Data）的首个可运行页面，并获得验证脚本的 `[PASS]` 结论。

### 2.2 核心概念四步解析卡集

#### 💡 概念卡 1：LLM、Tools、Agent、ReAct 与 Workflow 五位一体架构
1. **硬核工程定义**：LLM 推理引擎、Tools 接口、Agent 自主循环、ReAct 闭环与 Workflow 防火墙构成的五层系统。
2. **底层运作机制**：LLM 推理方案；Tools 执行写盘；Agent 在 ReAct 循环中自动纠错；Workflow 门禁进行权限拦截。
3. **具象业务比喻**：**建筑工程指挥部** 🏗️。
4. **IT 沟通场景**：“我们基于 LLM + Tools 架构搭建了 Agent 原型系统，通过 Workflow 门禁拦截越界修改。”

#### 💡 概念卡 2：三类业务原型分类 (Three Business Prototype Classes)
1. **硬核工程定义**：根据业务交互形态与数据流转特征划分的三种标准原型范式：监控决策型、任务流程型、操作工具型。
2. **底层运作机制**：A 类看图表；B 类走流程与状态机；C 类高效表单录入。
3. **具象业务比喻**：**医院的三个核心科室** 🏥。
4. **IT 沟通场景**：“本期原型确定为 B 类‘任务流程型’工单看板，优先验证流程状态机。”

#### 💡 概念卡 3：人在回路 (HITL) 授权与 Tools 权限沙箱门禁
1. **硬核工程定义**：在 Agent 自动化循环中强制植入人工审查盖章节点，配合系统级沙箱进行最小权限控制的设计。
2. **底层运作机制**：修改文件前物理被 Tools 防火墙拦截；等待主管在终端输入盖章口令后方解锁。
3. **具象业务比喻**：**财务付款的双签审批** ✍️。
4. **IT 沟通场景**：“项目严格执行人在回路授权，Agent 无法静默修改核心配置文件。”
