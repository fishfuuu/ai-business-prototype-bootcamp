## 二、 逆向目标与四步概念卡

### 2.1 Bloom ABCD 学习目标
完成本课后，学员将能够：
1. **[Objective 1 - Apply (3)]**：在 VS Code 终端环境下 (**C**)，学员 (**A**) 能下发指令与运行 `npm run dev` (**B**)，在 127.0.0.1 试衣镜中加载首个高保真页面 (**D**)。
2. **[Objective 2 - Analyze (4)]**：在面对模拟数据展示时 (**C**)，学员 (**A**) 能辨析静态 Mock 数据与生产真实 API 的解耦防护逻辑 (**B**)，恪守模拟数据防错红线 (**D**)。
3. **[Objective 3 - Evaluate (5)]**：在页面创建完成后 (**C**)，学员 (**A**) 能要求 AI 增量修改 `PROJECT_STATE.md` (**B**)，实现工程状态的磁盘物理盘点 (**D**)。

### 2.2 核心概念四步解析卡集

#### 💡 概念卡 1：Tools 权限沙箱与 127.0.0.1 试衣镜
1. **硬核工程定义**：指令隔离屏障与基于本地回环地址的实时 DOM 渲染界面。
2. **底层运作机制**：拦截越界系统调用，基于 Vite HMR 秒级刷新 DOM。
3. **具象业务比喻**：**商场的服装试衣镜与防盗安全门** 🪞。
4. **IT 沟通场景**：“我们基于 127.0.0.1 回环与 Tools 沙箱搭建了高保真原型试衣镜。”

#### 💡 概念卡 2：模拟数据防错红线 (Mock Data Guardrails)
1. **硬核工程定义**：原型阶段物理禁止调用真实后端 API，仅使用前端模拟对象。
2. **底层运作机制**：绑定本地静态 JSON/TS 文件，消除网络与后端的干扰。
3. **具象业务比喻**：**房屋样板间的塑料假电视** 📺。
4. **IT 沟通场景**：“原型阶段严格遵循模拟数据红线，优先验证交互与业务逻辑。”

#### 💡 概念卡 3：工程状态机与磁盘盘点 (`PROJECT_STATE.md`)
1. **硬核工程定义**：在根目录维护的纯文本 Markdown，记录模块就绪度与技术债务。
2. **底层运作机制**：修改代码后增量更新文件，作为跨会话的物理记忆载体。
3. **具象业务比喻**：**施工现场的进场施工进度牌** 📋。
4. **IT 沟通场景**：“项目状态收扣在 `PROJECT_STATE.md` 中，随时可审计工程完成度。”

## 五、 逐 Task 极客示范与巡视指导

### Task 0: 启动本地试衣镜与环境检查
- **教师示范**：运行 `npm run dev`，打开 `http://localhost:5173/`。
- **盖章口令**：`npm run dev`
- **巡视 Check**：确认学员浏览器正常加载初始试衣镜大盘。

### Task 1: 唤醒 AI 助手创建首个业务原型页面
- **教师示范**：在 CLI 中下发创建 `src/views/WorkOrderBoard.vue` 的指令。
- **盖章口令**：`请创建工单看板页面 WorkOrderBoard.vue`
- **巡视 Check**：页面编译成功无白屏，界面显示看板雏形。

### Task 2: 绑定静态 Mock 数据源与验证
- **教师示范**：演示页面交互，强调模拟数据防错红线。
- **盖章口令**：`绑定静态 Mock 数据`
- **巡视 Check**：学员点击页面按钮无控制台报错。

### Task 3: 磁盘状态盘点与 `PROJECT_STATE.md` 更新
- **教师示范**：展示 `PROJECT_STATE.md` 文件变化。
- **盖章口令**：`更新 docs/PROJECT_STATE.md`
- **巡视 Check**：`PROJECT_STATE.md` 中工单看板模块已被标记为已创建。
