## 2. 本课定位

说明：
- **解决什么学习问题**：帮助业务主管破除对 AI 开发的恐惧，建立三类业务原型分类认知，掌握“用自然语言控盘 Agent 从零创造业务页面”的控制感，并理解 **LLM、Tools、Agent、ReAct 和 Workflow** 5 个核心概念。
- **为什么安排在当前阶段**：作为首门课程，重点是激发兴趣、确立业务主导权并建立人机协作规范。
- **与前后课的关系**：本课建立分类认知与可运行原型；第 2 课根据业务目的（监控与决策页、任务与流程工作台、操作工具与助手页）选择对应信息结构与参考图美化；第 9 课深入业务 Agent 场景判断与产品设计。

---

## 3. 核心目标

1. 理解并用自己的话说明 **LLM、Tools、Agent、ReAct 和 Workflow** 5 个基础概念。
2. 能在 Claude Code 页面制作过程中准确识别这五个概念对应的实际动作。
3. 掌握“需求表达 -> 方案裁决 -> 代码生成 -> ReAct 微调”的人机协作闭环，能使用 Workflow 确认门禁有效控制 Agent。
4. 完成至少 1 次高质量人在回路的 ReAct 微调闭环（含运行 `verify-student-project.ps1` 校验通过），产生第一个符合所选原型类型的模拟数据页面。

---

## 4. 可见成果

学员完成一个符合所选原型类型的最小业务页面：

* **监控与决策型**：一个关键信息或异常展示区域，以及一个可执行的决策动作。
* **任务与流程型**：一个任务或记录区域，一个清晰的当前状态与状态流转过程，以及一个处理动作。
* **操作工具型**：一个输入区域，一个执行动作，以及一个结果展示区域。

**共同成果**：
* 一个包含 LLM、Tools、Agent、ReAct、Workflow 的清晰人机协作认知；
* 侧边栏新增一个专属业务菜单入口；
* 基于虚构模拟数据呈现的业务结构、流程或处理结果；
* 经过至少 1 次人在回路高质量微调修正的页面呈现；
* 一份填写完整的课后概念与业务复盘记录。

---

## 5. 本课明确不做

- 不讲解 Transformer、Token 计算、Vector/Embedding 或 Function Calling 协议。
- 不讲解 LangGraph、API Schema 或 Agent 框架源码。
- 不开发登录、真实权限、后端 API 接入或真实数据库。
- 不把 Agent 描述为完全自主、可脱离人工管理的系统。

## 9. 业务场景

* **演示案例**：订单履约超时预警台（属于“监控与决策型”示例）
* **使用者**：采购主管
* **当前问题**：无法实时发现交货延期的供应商与即将超期的采购单
* **工作场景**：每日早晨巡视履约风险、筛选超时采购单并发送催单提醒
* **数据说明**：硬编码在前端组件中的虚构模拟数据演戏道具
* **强调说明**：此演示案例仅用于展现共同的人机协作流程，学员可根据自身部门痛点自由选择任务流程型或操作工具型原型。

## 10. 教师演示步骤 (5 个暂停点)

> 💡 **演示前口播**：“今天教师使用监控与决策型案例演示，但相同的人机协作流程同样适用于任务与流程型和操作工具型原型。”

### 暂停点 1：LLM 生成方案 (Task 1 阶段)
* **教师动作**：发送 Task 1 需求文本，展示 Claude 正在用自然语言生成模块规划，但终端未发生文件读写。
* **教师提问**：“Claude 刚才在提出方案时，修改你电脑上的文件了吗？”
* **结论**：没有，本步骤不主动调用新的文件读写 Tools，重点观察 LLM 对业务输入的理解与方案生成能力。

### 暂停点 2：Tools 读取项目 (Task 2 阶段)
* **教师动作**：发送 Task 2 指令，观察终端中出现 `Read file CLAUDE.md`、`Read file DESIGN.md` 等工具调用日志。
* **教师提问**：“Claude 是怎么知道咱们项目的编码规范和已经存在的组件的？”
* **结论**：它使用了 **Tools (手脚)** 读取了项目配置文件 `CLAUDE.md`（眼睛/校规）。

### 暂停点 3：Workflow 确认门禁 (Task 3 阶段)
* **教师动作**：发送主管裁决模板，停在 Claude 输出修改计划并等待回应的界面，故意停顿不输入“同意方案”。
* **教师提问**：“Claude 已经想好怎么改代码了，为什么它现在不敢直接修改文件？”
* **结论**：因为受到 **Workflow 门禁** 约束，必须等待主管人在回路授权（Human-in-the-Loop 盖章）。

### 暂停点 4：Agent 连续执行 (Task 3 执行阶段)
* **教师动作**：输入“同意方案，请开始修改代码”，观察 Agent 自动创建 Vue 页面、注册路由、添加侧边栏菜单并运行 verify 脚本。
* **教师提问**：“刚才 Agent 在获得授权后连续完成了哪些工作？”
* **结论**：Agent 是获得目标和工具后，能够在主管下达的已授权范围内连续完成多步工作的执行者。

### 暂停点 5：ReAct 观察与调整 (Task 4 阶段)
* **教师动作**：打开 `http://127.0.0.1:8888` 试衣镜，指出一个视觉或交互问题，发送微调指令，观察 Agent 修改并自动自测。
* **教师提问**：“Claude 如何根据工具返回、验证结果或浏览器效果继续调整下一步？”
* **结论**：这是可见的 ReAct 循环：行动 -> 观察结果 -> 调整 -> 再行动。它不代表 Claude 必然能够自动修好所有问题，最终仍需脚本验证和主管验收。
