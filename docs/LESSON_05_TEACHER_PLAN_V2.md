## 2. 本课定位
- **在全套课程中的位置**：承接第四课《受控 Agent 循环与 Working Tree》，构建完整的项目物理护栏与内存管理。
- **解决的核心痛点**：AI 经常“幻觉造词”、“遗忘前文约定的业务规则”、“擅自引入不相干的依赖库”导致工程失控。
- **核心突破口**：使用原生指令 `/init` 一键初始化 `CLAUDE.md`，打造工程 Harness (安全鞍具)，并建立“短期/中期/长期”三分记忆模型与 S/L 存档恢复机制。

## 3. 核心目标与 Bloom ABCD 能力矩阵

### 3.1 核心大观与本质提问 (Backward Design Stage 1)
- **核心大观 (Big Idea)**：AI 的上下文内存是有限的且会遗忘，真正的企业级 AI 编程必须依赖磁盘硬记录 (`CLAUDE.md` + 实施计划 + 规则文件) 打造工程 Harness 护栏。
- **本质提问 (Essential Question)**：如何确保 AI 在经历 50 轮对话后，依然严密遵守第一天订立的业务规范与禁用红线，绝对不产生幻觉？

### 3.2 Bloom ABCD 学习目标
完成本课后，学员将能够：
1. **[Objective 1 - Apply (3)]**：在给定的工程根目录下 (**C**)，学员 (**A**) 能使用原生 `/init` 命令行指令 (**B**)，成功生成并配置项目专属的 `CLAUDE.md` Harness 物理文件 (**D**)。
2. **[Objective 2 - Analyze (4)]**：在面对 Agent 潜在的幻觉与遗忘风险时 (**C**)，学员 (**A**) 能熟练运用上下文防幻觉三件套 (Context Inspection / Token Audit / Compact) (**B**)，准确判断 AI 的注意力衰减点并及时进行长短期记忆提纯 (**D**)。
3. **[Objective 3 - Create (6)]**：在跨会话开发与中断恢复场景下 (**C**)，学员 (**A**) 能通过存读档机制 (`S/L State Restore`) (**B**)，创建并还原完整的工程快照状态机 (**D**)。

## 9. 业务场景
- **案例背景**：团队多人协同开发业务原型，不同人使用的 AI 助手经常各自使用 `yarn`、`pnpm` 或 `npm` 导致安装依赖冲突，或者 AI 擅自修改未授权的底层系统路由。
- **解决方案**：在根目录配置 `CLAUDE.md` Harness，统一包管理器为 `npm`，硬性封杀未经许可的全局依赖安装。

## 14. 核心工程概念【四步解析卡】

### 概念 1：Engineering Harness (工程鞍具 / 物理护栏)
1. **硬核工程定义**：为了约束 AI Agent 行为边界而建立的物理配置文件、自动化校验脚本与权限防火墙组合。
2. **底层运作机制**：在 Agent 发起系统调用或修改代码前，强制先读取 Harness 规则，违规操作将被静默系统直接拦截。
3. **具象业务比喻**：**赛马的鞍具与缰绳**。给野马套上鞍具和缰绳，骑手（主管）才能精准控制马儿奔跑的方向。
4. **IT 沟通与交接价值**：“我们为 Agent 部署了工程 Harness，防止其产生幻觉或越权修改生产代码。”

### 概念 2：CLAUDE.md (项目级长期记忆护栏)
1. **硬核工程定义**：位于工程根目录下的 Markdown 规范文件，专门用于向 Claude Code CLI 提供项目指令、构建规则与行为禁令。
2. **底层运作机制**：在每次交互开始时被系统自动注入 Context 顶部，权重仅次于 System Prompt。
3. **具象业务比喻**：**贴在办公桌前盖了公章的《员工守则与红线禁令》**。
4. **IT 沟通与交接价值**：“通过 `CLAUDE.md` 物理锁定包管理器与构建脚本，确保 AI 生成的代码符合团队工程规范。”
