## 一、 课程元数据与定位

### 1.1 课程元数据
- **课程名称**：AI 业务原型开发训练营·第三课
- **主讲主题**：把模糊想法变成可执行的业务契约：grill-me 澄清与 3 份契约冻结
- **授课对象**：非技术背景业务主管 / 产品经理 / 业务专家 (10–30人)
- **课时时长**：90 分钟 (极客控场 + 5 个固定 Pause Points)
- **授课模式**：18 分钟极客示范 ➔ 10 分钟概念核对 ➔ 45 分钟学员分步实操 ➔ 10 分钟验证归档
- 本课学员 Skill 名称 | /grill-me
- **前置依赖**：学员已完成第二课并掌握 `DESIGN.md` 视觉 Harness 与 Discard Changes 物理撤销。
- **教学验证状态**：PILOT_PASSED
- **课程负责人**：官方教研组

### 1.2 本课定位与背景痛点
- **在全套课程中的位置**：承接第二课《视觉 Harness 与事实锚定》，从前端样式走向真正的业务逻辑与数据契约冻结。
- **解决的核心痛点**：需求模糊盲目开工、AI 自作主张脑补字段、数据格式与组件失配、缺乏生产脱敏规约。
- **核心突破口**：唤醒 `/grill-me` 互动追问，解构 6 大业务要素，标注敏感度脱敏规约，冻结 3 份业务与数据契约，并通过 Task 3A 只读结构预览门禁实现受控写入。

## 二、 逆向目标与四步概念卡

### 2.1 Bloom ABCD 学习目标 (100% 原始权威对齐)
完成本课后，学员将能够：
1. **[Objective 1 - Apply (3)]**：在 CLI 环境下 (**C**)，学员 (**A**) 能唤醒 `/grill-me` 追问 Skill 并完成 3 轮问答 (**B**)，梳理出包含 6 大要素的业务功能边界 (**D**)。
2. **[Objective 2 - Analyze (4)]**：在面对需求资产与 Mock 数据时 (**C**)，学员 (**A**) 能标注数据敏感等级 (**B**)，建立面向未来生产网关的脱敏规约 (**D**)。
3. **[Objective 3 - Evaluate (5)]**：在执行代码写入前 (**C**)，学员 (**A**) 能要求执行 Task 3A 只读结构预览门禁 (**B**)，并在确认无误后下发 Task 3B 盖章口令授权写入 (**D**)。

### 2.2 核心概念四步解析卡集

#### 💡 概念卡 1：`grill-me` 追问澄清机制与 6 大业务要素 (`BUSINESS_FEATURE_CARD.md`)
1. **硬核工程定义**：AI 扮演资深产品架构师，通过连续多轮针对性提问，逼平业务模糊点并落盘为包含 6 大业务要素的功能契约的范式。
2. **底层运作机制**：针对 User & Problem, Goal, Boundary, Risk, Given-When-Then, Stop / Escalation 依次提问。
3. **具象业务比喻**：**装修开工前的主材确认清单** 📝。
4. **IT 沟通场景**：“需求已通过 `grill-me` 完成澄清，落盘为包含 6 大要素的 `BUSINESS_FEATURE_CARD.md`。”

#### 💡 概念卡 2：工程拨乱反正卡：为什么假数据也要标记敏感度？
1. **硬核工程定义**：在原型阶段为 Mock 字段标注隐私等级，建立面向生产环境的脱敏规约。
2. **底层运作机制**：告知未来生产网关必须在物理层切断该敏感字段，禁止送入 LLM 模型。
3. **具象业务比喻**：**演习炸药箱上的红字警示标签** ⚠️。
4. **IT 沟通场景**：“数据契约表标注了敏感等级，作为未来生产 API 网关脱敏过滤的交接规约。”

#### 💡 概念卡 3：数据契约与海关报关单 (Data Contract TS Types & Mock Data)
1. **硬核工程定义**：使用 TypeScript Interface 强类型定义业务对象物理字段，配合 Mock 数据文件实现的前后端数据协议。
2. **底层运作机制**：在 `prototype-contract.d.ts` 声明类型，在 `prototype-data.ts` 填充静态测试对象。
3. **具象业务比喻**：**海关进口商品的标准报关单海关编码** 📦。
4. **IT 沟通场景**：“我们冻结了 `prototype-contract.d.ts` 数据契约，保证前端界面与数据字典 100% 匹配。”

#### 💡 概念卡 4：`Given-When-Then` 验收标准与 `Stop / Escalation` 升阶条件
1. **硬核工程定义**：行为驱动开发 (BDD) 的结构化验收语法，配合异常越界时的自动停止与人工升阶机制。
2. **底层运作机制**：定义前置条件、触发动作与预期结果；遇到数据丢失或规则冲突时触发 Stop 熔断并升级升阶。
3. **具象业务比喻**：**工厂流水线的紧急拉绳熔断阀** 🛑。
4. **IT 沟通场景**：“功能卡包含了 Given-When-Then 验收链条与 Stop / Escalation 升阶条件，规避了黑盒风险。”

## 五、 逐 Task 极客示范与巡视指导

### Task 1: 唤醒 `grill-me` 技能进行需求追问
- **教师示范**：下发选择 B 类原型与痛点的 `grill-me` 提示词模板，示范救援指令。
- **盖章口令**：下发 `grill-me` 发起提示词模板
- **巡视 Check**：确认学员完成了 3~5 轮单问题追问，未触发提前写文件。

### Task 2: 数据契约卡梳理与敏感度标记
- **教师示范**：下发 7 维基础契约表与 3 类原型专属扩展契约 Prompt 模板。
- **盖章口令**：下发数据契约表 Prompt 模板
- **巡视 Check**：表格包含了公开/内部/严禁发送AI 的敏感等级。

### Task 3 (Task 3A/3B): 只读结构预检与授权落盘数据契约
- **Task 3A 示范**：下发 Task 3A 只读预览 Prompt 模板，强调禁止直接写入代码与禁止 `cd` 切换目录。
- **Task 3B 示范**：发送 HITL 盖章口令授权 Task 3B 写入。
- **盖章口令**：`同意方案，请开始落盘功能卡与契约资产`
- **巡视 Check**：`docs/BUSINESS_FEATURE_CARD.md`、`src/types/prototype-contract.d.ts` 与 `src/mocks/prototype-data.ts` 成功落盘。

### Task 4: 验证、状态更新与 Git 提交
- **教师示范**：演示 `PROJECT_STATE.md` 中记录基线 Commit SHA 步骤与脚本校验。
- **盖章口令**：`git commit -m "feat: complete lesson 3 requirement..."`
- **巡视 Check**：日志显示完结 Commit SHA 作为第 4 课前置凭证。
