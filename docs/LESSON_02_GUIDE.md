# 第二课学员指南：用参考图与设计规则做出像样的企业页面

欢迎来到第二课！在第一课中，你已经建立了属于自己的系统页面雏形。这节课，我们将学习如何使用脱敏参考图和项目 Design Rules（设计规范），把粗糙的雏形重构为好看、规范、符合企业级水准的高颜系统页面！

---

## 0. 这节课解决什么问题

### 核心问题
> **如何借用参考图的好布局，但又不抄参考图的杂乱颜色和字体？如何确保样式美化时不把业务逻辑改坏？**

```text
+-----------------------------------------------------------------------------------+
|                         第二课 视觉重构四步闭环                                   |
|                                                                                   |
|  [Task 1: 提取结构] -> [Task 2: 规范映射] -> [Task 3: 取舍裁决] -> [Task 4: 微调验收] |
|                                                                                   |
|   - 借用布局主次          - 100% 映射变量       - Keep / Omit        - 试衣镜对比      |
|   - 禁用参考图杂色        - 优先 --art-* Token  - Remove / Modify    - 脚本验证 PASS   |
+-----------------------------------------------------------------------------------+
```

### 核心设计原则：`业务需求 > DESIGN.md 规范 > 现有组件样式 > 参考图灵感`

一句话记住视觉美化铁律：
> **参考图只借布局和视觉主次，绝不继承杂色与字体；重构样式绝对不等于修改业务逻辑！**

## 1. 开始前准备与 Git 安全概念

1. **环境确认**：确认你在第一课创建的项目可在 `http://127.0.0.1:8888` 本地试衣镜中正常渲染和点击。
2. **选择脱敏参考图卡**：根据你在第一课选择的业务原型，选择对应的参考图卡进行多模态分析：
   - **A. 监控与决策型**：使用脱敏图卡 `docs/assets/lesson-02/ref-monitor-decision.png`
   - **B. 任务与流程型**：使用脱敏图卡 `docs/assets/lesson-02/ref-task-workflow.png`
   - **C. 操作工具型**：使用脱敏图卡 `docs/assets/lesson-02/ref-operation-tool.png`

### 🛡️ 概念理解：把 Git 当作“游戏阶段存档（SL 大法）”
对于运营主管来说，**Git 就是代码界的“游戏阶段存档与读档（Save & Load）”**：
- **`Git Commit` (提交)** 相当于 **【节点手动存档 Save】**：每当完成一个重要的阶段节点，手动存个档，记录一个稳定的代码里程碑；
- **`Git Diff` (对比)** 相当于 **【装备属性对比】**：监视 AI 帮你改了哪些行（绿色新增、红色删除），防止 AI 越界误删业务代码；
- **`Git Discard` (撤销)** 相当于 **【一键读档 Load】**：万一 AI 把代码改崩，1 秒恢复到上一个稳定存档，绝不掉进度。

## 2. Task 1：视觉结构提取卡 (15 分钟)

### 💡 知识卡：借用结构与视觉主次
* 参考图是视觉灵感来源，但我们只从中提取 **(1) 首屏布局**、**(2) 模块划分** 和 **(3) 视觉焦点**。
* 禁用参考图中的背景色、品牌色与自定义字体，防止页面变成不可维护的“大杂烩”。

### 复制并发送给 Claude Code（提取结构 Prompt）：

```text
请读取项目中的参考图卡文件：
- docs/assets/lesson-02/ref-monitor-decision.png (或 ref-task-workflow.png / ref-operation-tool.png)

请帮我分析这张参考图的视觉结构，并列出：
1. 首屏的整体布局（如顶部 KPI 栏、左右双栏、三段式卡片流）
2. 页面中视觉最醒目的核心模块（主视觉焦点）
3. 次要信息与操作区域的排布规律

注意：请只提取布局和结构，不要使用参考图中的任何背景颜色、字体或杂乱样式。
先不要修改代码，只输出分析结果。
```

### 🚩 本步检查 (Checklist)
- [ ] Claude Code 识别出了参考图的首屏布局与主次焦点。
- [ ] Claude 明确承诺只借用结构，不复制杂色。

## 3. Task 2：设计规范映射卡 (15 分钟)

### 💡 知识卡：Design Tokens (设计变量) 与品牌一致性
* 翻看项目的设计系统规则 [DESIGN.md](./DESIGN.md) 和通用组件库 [docs/COMPONENT_CATALOG.md](./COMPONENT_CATALOG.md)。
* 映射规则：将颜色、圆角、阴影、文字层级等**优先映射到项目已有的 `--art-*` Tokens**（如 `--art-primary`, `--art-card-bg`, `--art-text-primary`, `--art-border-default`, `--art-radius-panel`, `--art-shadow-panel`）、现有组件配置与允许的 8/12/16/24px 间距规则。
* ⚠️ **禁令**：不得虚构 Token，不得新建颜色体系，不得擅自覆盖 `.el-*` 主题样式。

### 复制并发送给 Claude Code（规范映射 Prompt）：

```text
现在，请戴上眼睛读取项目中的设计规范文件：
- DESIGN.md
- docs/COMPONENT_CATALOG.md

请将 Task 1 提取的结构与 DESIGN.md 进行映射，说明：
1. 页面背景、卡片容器与文字颜色如何映射到已有的 --art-* 变量
2. 间距与圆角如何符合 8/12/16/24px 规范
3. 哪些区域可以直接复用现有组件库中的结构（如 ElCard, ElTag, ElButton）

注意：不得虚构不存在的 Token，不得新建样式库。先不要修改文件，只输出映射方案。
```

### 🚩 本步检查 (Checklist)
- [ ] 所有颜色与样式均显式映射到 `--art-*` 规范。
- [ ] 未产生硬编码颜色与自定义 CSS 变量。

## 4. Task 3：Keep / Omit / Remove / Modify 裁决与安全重构 (10 分钟)

### 💡 知识卡：业务逻辑冻结线与人在回路授权
* 视觉美化绝对不能破坏业务逻辑。必须明确区分：
  - **Keep (保留现有的业务逻辑/模拟数据)**：硬性冻结第一课已确认的字段、计算规则与模拟数据；
  - **Omit from Reference (参考图中忽略的内容)**：参考图中与我们业务无关的修饰；
  - **Remove from Current Page (现有页面清理项)**：第一课雏形中临时搭的粗糙废料；
  - **Modify (3 项视觉改进)**：本课重点改进的首屏层级、布局间距与核心动作显眼度。

### 🎮 节点 1 存档动作（在喊授权口令前执行）：
在将裁决矩阵发送给 AI 之前，先完成**【节点 1 游戏手动存档 Save】**：
1. 打开 PowerShell 终端；
2. 依次运行以下安全存档指令：
   ```powershell
   git status
   git add .
   git diff --cached
   git commit -m "baseline: complete lesson 1 prototype"
   ```
   锁定第一课完成态基线提交！

### 复制并发送给 Claude Code（主管裁决与授权模板）：

```text
针对第二课页面美化，我的裁决如下：

1. Keep (保留并冻结现有业务内容)：
【填写第一课页面中必须保留的字段、模拟数据与计算逻辑】

2. Omit from Reference (参考图忽略项)：
【填写参考图中不需要复制的无关图表或修饰元素】

3. Remove from Current Page (现有页面清理项)：
【填写第一课页面中粗糙无用的临时占位文本】

4. Modify (明确进行的 3 项视觉改进)：
(1) 重构首屏视觉层级，突出核心区域
(2) 优化卡片布局与 16/24px 间距
(3) 提升关键状态与核心操作按钮的显眼度

请复述你理解的重构范围。在得到我回复“同意方案，请开始修改代码”前，不要修改文件。
```

当 Claude 复述完并等待授权时，发送最终授权口令：
`同意方案，请开始修改代码`

### 🚨 监视与一键读档救急（Diff & Discard）：
- AI 修改代码后，点击侧边栏变更的文件列表打开 **Diff 红绿视图**，监视是否有第一课的核心业务代码被误删；
- **如果满意**：准备进入 Task 4；
- **如果 AI 改崩代码**：在 VS Code 源代码管理面板中找到该文件，点击右侧的 **Discard Changes (放弃更改 / 反转箭头图标)**，安全恢复修改前状态！

### 🚩 本步检查 (Checklist)
- [ ] 已完成节点 1 手动存档 `baseline: complete lesson 1 prototype`。
- [ ] 仅对许可的页面进行视觉重构，没有改变业务计算公式与模拟数据字段。

### 💡 概念参考答案：
* **参考图定位**：借用首屏布局与视觉主次，绝不继承参考图的背景杂色或字体。
* **Design Tokens**：优先使用项目 `--art-*` 设计变量，保持系统全局颜色与规范一致。
* **业务逻辑冻结**：通过 Keep 标记将业务逻辑、运算与字段硬性冻结，防止视觉美化破坏业务正确性。
* **Git 游戏节点存档**：相当于完成阶段节点时的“手动存档 Save”。分别在“Task 3 授权 AI 修改代码前（提交 lesson-02-before-refactor）”和“Task 4 课程结束验证 PASS 后（提交 lesson-02-complete）”完成两次存档。
* **一键读档救急**：点击 Discard Changes（放弃更改 / 小撤销图标），1 秒恢复到上一个稳定存档。
* **验证状态**：运行 `verify-student-project.ps1` 校验成功获得 `[PASS]`。
