## 2. 本课定位
在第一课学员完成粗糙未排版原型页面的基础上，帮助主管建立 **“多模态视觉提取 + DESIGN.md 规则约束 + Keep/Remove/Modify 裁决”** 的标准化美化方法论。防止主管对 AI 随意说“做得好看一点”导致样式崩溃，训练主管控制 Agent 完成一个页面的 3 项视觉改进。

---

## 3. 核心目标
1. 能够使用 1 张参考图提取信息排版与字段层级；
2. 能够在 `DESIGN.md` 约束下下达样式铁律（禁止继承参考图杂乱颜色）；
3. 能够填写《Keep / Omit / Remove / Modify 裁决卡》，守住业务逻辑冻结线；
4. 能够完成一个页面的 3 项最小视觉改进，并保存前后对比截图（存入 `artifacts/lesson-02-evidence/`）；
5. 运行 `verify-student-project.ps1` 校验显示 PASS。

---

## 4. 可见成果
* 修改前的粗糙原型截图 `artifacts/lesson-02-evidence/before.png`；
* 修改后的专业原型截图 `artifacts/lesson-02-evidence/after.png`；
* 填写完整的 4 张标准化实操卡；
* 显示 PASS 的工程校验脚本输出。

---

## 5. 本课明确不做
* 全系统多页面联动重构；
* 重写通用底层组件或 Element Plus 内部样式；
* 增加复杂的动态动画与高并发接口；
* 修改第一课已有的业务口径与计算逻辑；
* 完整响应式移动端适配。

## 9. 业务场景
采购主管的“供应商履约预警工作台”在第一课做出了原型，但字段堆叠、颜色混乱、超时预警 Tag 不明显。主管通过一张清晰的列表型参考图，结合 `DESIGN.md` 的警告色变量，将其重构为专业级管控台。

---

## 10. 教师演示步骤 (含 5 个固定暂停点)

### 演示准备
打开第一课粗糙页面与 Element Plus `DESIGN.md`。

### 暂停点 1：看到参考图时暂停
* **提问**：“参考图中我们真正需要借鉴的是什么？”
* **结论**：借排版和结构层级，不照抄皮肤和杂乱颜色。

### 暂停点 2：完成视觉提取后暂停
* **提问**：“参考图里炫酷的模块适合我们的业务吗？”
* **结论**：参考图是灵感，不是需求文档，不符合业务的果断删去。

### 暂停点 3：读取 `DESIGN.md` 后暂停
* **提问**：“当参考图的视觉风格和我们项目的 `DESIGN.md` 冲突时，听谁的？”
* **结论**：设计优先级：`业务需求 > DESIGN.md 规范 > 项目现有组件样式 > 参考图灵感`。

### 暂停点 4：Agent 修改代码前暂停
* **提问**：“Keep、Remove 和 Modify 是否已由主管签字确认？”
* **结论**：主管掌控取舍与业务冻结，Agent 负责实现。未授权不能改业务逻辑。

### 暂停点 5：浏览器预览后暂停
* **提问**：“`verify` 脚本 PASS 是否代表视觉设计就合格了？”
* **结论**：工程代码没崩与视觉清晰好看是两回事，必须看对比截图肉眼验收。

## 19. 常见问题
* **Q**：Agent 把参考图的品牌颜色硬编码进了页面怎么办？
  * **A**：要求 Agent 立即撤销，下达指令：“强制使用 DESIGN.md 变量，禁止硬编码颜色”。
* **Q**：Agent 修改完后页面空白或报错怎么办？
  * **A**：使用救援提示词：“请立即停止修改，将代码撤销恢复到上一步”。
