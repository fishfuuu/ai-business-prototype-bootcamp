## 2. 本课定位

说明：
- **解决什么学习问题**：破除“美化页面就是抄杂色”或“视觉重构会破坏业务逻辑”的误区。掌握多模态视觉解构、`DESIGN.md` 设计规范约束与 Keep/Modify 裁决矩阵，理解 AI Token 随机猜测机制与 Design Token 确切收敛的物理逻辑。
- **为什么安排在当前阶段**：第 1 课解决“从无到有”，本课解决“从粗糙到高颜值与工程规范”，为后续需求深化奠定高保真视觉基底。
- **与前后课的关系**：重构第 1 课雏形；第 3 课在此高颜页面基础上，使用 `grill-me` 澄清业务功能卡。

---

## 3. 核心目标

基于布鲁姆分类法（Bloom's Taxonomy），本课目标如下：

1. **阐述** AI Token 概率采样导致的输出随机性，以及如何使用 Design Token 强制收敛 AI 的视觉挥发。
2. **运用** Agent 多模态视觉能力，从脱敏参考图中解构首屏布局与视觉焦点，100% 过滤物理杂色。
3. **查阅与映射** `DESIGN.md` 设计字典，将样式显式映射至 `--art-*` 设计变量与标准组件库。
4. **执行** Keep/Modify 裁决矩阵，划定业务逻辑冻结线，实现视觉重构零破坏业务代码。
5. **运用** Git 3 步安全防护法（Commit 节点存档、Diff 红绿监视、Discard 1秒还原），获得 `verify-student-project.ps1` 校验 `[PASS]`。

## 5. 本课明确不做

- 不继承参考图中的背景色、品牌杂色或未授权的第三方字体。
- 不修改与视觉重构无关的全局路由骨架或后端通信协议。
- 不使用脱离 `DESIGN.md` 约束的黑盒生成技能（如 `UI UX Pro Max` 等容易引入私货杂色的技能）。

## 10. 教师演示步骤 (5 个固定暂停点)

### 暂停点 1：参考图多模态结构提取 (Task 1 阶段)
* **教师动作**：展示参考图卡 `ref-monitor-decision.png`，指示 Agent 提取首屏布局，强调禁用参考图杂色。
* **教师提问**：“参考图上的所有元素和颜色我们都要抄过来吗？AI 提取图片的底层工程机制是什么？”
* **硬核解析**：不抄杂色！这是 Agent 的**多模态能力**，将物理图片转化为 Vision Tokens 理解空间结构。主管可在日常业务中拍竞品截图、纸质单据或白板草图发给 Agent 提炼结构。

### 暂停点 2：点开 DESIGN.md 与双 Token 映射 (Task 2 阶段)
* **教师动作**：在大屏幕上点击打开 `DESIGN.md` 文件，指着 `--art-primary` 规范说明，并同步指示运行时 CSS 变量保存在 `src/assets/styles/tailwind.css`。
* **教师提问**：“大家看 `DESIGN.md`，它是规范说明书；真正被浏览器加载的运行时定义在 `tailwind.css`。为什么组件不能直接硬编码 Hex 颜色，而必须引用 `var(--art-primary)`？”
* **硬核解析**：AI 因为一直在“猜测下一个 Token”，表现得像一个概率采样的画家；而 `DESIGN.md` 规范与 `tailwind.css` 变量就是物理戒尺。组件引用 Token 变量，修改 `tailwind.css` 物理定义即可影响全站效果。

### 暂停点 3：节点 1 Git 存档与 Keep 业务裁决 (Task 3 阶段)
* **教师动作**：展示 PowerShell 运行 `git commit -m "baseline: ..."`，然后在 Keep 矩阵中填入第一课的超时计算公式。
* **教师提问**：“为什么在喊授权口令前一定要先进行 Git Commit 存档？为什么特别标明 Keep？”
* **硬核解析**：`Git Commit` 是代码界的【手动存档 Save】；Keep 是业务逻辑冻结线，确保视觉美化绝不破坏业务正确性。

### 暂停点 4：Agent 连续重构与监视 (Task 3 执行阶段)
* **教师动作**：发送“同意方案，请开始修改代码”，展示 Agent 自动重构样式，并打开 VS Code Diff 视图展示红绿对比。
* **教师提问**：“如果 AI 在改样式时改崩了代码，或者误删了业务公式，我们怎么无损救急？”
* **硬核解析**：使用 VS Code 的 `Discard Changes`（放弃更改），1 秒就能【无损读档 Load】恢复到刚才 Commit 的快照！

### 暂停点 5：试衣镜对比与自动化脚本验收 (Task 4 阶段)
* **教师动作**：打开试衣镜展示高颜效果，运行 `powershell -File .\scripts\verify-student-project.ps1` 输出 `[PASS]`。
* **教师提问**：“重构完成后，如何证明我们的页面既好看又没有把工程改崩？”
* **硬核解析**：通过试衣镜观察视觉效果，配合 `verify-student-project.ps1` 脚本进行静态语法与工程结构断言。
