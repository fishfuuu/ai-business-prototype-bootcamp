# 第十课教师教案——冻结原型包，形成产品决策与开发启动包

> **核心思想：收口十课主线，不再新增功能；把原型、契约、智能机会、证据、评审、红线、责任和未完成项交给 IT，明确哪些仍不能上线。**

## 一、课程元数据与定位

| 项目 | 本课设定 |
| --- | --- |
| 学员 | 已完成前九课、拥有候选原型、契约、证据、评审记录和部门 AI 机会与 Agent 范式选型图的业务主管 |
| 时长 | 90 分钟硬上限：85 分钟主线 + 5 分钟机动 |
| 课堂主成果 | 产品决策与开发启动包：包含问题与使用者、现有原型、业务/数据/验收契约、AI 机会与范式选型、测试和独立评审证据、风险红线、三链责任、未完成项、主管决策和五分钟业务汇报 |
| 主管判断成果 | 作出继续开发、调整方向、暂缓或拒绝的产品决定，明确生产化前置和责任人 |
| 支撑成果 | `docs/PROJECT_STATE.md` 更新最终产品决策摘要，只作跨课交接 |
| 数据边界 | 只使用 Mock 或已脱敏数据；不执行真实上线、部署或发布 |

本课用同一个个人原型串起两条学习线：原型线要求"冻结当前可操作原型与证据，不在最后一课临时补新页面或新能力"，主管线要求"作出继续开发、调整方向、暂缓或拒绝的产品决定，明确生产化前置和责任人"。两条线分别验收，不能相互抵分。

本课不做：在最后一课新增功能填满"完整度"、用 placeholder 假装缺口已完成、声称课程产物生产就绪、执行真实上线或部署。

开场必须先制造一个可见区别：把一堆散乱 HTML 文件丢给 IT 被拒收 vs 一份可追溯、有证据、有红线的开发启动包让 IT 能开始正式设计。先让学员看见"散乱交付 vs 结构化交接"的区别，再解释五个概念。

## 二、逆向目标、证据与核心概念

### 2.1 目标—活动—证据

| 学习目标 | 课堂活动 | 通过证据 |
| --- | --- | --- |
| 学员能盘点十课资产，区分已证实、仅 Mock/模拟、未验证和明确未实现 | Task 1 资产盘点 | 四类资产有清单，每项有来源和状态标签 |
| 学员能对照 L9 选型，确认保留的智能机会、拒绝项、风险红线与 owner | Task 2 红线与选型确认 | 保留项、拒绝项和红线有理由，每项有 owner |
| 学员能用 L7/L8 证据说明原型在哪些范围内成立，列出未解决 findings | Task 3 证据覆盖范围 | 成立范围有证据引证，未解决 findings 有清单 |
| 学员能作出继续/调整/暂缓/停止的产品决定，并形成 IT 下一步清单 | Task 4 产品决策 | 决定有理由，IT 清单有优先级和前置 |
| 学员能完成五分钟汇报：业务问题、原型证据、AI 选择、风险边界、需要 IT 做什么 | Task 5 五分钟汇报 | 五分钟内覆盖五个要素，结论可追溯 |

概念分层：核心概念为原型与生产系统、风险红线与非目标、产品决策、生产就绪缺口、责任交接；原型交付就绪度检查为课程方法，开发启动包为交付产物。PROJECT_STATE.md 在实操中使用但不升级为核心概念。

### 2.2 四步概念解析公式

#### 非生产就绪系统（原型与生产系统）

1. **是什么 / 不是什么**：原型验证路径和决策；生产系统还需正式架构、安全、数据、测试、运维与责任治理。原型能跑通不等于能上线，原型的 Mock 数据和模拟智能行为不能冒充生产能力。
2. **机制**：原型回答"这条业务路径值不值得做、该不该用 AI"；生产系统回答"如何在安全、性能、成本和合规下稳定运行"。两者面向不同问题、不同标准和不同团队。
3. **类比 / 反例**：建筑模型与真实建筑——模型验证户型和动线是否合理，真实建筑还需要结构计算、消防审批、水电工程和施工许可；不能因为模型好看就跳过施工图。
4. **交接价值**：回指 Task 1——学员盘点十课资产时，必须区分已证实和仅 Mock/模拟，这就是原型与生产系统的分界线。

#### 风险红线与非目标

1. **是什么 / 不是什么**：明确不能自动执行、必须人工批准、暂不建设或留给后续工程的事项；不是"所有风险都要在本课解决"，而是"所有风险都要被看见、被记录、有 owner"。
2. **机制**：从 L9 的三链责任和 fallback 中提取红线——不可逆动作（资金、合同）、高敏感数据、责任不清的模糊判断、难以验证的开放任务；把红线写入开发启动包，让 IT 知道哪些不能碰、哪些暂不做。
3. **类比 / 反例**：交房时的非交付清单——房屋交付时附一份"尚未完成或需要业主自行处理"的清单，不假装一切都好；也不是"有问题就不交房"，而是"交房时说明清楚"。
4. **交接价值**：回指 Task 2——学员对照 L9 选型确认红线和 owner 时，就在做风险红线与非目标的确认。

#### 产品决策

1. **是什么 / 不是什么**：根据价值、证据、风险和成本选择继续、调整、暂缓或停止，不以"做出来了"自动等于应该建设；不是所有原型都要上线，也不是做出来就白做了。
2. **机制**：把价值（值不值得）、证据（能不能证明成立）、风险（出了问题多大代价）和成本（正式开发需要多少投入）四项放在一起，作出一个有理由的产品决定。决定可以是继续、调整方向、暂缓或停止，四者都是合理选择。
3. **类比 / 反例**：投资决策——不是每个项目都投，不是每个项目都拒绝；依据预期回报、风险评估、已有证据和资金成本作决定；做出来了不等于应该投，没做也不等于白做。
4. **交接价值**：回指 Task 4——学员作出继续/调整/暂缓/停止的决定并写理由。

#### 生产就绪缺口

1. **是什么 / 不是什么**：把已确认事实、证据、缺口和下一步交给 IT；不是一键生成的可上线包，不是包含源码和数据的交付 ZIP。它是一份结构化的输入文件，让 IT 知道从哪里开始、依据什么、缺什么。
2. **机制**：汇总十课成果——问题与使用者、现有原型、业务/数据/验收契约、AI 机会与范式选型、测试和独立评审证据、风险红线、三链责任、未完成项、主管决策——形成一份 IT 能读懂、能追溯、能开始正式设计的输入。
3. **类比 / 反例**：项目交接仪式——不是把钥匙丢给对方就走，而是带着建筑模型、竣工证据、红线清单和未完成清单坐下来，逐项说明"这是什么、证明了什么、还差什么、谁负责"。
4. **交接价值**：回指 Task 1—4 的汇总——学员把所有资产和决策汇总成一份结构化包。

#### 责任交接

1. **是什么 / 不是什么**：业务、数据、模型、工具、审批、失败处置和上线门禁都有明确 owner；不是"交给 IT 就完了"，也不是"主管保留所有决定权"。交接是责任转移，不是责任消失。
2. **机制**：对开发启动包中每一项写明——谁是业务 owner、谁是数据 owner、谁是技术 owner、谁负责审批、谁负责失败处置、谁决定能否上线。暂不能确定的 owner 必须标"待定"并写明由谁去落实。
3. **类比 / 反例**：铁路交接——新铁路开通前，运营权、维护权、安全审批权分别移交不同部门，不是一个人全管，也不是"交了就没人管了"。
4. **交接价值**：回指 Task 2 和 Task 4——学员确认 owner 和作出决策时，就在做责任交接。

### 2.3 操作方法与交付产物

#### 交付产物：开发启动包

开发启动包汇总问题定义、现有原型、业务/数据/验收契约、AI 机会与范式选择、证据、风险红线、生产就绪缺口、责任 owner 和产品决策，供 IT 开始正式设计与开发；它不是可上线包，也不替代后续安全、数据、测试、运维和合规门禁。教师用 2—4 分钟展示清单，不展开。

#### 操作方法：原型交付就绪度检查

可以演示、可以试点、可以有限内部使用、可以生产上线是不同等级。原型完成不等于生产上线。教师用 2 分钟说明四个等级，不展开。

讲解时将五张核心卡放在同一个项目交接仪式的故事中：先看模型和真实建筑的区别，再确认红线与非目标，识别生产就绪缺口，作出产品决策，最后明确责任交接。开发启动包是交付产物，就绪度检查是操作方法。总计控制在 10 分钟左右；不要逐字朗读。

## 三、教学准备与安全边界

### 课前预检

- 前九课原型和证据可用：学员有候选原型、契约、浏览器验收证据、独立评审记录和部门选型图。
- `docs/PROJECT_STATE.md` 有选型图摘要和上一课输入说明。
- 学员能说出自己的 L9 优先候选和一个明确不做项。
- Working Tree 处于 Clean 状态：教师演示前先 `git status` 确认。
- 助教理解学员对资产盘点不熟悉时的引导方式（帮助分类而非代判断）。

### 实操前只讲四条红线

1. 不在最后一课新增功能填满"完整度"；冻结当前原型，不临时补新页面或新能力。
2. 不用 placeholder 假装缺口已完成；未完成项必须标"未实现"，Mock 项必须标"模拟"。
3. 不声称课程产物生产就绪；原型是开发起点，不是生产系统。
4. 不执行真实上线、部署或发布；不连接真实生产系统。

教师不得虚构 verify-project.ps1、package-it-handover.ps1、IT_HANDOVER_PACKAGE.zip、[PASS] 全量校验等课堂能力。实际运行什么，就展示什么证据。

## 四、90 分钟控场主线

| 时间 | 宏观阶段 | 教师动作 | 学员动作 | 阶段证据 |
| --- | --- | --- | --- | --- |
| 0—10 分 | **看见区别，建立模型** | 对比"散乱 HTML 丢给 IT 被退"vs"结构化开发启动包让 IT 能开始"；用项目交接仪式比喻和融合图讲五个概念 | 回顾前九课，能说出自己的优先候选和不做项 | 知道本课成果与五者关系 |
| 10—25 分 | **教师完整示范** | 用统一案例串演 Task 1—5，只演方法，不让学员复现 | 观察"盘资产→确认红线→核对证据→作决策→五分钟汇报"的完整动作 | 建立整体动作锚点 |
| 25—35 分 | **概念核对与准备** | 提问核对五张概念卡；确认学员想好自己的优先候选和不做项 | 口头回答卡片；完成资产盘点准备 | 概念理解和资产就绪 |
| 35—80 分 | **学员实操** | 按 Task 1（约 10 分）→ Task 2（约 10 分）→ Task 3（约 8 分）→ Task 4（约 10 分）→ Task 5（约 7 分）巡视 | 完成资产盘点、红线确认、证据覆盖、产品决策和五分钟汇报 | 产品决策与开发启动包 |
| 80—90 分 | **验收与闭合** | 指导主管验收开发启动包；检查通过证据；收取随堂题；总结十课完整认知链 | 主管验收、核对包完整性、核对答案 | 原型线和主管线分别判定 |

压缩顺序：先取消个别展示，再压缩教师示范；不得删除资产盘点、产品决策或五分钟汇报。5 道必答题分散在相应 Task 后完成，最后只检查提交。

## 五、逐 Task 示范、口令、巡视与降级

教师统一案例只走一条路径：以仓储管理为例，盘点"收货→质检→上架→拣货→发货"原型的十课资产，确认红线，核对证据，作出产品决策，完成五分钟汇报。每个 Task 均按以下四项执教。

### Task 1：盘点十课资产，区分已证实、仅 Mock/模拟、未验证和明确未实现

- **教师示范**："先把十课做的所有东西盘点一遍。"展示如何列资产清单：L1 原型路径（已证实：可操作）、L3 数据契约（已证实：字段和验收场景确认）、L4 薄切片（已证实：可见变化）、L5 智能薄片（仅 Mock/模拟：智能行为是模拟的）、L7 浏览器验收证据（已证实：截图和日志）、L8 独立评审 finding（已证实：有记录）、L9 选型图（已证实：有理由和拒绝项）、拣货路径优化智能能力（未验证：只有模拟，未接真实模型）。每项标注来源课次和状态。
- **教师口令**："盘点你十课做的所有资产。列一张清单，每项标注：来自哪课、是什么、当前状态（已证实/仅 Mock 模拟/未验证/未实现）。不要新增东西，只盘点已有的。"
- **巡视判断**：四类状态都出现了；不是所有项都标"已证实"；Mock 项标了"模拟"；未实现项标了"未实现"而非省略。
- **失败降级**：所有项都标"已证实"时追问"智能行为是模拟的还是真跑的"；漏了某课资产时提示回看 PROJECT_STATE.md；状态标签混淆时逐项确认。

### Task 2：对照 L9 选型，确认保留的智能机会、拒绝项、风险红线与 owner

- **教师示范**："对照 L9 选型图，确认保留和拒绝。"展示如何对"拣货路径优化"确认保留（有证据、低风险、可降级），对"决定是否合格"确认拒绝（责任重大、不可逆），对资金相关动作划红线，对每项写 owner（业务 owner 是主管，技术 owner 待定 IT）。
- **教师口令**："对照你的 L9 选型图，逐项确认：保留哪些智能机会、拒绝哪些、哪些是风险红线、每项的 owner 是谁。拒绝项和红线要写理由。"
- **巡视判断**：保留项有理由和 owner；拒绝项有理由；红线项有明确禁止范围；owner 不是全部写"自己"或"IT"，而是按三链分别标注。
- **失败降级**：没有拒绝项时回指 L9；owner 全写"IT"时追问"业务 owner 是谁"；红线缺失时追问"有没有不可逆动作"。

### Task 3：用 L7/L8 证据说明原型在哪些范围内成立，列出未解决 findings

- **教师示范**："用证据说明成立范围。"展示如何引证 L7 浏览器验收（"正常路径有截图证明"）和 L8 独立评审（"评审有 finding 记录"）说明原型在正常路径范围内成立；列出未解决 findings（如"失败降级路径未验证""智能行为未接真实模型"）。
- **教师口令**："用 L7 验收证据和 L8 评审记录说明你的原型在哪些范围内成立。列出未解决的 findings。不要用'应该没问题'代替证据。"
- **巡视判断**：成立范围有具体证据引证（不是笼统说"应该没问题"）；未解决 findings 有清单；没有把 Mock 当真实证据。
- **失败降级**：成立范围太笼统时追问"哪条证据证明了哪个范围"；未解决 findings 缺失时回看 L8 finding 清单；把 Mock 当真实证据时纠正。

### Task 4：作出继续/调整/暂缓/停止的产品决定，并形成 IT 下一步清单

- **教师示范**："作产品决定。"展示如何把价值（拣货路径优化值得做）、证据（有模拟和验收证据但无真实模型验证）、风险（中低，可降级）、成本（需 IT 接入真实模型和路径 API）放在一起，决定"继续开发"但标注前置条件（真实模型验证、路径 API 对接）。形成 IT 下一步清单（1. 接入真实路径计算 API；2. 接入 AI 模型验证智能行为；3. 补集成测试；4. 补监控和回滚）。
- **教师口令**："基于你的资产盘点、红线确认和证据覆盖，作出产品决定：继续、调整、暂缓还是停止？写理由。然后形成 IT 下一步清单，每项标优先级和前置条件。"
- **巡视判断**：决定有四项依据（价值/证据/风险/成本）；不是所有项都"继续"；IT 清单有优先级和前置条件；不是"全交 IT 自己看着办"。
- **失败降级**：全部"继续"时追问"有没有该暂缓的"；IT 清单没优先级时排序；决定没理由时补写。

### Task 5：完成五分钟汇报——业务问题、原型证据、AI 选择、风险边界、需要 IT 做什么

- **教师示范**："五分钟汇报。"展示五分钟汇报框架：业务问题（30 秒：仓储拣货效率低）、原型证据（60 秒：原型路径可操作、有浏览器验收证据）、AI 选择（60 秒：拣货路径优化选 ReAct、决定是否合格不用 AI）、风险边界（60 秒：资金和法务是红线、智能行为未验证、失败有 fallback）、需要 IT 做什么（30 秒：接入真实 API 和模型、补集成测试）。总计五分钟，结论可追溯。
- **教师口令**："准备你的五分钟汇报。五个要素：业务问题、原型证据、AI 选择、风险边界、需要 IT 做什么。每个要素 30—60 秒。不要超时，不要编造。"
- **巡视判断**：五分钟内覆盖五个要素；结论可追溯到前四步的资产和证据；没有编造能力或夸大已证实范围。
- **失败降级**：超时时压缩各要素时间而非删除要素；结论不可追溯时回指具体证据；编造时纠正。

核心路径通过后，让 Agent 更新 `docs/PROJECT_STATE.md`，记录最终产品决策摘要、IT 下一步清单和课程完成标记。它是课程终局交接单，不是第二份主要作业。

## 六、现场 Debug 与降级预案

| 问题类型 | 教师处置 | 禁止说法 |
| --- | --- | --- |
| 学员想补新功能填满"完整度" | 纠正"最后一课不新增功能，只盘点和冻结" | "再做一点就更完整了" |
| 学员把 Mock 当真实生产能力 | 纠正"Mock 是模拟，不是已证实能力" | "模拟跑通了就算成功" |
| 学员全部选"继续开发" | 追问"有没有该暂缓或停止的" | "做出来了就应该继续" |
| 学员把责任全推给 IT | 纠正"业务 owner 和数据 owner 是主管" | "全交给 IT 就行了" |
| 学员声称原型生产就绪 | 纠正"原型是开发起点，不是生产系统" | "原型已经可以上线了" |

## 七、随堂测试、通过标准与课后任务

### 两条线分别通过

- **原型线**：冻结当前可操作原型与证据，不在最后一课临时补新页面或新能力。
- **主管线**：包内关键结论能够追溯到契约、原型、测试或评审证据；Mock、模拟、真实能力和未验证项清楚区分；主管能说出至少三项可以继续开发和三项不能直接上线的事项；所有高风险动作、数据、系统和失败路径有 owner 或明确待定责任。
- **PROJECT_STATE.md** 只作交接，不能抵消任何一条主线的未通过。

### 必答题（5 题）

1. 原型与生产系统有什么区别？为什么原型能跑通不等于能上线？
2. 风险红线与非目标包括什么？为什么"所有风险都要被看见"比"所有风险都要被解决"更重要？
3. 产品决策的四个依据是什么？为什么"做出来了"不等于"应该建设"？
4. 开发启动包含什么？为什么不叫"可上线包"？
5. 责任交接要求什么？为什么交接是责任转移而不是责任消失？

参考要点：原型验证路径和决策，生产系统还需正式架构/安全/数据/测试/运维/责任治理；因为原型用 Mock 数据和模拟行为，缺少安全评审和集成测试等门禁。红线包括不可逆动作/高敏感数据/责任不清判断/难验证任务，因为本课是交接不是解决，让 IT 知道边界比假装解决更重要。四个依据是价值/证据/风险/成本，做出来只证明路径可走，不证明值得投入正式开发。包含已确认事实/证据/缺口/下一步，叫启动包是因为它是 IT 开始设计的输入，不是可上线的交付物。要求每项有 owner，交接是责任从主管转移到 IT 和其他角色，不是没人负责也不是主管全管。

### 拓展题（选做，2 题）

1. 生产就绪缺口有哪些？你的原型离生产上线还差哪些门禁？
2. 能力分级（可演示/可试点/可有限内部使用/可生产上线）四个等级的区别是什么？你的原型目前在哪一级？

### 课后任务

10—15 分钟：在 `PROJECT_STATE.md` 中补齐最终产品决策摘要和 IT 下一步清单。不继续开发功能；本课是训练营终局，不再有下一课。
