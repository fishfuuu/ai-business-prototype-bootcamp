LLM、Tools、Agent 与三类业务原型

理解 LLM 大脑、Tools 手脚与 Agent 执行者的物理区别，行使人在回路 (HITL) 授权，在 127.0.0.1 试衣镜中建立首个受控原型。

🎯 本课目标：① 识别与阐述 LLM/Tools/Agent/ReAct/Workflow 物理区别；② 选择适合部门的三类业务原型 (A/B/C)；③ 行使人在回路 (HITL) 盖章授权；④ 交付绑定 Mock 数据可调度的首个可运行页面。

01 本课背景与底层原理

非技术主管在尝试使用 AI 进行业务原型开发时，最常踩的坑就是在大模型网页聊天框中盲目复制无用代码。网页聊天框只有 LLM 大脑，缺乏物理读写磁盘的 Tools 手脚与 ReAct 自修循环。本课带领大家建立首个 127.0.0.1 本地试衣镜受控工程。

记住核心法则：
大模型 (LLM) 只在内存里推演图纸；真正的读写必须通过受控的工具箱 (Tools)；而人类主管手握公章（人在回路 HITL），随时决定是否授权写盘。

02 💡 本课 7 大核心工程概念卡 (4 步拆解法)

🧠 核心概念 1：LLM (大语言模型 / 大脑)

1. 硬核工程定义基于 Transformer 架构的海量参数概率预测与自然语言推理引擎。
2. 底层运作机制接收 Token 输入，根据注意力机制推演代码方案，物理上无法直接修改磁盘文件。
3. 具象业务比喻建筑工程总工程师 👨‍🔬。坐在办公室里出设计图纸，但不亲自下工地挥水泥铲。
4. IT 沟通场景“LLM 负责需求理解与方案推演，实际文件读写由 Tools 接口执行。”

🛠️ 核心概念 2：Tools (工具调用 / 手脚)

1. 硬核工程定义Agent 客户端与宿主操作系统交互的 API 函数接口与命令行白名单工具集。
2. 底层运作机制提供 `readFile`、`writeFile` 等原子化函数，使 AI 拥有物理读写磁盘与运行终端的能力。
3. 具象业务比喻施工现场的重型机械与工具箱 🚜。包括挖掘机、起重机，是真正把图纸变成建筑物的物理手脚。
4. IT 沟通场景“Agent 必须通过受控的 Tools 工具箱读写磁盘，Tools 的权限受物理沙箱严格限制。”

👷 核心概念 3：Agent (自主循环体 / 执行者)

1. 硬核工程定义以 LLM 为核心决策大脑，具备目标拆解、工具调用与自我修复能力的自主循环系统。
2. 底层运作机制将复杂目标分解为多步 Task，在每次调用 Tools 后评估执行结果，直到达成目标。
3. 具象业务比喻现场施工队长 👷‍♂️。带上图纸（LLM）和机械（Tools），在工地盯盘，遇到积水自动调整施工。
4. IT 沟通场景“我们使用的是 Agent 架构，它能自主感知终端报错并尝试单步修复。”

🔄 核心概念 4：ReAct (推理-行动闭环 / 反馈循环)

1. 硬核工程定义Reasoning and Acting 联合范式 (Thought ➔ Action ➔ Observation) 的三步闭环。
2. 底层运作机制AI 先给出思考推演，接着调用 Tools 执行行动，然后观察终端返回日志，若报错则重新思考调整。
3. 具象业务比喻师傅修水管的看试过程 🔧。看一眼 (Thought) ➔ 拧紧螺丝 (Action) ➔ 看是否漏水 (Observation)。
4. IT 沟通场景“Agent 在 ReAct 闭环中完成了代码的静态编译检查与自修。”

👮 核心概念 5：Workflow (流程门禁 / 安全防护)

1. 硬核工程定义为了防止 Agent 行为跑偏而建立的前置约束条件、状态机流转控制与规则防火墙。
2. 底层运作机制在 Agent 发起物理写操作前匹配预设规则，违规指令直接被系统物理拒绝。
3. 具象业务比喻工地安全监理 👮。即使队长想拆承重墙，安全监理手持规范手册坚决予以物理拦截。
4. IT 沟通场景“Workflow 流程门禁锁定了 Agent 的权限边界，确保未授权目录不会被随意动用。”

✍️ 核心概念 6：人在回路 (HITL / 授权盖章)

1. 硬核工程定义在 Agent 自动化循环的关卡节点上强制挂起，必须等待人类操作员裁决与授权的机制。
2. 底层运作机制当 Agent 准备写代码或更新状态时触发暂停，只有主管在终端输入授权口令后系统才解锁。
3. 具象业务比喻财务付款的双签审批与出纳 U 盾 ✍️。付款前必须由部门主管在 U 盾上按确定键。
4. IT 沟通场景“项目严格执行人在回路 (HITL) 授权，Agent 无法在未经许可的情况下静默修改核心代码。”

🏥 核心概念 7：三类业务原型分类 (Three Business Prototype Classes)

1. 硬核工程定义根据业务交互形态与数据流转特征划分的三种标准原型范式：监控决策型、任务流程型、操作工具型。
2. 底层运作机制A 类以大盘看板为主，B 类以工单状态机为主，C 类以表单计算为主。
3. 具象业务比喻医院的三个核心科室 🏥。ICU 监视屏 (A类)、转诊分诊流水线 (B类)、化验单打印机 (C类)。
4. IT 沟通场景“本期原型确定为 B 类‘任务流程型’工单看板，优先验证流程状态机的完整性。”

Task 1: 唤醒 Agent 创建工单看板页面

你是一个资深的 Web 前端原型工程师。请帮我创建工单处理看板页面 src/views/WorkOrderBoard.vue。

要求如下：
1. 页面标题为“工单处理看板”。
2. 包含顶部状态筛选栏，支持“全部”、“待处理”、“处理中”、“已完成” 4 种状态维度。

注意：本原型定位为 B 类（任务流程型）原型，请确保点击状态筛选按钮时，列表能秒级响应过滤。严禁连接任何外部数据库。
