Lesson 01 · 智能体架构与受控原型

AI Agent 是什么？
从"会聊天"到"会干活"

用一个具体的业务场景——自动构建受控系统原型与排查数据异常，理清模型、工具、循环和 Workflow 的物理区别，彻底搞懂 AI Agent 的底层物理逻辑。

🎯 本课目标：学完你能做到 ① 用工程语言向 IT 部门说出 Agent 与普通聊天机器人的物理区别；② 准确画出“思考 ➔ 行动 ➔ 观察 ➔ HITL盖章”循环；③ 在 90 分钟内跑出第一个受控业务原型雏形。

01 为什么要从这一课开始？

作为业务主管，你掌握 AI Agent 的核心目标是：用自然语言指挥 Agent 帮你快速生成高保真原型，并在无需写底层代码的前提下实现 IT 高效交接。

记住这句话：
Agent 不是更聪明的大语言模型（LLM），而是给大语言模型装上了“手脚和眼睛”（Tools），并嵌入了“工程防错护栏与公章门禁”（Workflow & HITL）。

先想清楚这台“自动化机器”的物理构造，你才能在后续课程中放心指挥它干活，而不必担心它出现白屏、死循环或篡改未授权的代码。

02 核心物理公式：Agent = 模型 + 工具 + 循环

1. 聊天机器人（纯 LLM 应用）

普通的聊天机器人只有单步：你输入 ➔ 模型在内存中预测输出文字 ➔ 结束。模型再聪明，也只会在内存中推演文本，无法直接操作你电脑上的任何文件。

💡 大语言模型的“禁闭室”比喻：
LLM 就像一个被关在无网禁闭室里的极聪明架构师。他懂天底下所有的代码语法和业务逻辑，但他既没有联网，也无法凭空修改你硬盘里的任何文件。你问他“帮我生成个系统”，他只能给你吐出一堆 Markdown 文本，没有手去创建文件。

2. AI Agent 的三大物理组件

🧠 1. 大脑：LLM (大语言模型)

负责理解需求、逻辑推理、决策下一步使用什么工具。它只输出指令，本身没有任何写盘与系统访问句柄。

🛠️ 2. 手脚与眼睛：Tools (工具接口)

宿主程序暴露的可执行函数（如读取文件 read_file、终端运行 run_command）。它们是模型接触真实世界文件的物理媒介。

🔄 3. 反馈与调优：ReAct 循环 (Loop)

Reasoning + Acting。将行动结果 Observation（如命令行报错或编译日志）送回 LLM，引导模型自动调整下一步行动。

🛡️ 4. 物理公章：HITL (人在回路门禁)

在物理写盘或物理修改前中断自动化，强制人类主管进行公章盖章授权，符合企业安全审计红线。

物理控制流程图

用户需求 ➔ Thought (思考) ➔ Action (工具调用) ➔ Observation (观察返回) ➔ HITL 盖章确认 ➔ 127.0.0.1 试衣镜渲染

反复循环，直到目标完成、单元测试 [PASS]，或拿到试衣镜预期效果。

观察重点：
  1. 基础问候不需要调用 Tools，直接在内存中生成回复；
  2. 业务原型需求触发了真正的 Tool Call（写文件、创组件），并在写盘前触发了 HITL (主管公章盖章)；

04 三类业务原型选型（选择你的战场）

在开始制作前，请评估你的业务问题属于哪一类。点击下方卡片查看推荐的落地组件组合：

A. 监控与决策型

经营分析、履约预警、指标监控。
核心：看指标 ➔ 看异常 ➔ 下钻明细。

B. 任务与流程型

预算审批、退货处理、工单派发。

C. 操作工具型

文案生成、数据清洗、规则计算。
核心：参数输入 ➔ 规则处理 ➔ 导出/复制。

05 测验：检验你的 Agent 心智模型

5 道题，答完立即知道正误与深度解析。暴露误区是掌握工程护栏的最佳方式：

Q1 · 一个只能对话、不能调用任何本地工具的 LLM 应用（如普通网页版 ChatGPT），算 AI Agent 吗？
Q2 · Agent 物理写盘修改代码前，Workflow 要求人类主管确认，这在工程设计中叫什么？
Q3 · 当 Agent 运行 `run_command` 尝试构建页面时，终端返回了错误日志 `Cannot find module 'vue'`，Agent 在 ReAct 循环中接下来会做什么？
Q4 · 为什么在制作业务原型时，必须恪守“模拟数据红线 (Mock Data Line)”？
Q5 · 业务主管在 Agent 协作原型制作中的核心身份定位是什么？

06 本课小结 + 知识扩充 + 下一步

三句话带走 (Key Takeaways)：
  1. AI Agent = 模型（大脑）+ 工具（手脚）+ 循环（流程）+ HITL（公章门禁）。
  2. ReAct 循环 = 思考 ➔ 行动 ➔ 观察 ➔ 盖章，反复迭代直到完成；“观察 Observation”让 Agent 用真实编译与日志数据说话，不凭空捏造。
  3. 能固定的常规任务用自动化脚本，需要灵活决策与原型制作的任务才用 Agent。
