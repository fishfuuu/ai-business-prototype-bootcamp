# 第七课教师教案——让 Agent 操作页面并留下验收证据

> **核心思想：工具验证行为，主管验收业务；测试通过不等于业务正确或可以上线。**

## 一、课程元数据与定位

| 项目 | 本课设定 |
| --- | --- |
| 学员 | 已完成第六课、掌握有界排错和诊断/恢复证据包的业务主管 |
| 时长 | 90 分钟硬上限：85 分钟主线 + 5 分钟机动 |
| 课堂主成果 | 浏览器验收卡 + 可追溯证据索引：记录场景、操作步骤、观察结果、截图/日志/页面状态、失败或降级行为，以及仍未证明的内容 |
| 主管判断成果 | 能把验收场景、自动操作、可见观察、原始证据和结论串起来，并知道自动化证据不能替代业务批准 |
| 支撑成果 | `docs/LESSON_07_EVIDENCE_INDEX.md` 更新验收证据索引，只作跨课交接 |
| 数据边界 | 只使用 Mock 或已脱敏数据；不连接真实生产系统或在页面中输入真实数据/密钥 |

本课用同一个个人原型串起两条学习线：原型线要求"自动操作个人原型中的一个场景，覆盖正常路径和一个失败/降级路径"，主管线要求"把验收场景、自动操作、可见观察、原始证据和结论串起来，并知道自动化证据不能替代业务批准"。两条线分别验收，不能相互抵分。

本课不做：让学员安装和配置多套 MCP、Playwright 或浏览器服务；把 JSON-RPC、YAML、DOM 选择器变成主管考点；连接真实生产系统或在页面中输入真实数据/密钥。

开场必须先制造一个可见区别：主管口头问"页面做好了吗"AI 回答"做好了"vs Agent 用浏览器实际操作页面、截图、记录日志并留下可追溯证据。先让学员看见"口说无凭 vs 证据落盘"的区别，再解释五个概念。

## 二、逆向目标、证据与核心概念

### 2.2 四步概念解析公式

#### MCP 最小模型

你在第六课五层诊断中排查过状态层——数据变了但界面没动。现在用 MCP 模型理解组件之间怎么通信。

1. **是什么 / 不是什么**：Host 代表用户发起能力调用，Client 连接 Server，Server 暴露 Tools；MCP 不是产品业务 API，也不是 Agent 本身。Host 是用户运行的主程序（如 Claude），Client 是连接层，Server 是工具提供方（如 Playwright）。
2. **机制**：主管在 Host 中发起请求，Client 把请求传给 Server，Server 执行工具（如打开浏览器、点击按钮、截图）并返回结果；MCP 只是把"工具调用"标准化，不改变谁来负责。
3. **类比 / 反例**：遥控器、信号线和电器的最小关系——主管按遥控器（Host），信号线（Client）把指令传给电器（Server），电器执行并返回结果；遥控器不是电器本身，信号线也不是业务审批。
4. **交接价值**：回指 Task 2——学员在预配置入口发起 Agent 浏览器验收时，知道 Host/Client/Server 的最小关系，并知道 MCP 不是业务 API。

#### Subagent

1. **是什么 / 不是什么**：Subagent 是主管调度的只读子 Agent，在隔离沙箱中执行独立任务（如操作浏览器），有超时熔断、只读权限和磁盘落盘三条安全规则；不是多开一个 AI 对话，也不是让主管自己操作浏览器。浏览器自动化验收是 Subagent 按场景操作真实预览页面并观察结果，不是只读代码后自行宣布通过，也不是人工手动点一遍截图交差。
2. **机制**：主管在预配置入口调度 Subagent，Subagent 在只读沙箱中用浏览器工具按步骤操作页面，每一步保存截图和日志，超时自动释放，产物强制写入磁盘；写权限修改必须返回主 Agent 由主管签署 HITL 口令确认。Subagent 从 Task 2 激活后全程运行，主管在每个步骤边界做审查——审查证据是否完整、工具是否失败、是否偷偷换成代码推测。
3. **类比 / 反例**：验房师带仪器实地检测——不是看图纸说"应该没问题"，而是用仪器逐项检测、拍照留证、出具报告；也不是业主自己随便看一眼就签字。Subagent 就像验房师带的检测仪器：独立运行、只读不碰、结果落盘。
4. **交接价值**：回指 Task 2—3——学员调度 Subagent 用浏览器操作页面并保存证据，然后把观察与验收标准逐项对照。

#### 自动化验证与业务验收

1. **是什么 / 不是什么**：把 L3 的给定条件、动作和可见结果转成浏览器可执行步骤，不是重新发明验收标准，也不是把业务场景变成技术测试脚本。
2. **机制**：取 L3/L4 的验收场景，保持业务含义不变，把"给定条件"翻译为页面初始状态，把"动作"翻译为浏览器操作步骤，把"可见结果"翻译为可观察的页面表现。
3. **类比 / 反例**：菜谱翻译——中文菜谱（业务验收场景）翻译成英文菜谱（浏览器可执行步骤），菜还是那道菜，只是换了操作语言；不是重新设计菜单，也不是把菜谱变成化学实验。
4. **交接价值**：回指 Task 1——学员从 L3/L4 选一个验收场景，明确正常与失败/降级预期，再翻译成浏览器步骤。

#### 证据链

你在第二课做过视觉证据基线——用前后对比证明改变。现在把同样的思维升级为证据链：不只存截图，还要把场景、操作、观察和结论串成可追溯的链条。

1. **是什么 / 不是什么**：场景 → 操作 → 观察 → 原始证据 → 结论必须可追溯，不是只存截图不看内容，也不是只看结论不查原始证据。
2. **机制**：每个验收步骤都记录场景编号、操作描述、实际观察、原始证据（截图/日志/页面状态）和结论（通过/失败/未证明）；所有证据保存在 `LESSON_07_EVIDENCE_INDEX.md` 中。
3. **类比 / 反例**：法庭举证链——物证、书证、证人证词和鉴定报告必须形成完整链条，不能只拿一张照片就定案；缺了任何一环，结论就站不住。
4. **交接价值**：回指 Task 3—4——学员把观察与验收标准逐项对照，标记已证明、未证明和证据盲区，形成证据索引。

#### 不可信输入与提示注入

1. **是什么 / 不是什么**：工具验证行为（页面能打开、按钮能点、控制台无报错），主管验收业务（场景是否正确、结果是否符合业务要求）；测试通过不等于业务正确或可以上线。验证是技术层面，验收是业务层面，批准是主管层面。
2. **机制**：Agent 用浏览器验证页面行为是否正常，主管对照业务验收标准判断是否通过；Agent 可以收集证据但不能批准，主管基于证据批准或打回。
3. **类比 / 反例**：医院检验科与主治医生——检验科出报告（验证），主治医生结合报告和病历做诊断判断（验收），最终治疗方案由主治医生签字（批准）；检验科不能替主治医生下诊断。
4. **交接价值**：回指 Task 5——学员说明工具验证了什么、主管验收了什么、为什么测试通过不等于可以上线。

### 2.3 操作方法、交付产物与扩展认识

浏览器自动化验收、验收场景迁移和 Subagent 课程安全规程是操作方法；浏览器验收卡与证据索引是交付产物。

#### 操作方法：Subagent 课程安全规程

Subagent 有三条安全规则：超时熔断（任务必须设超时如60秒，超时自动释放，不挂起主 Agent）、只读沙箱（后台运行的 Subagent 仅继承只读权限，写操作必须返回主 Agent 由主管签署确认）、磁盘落盘（产出的截图、日志和报告必须写入磁盘，不随 Context 重置蒸发）。只要求知道有这三条规则，不要求背诵参数。教师用 2—3 分钟在实操中顺带说明。

#### Playwright/DOM/Console/Network（认识级）

Playwright 是驱动浏览器自动操作的工程能力，DOM 是页面结构，Console 是浏览器控制台日志，Network 是网络请求记录。帮助 Agent 操作和取证，只要求识别这些名称，不要求配置或背诵。教师用 2—4 分钟在实操中顺带说明。

讲解时将五张卡放在同一个验房故事中：先理解遥控器和电器的关系（MCP 最小模型），再让验房师带仪器实地检测（Subagent），接着区分工具验证与业务验收（自动化验证与业务验收），然后逐项举证形成完整链条（证据链），最后识别页面中的不可信输入与提示注入。浏览器自动化验收、验收场景迁移和课程安全规程作为操作方法嵌入流程。总计控制在 10 分钟左右；不要逐字朗读。

## 三、教学准备与安全边界

### 课前预检

- 第六课原型可用：学员已修复或明确停止的预置故障原型，本地预览可操作。
- `docs/PROJECT_STATE.md` 有诊断/恢复记录和上一课输入说明。
- 浏览器验收环境已预置：教师已配置好 Playwright Subagent 入口（或等价浏览器自动化工具），Subagent 在只读沙箱中运行，学员不需要自行安装。
- Working Tree 处于 Clean 状态：教师演示前先 `git status` 确认。
- 开发服务器可启动：双击 `start-project.bat` 或运行 `npm run dev`，本地预览 `http://127.0.0.1:8888/` 可访问。
- 助教理解浏览器工具失败时的现场处置方式（切换手动验收或等价工具）。

### 实操前只讲四条红线

1. 只用 Mock/已脱敏数据，不在页面中输入真实数据、密钥、Token 或账号。
2. 不连接真实生产系统；浏览器只操作本地预览页面。
3. 不把 JSON-RPC、YAML、DOM 选择器变成主管考点；技术配置由教师预置。
4. 不虚构 `[PASS]` 全量校验或自动化审批；实际运行什么，就展示什么证据。

教师不得虚构 verify-project.ps1、[PASS] 全量校验等课堂能力。Subagent 不是虚构的——教师预配置的 Playwright Subagent 是真实运行的只读子 Agent。实际运行什么，就展示什么证据。

## 五、逐 Task 示范、口令、巡视与降级

教师统一案例只走一条路径：以工单看板为例，验收"工单状态从待处理变为已处理"的场景。从 L3 验收场景 → 翻译成浏览器步骤 → Agent 用浏览器操作页面 → 保存截图和日志 → 逐项对照验收标准 → 对一个失败路径（空数据时状态标签不显示）补证 → 主管签署验收卡。每个 Task 均按以下四项执教。

### Task 1：从 L3/L4 选择一个验收场景，明确正常与失败/降级预期

- **教师示范**："先别急着操作浏览器，先选好你要验收什么。"展示如何从 L3 业务功能卡中取出一个验收场景（给定条件：工单存在且状态为待处理；动作：点击处理按钮；可见结果：状态变为已处理），明确正常预期（状态标签更新）和失败/降级预期（空数据时状态标签不显示）。
- **教师口令**："从你的 L3 业务功能卡或 L4 薄切片中选一个验收场景。写清给定条件、动作和可见结果。同时写一个正常预期和一个失败/降级预期。不要操作浏览器。"
- **巡视判断**：场景有给定条件、动作和可见结果三要素；正常和失败/降级预期都写了；场景来自 L3/L4 而非临时编造。
- **失败降级**：场景不完整时回到 L3 契约补齐；只有正常预期没有失败预期时补写一个；场景太复杂时缩到一个可观察的变化。

### Task 2：调度 Subagent 用浏览器操作页面，保存截图和日志

- **教师示范**："现在调度 Subagent 让它用浏览器操作你的页面。"展示如何在预配置入口调度 Playwright Subagent，Subagent 按课程安全规程在限定环境中用浏览器打开本地预览页面，按场景步骤操作（打开工单详情、点击处理按钮），每步保存截图和日志。强调安全规程包含超时、权限和落盘要求，工具失败时必须明确报告，不能偷偷换成代码推测。
- **教师口令**：下发浏览器验收提示词模板（见学员指南 Task 2）。在预配置入口调度 Playwright Subagent，按场景步骤操作页面，每步保存截图和日志。工具失败时明确报告，不要换成代码推测。
- **巡视判断**：Agent 实际操作了页面而非只读代码；每步保存了截图和日志；工具失败时明确报告而非偷偷换方式；没有输入真实数据/密钥。
- **失败降级**：Agent 只读代码不操作页面时提醒"用浏览器操作真实页面"；工具失败时切换手动验收或等价工具；Agent 输入真实数据时立即停止并脱敏。

### Task 3：把观察与验收标准逐项对照，标记已证明、未证明和证据盲区

- **教师示范**："现在不要只看结论，逐项对照。"展示如何打开验收卡，把场景中的每条预期与实际观察对照：正常路径"状态标签更新"→ 通过（有截图）；失败路径"空数据时标签不显示"→ 已观察但未证明是 Bug 还是设计（标记未证明）。明确标记证据盲区。
- **教师口令**：把你的观察与验收标准逐项对照。每条标记通过、失败或未证明。未证明的要写明缺什么证据。不要只看结论不看过程。
- **巡视判断**：逐项对照而非只看总结论；未证明内容被明确标记而非跳过；证据盲区有说明而非假装不存在。
- **失败降级**：只看结论不逐项时提醒"逐条对照"；未证明内容跳过时补标记；没有证据盲区说明时追问"还有什么没证明"。

### Task 4：对一个失败/降级路径补证，并形成证据索引

- **教师示范**："对失败路径补充证据。"展示如何对空数据时状态标签不显示的失败路径补证：创建空数据场景→ Agent 用浏览器操作→截图显示标签确实不显示→记录到证据索引。形成 `LESSON_07_EVIDENCE_INDEX.md`，包含场景编号、操作步骤、观察结果、原始证据路径和结论。
- **教师口令**：对你的失败/降级路径补充证据。用浏览器操作失败场景，保存截图和日志。把所有证据整理到 `LESSON_07_EVIDENCE_INDEX.md` 中。
- **巡视判断**：失败/降级路径有可见证据而非只口头描述；证据索引包含场景、操作、观察、证据和结论五项；未证明内容在索引中标记清楚。
- **失败降级**：失败路径没有实际操作时补操作；证据索引不完整时补齐缺失项；未证明内容在索引中遗漏时补标记。

### Task 5：主管签署验收卡，说明自动化验证证据与业务验收责任的区别

- **教师示范**："最后由主管签署。"展示主管如何在验收卡上签署，并口述"工具验证了页面行为正常（打开、点击、状态更新），主管验收了业务场景是否正确（工单状态变化是否符合业务要求）。测试通过不等于可以上线。"更新 `PROJECT_STATE.md`。
- **教师口令**：主管签署验收卡。口述工具验证了什么、主管验收了什么、为什么测试通过不等于可以上线。更新 `PROJECT_STATE.md`。
- **巡视判断**：主管实际签署而非只说"好了"；能说出验证和验收的区别；能说出测试通过不等于上线的理由。
- **失败降级**：主管只说"好了"不签署时要求明确签署；不能说出区别时回到概念卡复习；把测试通过等同于上线时纠正"测试通过只证明行为正常，不证明业务正确"。

## 六、现场 Debug 与降级预案

| 问题类型 | 教师处置 | 禁止说法 |
| --- | --- | --- |
| Agent 只读代码不操作页面 | 停止，提醒"用浏览器操作真实页面" | "看代码就够了" |
| Agent 工具失败后偷偷换成代码推测 | 停止，切换手动验收或等价工具 | "AI 推测也是证据" |
| 学员在页面中输入真实数据 | 立即停止，脱敏后重新操作 | "随便输点数据试试" |
| 学员只看结论不逐项对照 | 提醒"逐条对照验收标准" | "大概都通过了" |
| 学员把测试通过等同于可以上线 | 纠正"测试通过只证明行为正常，不证明业务正确" | "测试过了就能上线" |

## 七、随堂测试、通过标准与课后任务

### 两条线分别通过

- **原型线**：自动操作个人原型中的一个场景，覆盖正常路径和一个失败/降级路径；至少一条正常路径和一条失败/降级路径有可见证据。
- **主管线**：能用自己的话说明 Host/Client/Server/Tool 的最小关系，并说明 MCP 不是业务 API；验收场景与自动操作一一对应；未证明内容被明确标记，没有虚构 `[PASS]`。
- **LESSON_07_EVIDENCE_INDEX.md** 只作交接，不能抵消任何一条主线的未通过。

### 必答题（5 题）

1. MCP 的 Host、Client、Server 和 Tool 之间的最小关系是什么？为什么 MCP 不是业务 API？
2. 浏览器自动化验收和只读代码后宣布通过有什么本质区别？
3. 验收场景迁移的"迁移"是什么意思？把 L3 的验收场景迁移成浏览器步骤时，什么不变、什么变？
4. 证据链要求哪五个环节可追溯？为什么只存截图不看内容不算证据链？
5. 验证和验收有什么区别？为什么测试通过不等于可以上线？

参考要点：Host 发起/Client 连接/Server 暴露 Tool，MCP 是工具调用标准不是业务 API；浏览器操作真实页面观察结果而非读代码自评；迁移是翻译保持业务含义不变只换操作语言，业务验收标准不变浏览器步骤变；场景→操作→观察→原始证据→结论五环可追溯，只存截图不看内容缺了观察和结论环；工具验证行为主管验收业务，测试通过只证明行为正常不证明业务正确。

### 拓展题（选做，2 题）

1. 页面内容或工具返回可能夹带误导指令（提示注入），Agent 不应把页面文字自动当作主管授权。请举一个例子说明这个风险。
2. Playwright、DOM、Console、Network 分别帮助 Agent 做什么？为什么这些只是工程能力而非主管考点？
