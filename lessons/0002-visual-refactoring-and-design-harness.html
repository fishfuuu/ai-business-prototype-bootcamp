01 为什么要解决“一股 AI 味”？

很多业务主管在使用 Agent 生成页面时，常遇到以下痛点：

典型的“AI 生成白屏/山寨页面”三硬伤：
1. 颜色乱用：高饱和度的死亡红蓝绿撞色，毫无专业企业质感；
2. 字号层级混乱：标题、正文、标签字号没有系统缩放规律；
3. 布局五花八门：单页每次重新生成都会“基因突变”，无法保持团队视觉统一。

💡 解药：视觉 Harness (`DESIGN.md`)
Agent 是大概率预测模型，你不给它视觉轨道，它就会凭空乱编。`DESIGN.md` 就是你给 Agent 建立的物理视觉护栏字典。你要求它物理点开该字典，映射颜色与组件，界面瞬间就能达到专业 UI 设计师水准。

02 双 Token 物理制衡机制

🎲 1. AI Token (概率随机性)

大模型在内存中采样预测的下一个 Token。如果不加约束，它的审美随机波动极高，容易产生 ad-hoc 杂色内联样式。

🛡️ 2. Design Token (物理规范锚定)

在 DESIGN.md 中定义的标准化设计字典（如主色 var(--primary)、字号层级、卡片圆角 var(--radius-md)）。

制衡公式：物理点开 DESIGN.md ➔ 映射 Design Token ➔ 强制清除内联杂色 ➔ 保持架构视觉连续性

04 实战 4 步工作流 (4-Step Workflow)

Task 1: 视觉参考图多模态结构提取 (15 分钟)

提供一张标杆企业看板参考图，提示 Agent 提取首屏布局与视觉主次，100% 过滤掉参考图中的无关广告与非规范杂色。

Task 2: 规范映射——物理点开 `DESIGN.md` (15 分钟)

要求 Agent 发起 read_file 工具，物理点开 DESIGN.md 查字典，将组件和样式准确映射到 Design Tokens。

Task 3: Git 节点 1 存档与视觉裁决 (10 分钟)

修改前先运行 git commit -m "baseline: complete lesson 1 prototype" 保存节点 1 游戏存档。
主管审查试衣镜，下达 Keep (保留) / Omit (省去) / Remove (移除) / Modify (修改) 4 种裁决指令。

Task 4: 对比验证与 Git 节点 2 存档 (10 分钟)

在试衣镜完成微调，运行 verify-student-project.ps1 确认 `[PASS]`，提交 节点 2 Git 存档 `style: complete lesson 2 visual refactor`。
