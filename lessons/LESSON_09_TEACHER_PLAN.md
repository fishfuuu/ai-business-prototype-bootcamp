# 第九课教师教案——画出部门 AI 机会与 Agent 范式选型图

> **核心思想：不是"我的部门能不能用 Agent"，而是逐环节判断任务性质、可验证性、风险和合适范式。**

## 一、课程元数据与定位

| 项目 | 本课设定 |
| --- | --- |
| 学员 | 已完成前八课、拥有经独立评审的候选原型和证据的业务主管 |
| 时长 | 90 分钟硬上限：85 分钟主线 + 5 分钟机动 |
| 课堂主成果 | 部门 AI 机会与 Agent 范式选型图：逐环节记录当前动作、输入、任务性质、可验证性、错误代价、数据风险、工具需求、AI 介入层级、Agent 范式、HITL、停止条件和责任人 |
| 主管判断成果 | 形成部门 AI 机会地图，能够拒绝不需要 AI 或不应自动化的环节，并为值得验证的环节选择范式 |
| 支撑成果 | `docs/PROJECT_STATE.md` 更新选型图摘要和优先候选，只作跨课交接 |
| 数据边界 | 只使用 Mock 或已脱敏数据；不写真实接口接入代码，不向学员发放 Key |

本课用同一个个人原型串起两条学习线：原型线要求"把当前原型中的智能薄片放回完整业务流程，补充来源、失败显性化和责任边界"，主管线要求"形成部门 AI 机会地图，逐环节选 AI 介入层级、范式、工具、证据和责任"。两条线分别验收，不能相互抵分。

本课不做：写真实接口接入代码、向学员发放 Key、把所有概率任务自动判成 Agent、把多 Agent 当成熟度象征。

开场必须先制造一个可见区别：泛泛问"我的部门能不能用 Agent"得到一堆空泛建议 vs 逐环节判断任务性质、可验证性和风险后画出选型图。先让学员看见"泛泛而谈 vs 逐环节判断"的区别，再解释五个概念。

**累积锚点**：你已经从 L5 到 L8 积累了四种判断——L5 判断哪个环节不用 AI、L6 判断什么时候停止和升级、L7 判断验证和验收的区别、L8 判断 accept/fix/stop/defer。现在把这些判断扩展到整个部门流程，不是学新技能，而是把已有判断规模化应用。

## 二、逆向目标、证据与核心概念

### 2.1 目标—活动—证据

| 学习目标 | 课堂活动 | 通过证据 |
| --- | --- | --- |
| 学员能画出部门一条真实业务流程，拆成具体人工/系统动作 | Task 1 流程拆解 | 一条完整业务流程拆成具体动作，每个有输入和输出 |

概念分层：核心概念为 AI 机会地图、AI 介入层级迁移、Agent 范式选型、三链区分、Fallback 来源与失败责任；扩展认识为自动化红线预览、多 Agent 的必要条件。PROJECT_STATE.md、选型图模板在实操中使用但不升级为核心概念。安全红线横向管理，不占概念名额。

### 2.2 四步概念解析公式

#### AI 机会地图

1. **是什么 / 不是什么**：以真实业务流程节点为单位判断 AI 机会，不以"部门想用 AI"为单位；不是从"AI 能做什么"出发，而是从"这个环节需要什么"出发。
2. **机制**：画出部门一条真实业务流程，拆成具体动作，逐个判断任务性质、可验证性、错误代价和数据风险；只有满足条件的动作才进入 AI 候选，不满足的明确拒绝。
3. **类比 / 反例**：城市交通规划——不是先买公交车再找路线，而是先看每条路的客流需求，再决定哪条线适合公交、哪条适合地铁、哪条走路就行；不能每条路都配公交。
4. **交接价值**：回指 Task 1—2——学员画出部门业务流程并逐环节评估时，已经在做 AI 机会地图的基础工作。

#### AI 介入层级迁移

1. **是什么 / 不是什么**：不用 AI、辅助、建议、单步执行、受控 Agent 和受控闭环必须按风险与价值选择；不是从 L5 的单点初筛直接跳到部门全面 AI 化，而是把 L5 的方法迁移到每个环节。
2. **机制**：对每个环节判断——能用规则的不用 AI（不用 AI），需要建议但不自动执行（辅助），需要生成但不直接修改（建议），需要单步执行（单步），需要多步调查（受控 Agent），需要闭环但低风险（受控闭环）。
3. **类比 / 反例**：工厂自动化程度迁移——L5 是在一个工序上试自动化，L9 是把所有工序排开逐个判断自动化程度；不是所有工序都配最高自动化，有些工序人工更好。
4. **交接价值**：回指 Task 3——学员对每个环节选择 AI 介入层级，明确拒绝 AI/Agent 的环节及理由。

#### Agent 范式选型

1. **是什么 / 不是什么**：在 Prompt、Skill、Workflow、ReAct、增量实施范式（Plan & Execute）、Routing、Evaluator-Optimizer、多 Agent 等方式中选择最简单足够者；不是越多范式越好，也不是多 Agent 就是高级。
2. **机制**：判断路径是否预先确定（是则用 Workflow），是否需要动态调查（是则用 ReAct），是否需要先规划再执行（是则用 增量实施范式（Plan & Execute）），是否需要评估优化（是则用 Evaluator-Optimizer）；单 Agent 足够时不拆多 Agent。
3. **类比 / 反例**：工具箱选工具——锤子适合钉钉子，螺丝刀适合拧螺丝，不是每件工具都要用上，也不是越复杂的工具越好；选最简单足够的。
4. **交接价值**：回指 Task 4——学员对保留候选选择范式，补数据、工具、HITL 和停止条件。

#### 三链区分

你在第八课学了上下文隔离——评审者和实现者不能混在同一个上下文里。现在把同样的思维扩展到三条链：开发工具、业务 API 和模型 API 也不能混为一谈。

1. **是什么 / 不是什么**：区分开发工具链、产品业务 API 链和模型 API 链中的对象、凭证、数据与责任；MCP 不等于业务 API，开发工具也不等于产品能力。三链不能混为一谈。
2. **机制**：开发工具链是 Claude/Codex/Playwright 等帮助开发的工具；产品业务 API 链是产品运行时调用的业务接口；模型 API 链是产品运行时调用的 AI 模型接口。三链中的对象、凭证、数据和责任分别归属不同 owner。
3. **类比 / 反例**：建筑工地三条供应链——施工设备链（开发工具）、建材供应链（业务 API）、设计咨询链（模型 API）；三种链的供应商、合同和责任完全不同，不能混在一起管。
4. **交接价值**：回指 Task 5——学员画三链责任与 fallback，明确每条链的 owner。

#### Fallback 来源与失败责任

1. **是什么 / 不是什么**：降级结果必须显示来源、原因、限制和 owner，不能把 Mock/缓存结果伪装成真实成功；失败时必须有明确的责任人，不是"AI 出错了所以 AI 负责"。
2. **机制**：对每个 AI 候选环节写明降级方式（人工接管、规则降级、缓存回退）、降级来源标签（模拟/缓存/人工）、降级原因类型和失败责任人；降级结果不能冒充正常结果。
3. **类比 / 反例**：航空公司备降——航班因天气备降其他机场时，必须告知旅客"备降原因、预计延误、替代方案"，不能假装"已到达目的地"；也不是"天气不好所以没人负责"。
4. **交接价值**：回指 Task 5——学员画三链责任与 fallback，选出一个优先候选和一个明确不做项。

### 2.3 扩展认识概念卡

#### 自动化红线预览（认识级）

不可逆、高敏感、责任不清和难验证事项默认不进入自主执行。例如删除操作、资金转账、人事决定等不可逆动作，涉及个人隐私的高敏感数据，责任归属不清的模糊判断，以及结果难以验证的开放任务。教师用 2—4 分钟展示红线清单，不展开。

#### 多 Agent 的必要条件（认识级）

单 Agent 足够时不拆多 Agent；只有专业分工、并行或独立性确有价值时才采用。多 Agent 不是成熟度象征，而是复杂度响应。教师用 2 分钟说明，不展开。

讲解时将五张卡放在同一个城市交通规划故事中：先画路网看每条路的客流需求（AI 机会地图），再逐条路选交通方式档次（AI 介入层级迁移），接着选具体交通工具（Agent 范式选型），然后区分三条供应链（三链区分），最后说明备降方案和责任（Fallback 来源与失败责任）。总计控制在 10 分钟左右；不要逐字朗读。

## 三、教学准备与安全边界

### 课前预检

- 前八课原型和证据可用：学员有经独立评审的候选原型。
- `docs/PROJECT_STATE.md` 有独立评审记录和上一课输入说明。
- 学员能说出自己的部门一条真实业务流程（课前可提前想好）。
- Working Tree 处于 Clean 状态：教师演示前先 `git status` 确认。
- 助教理解学员对部门流程不熟悉时的引导方式（帮助拆解而非代判断）。

### 实操前只讲四条红线

1. 不写真实接口接入代码，不向学员发放 Key；选型图只记录需求和方案，不实施。
2. 不把所有概率任务自动判成 Agent；逐环节判断最简单足够的方式。
3. 不把多 Agent 当成熟度象征；单 Agent 足够时不拆。
4. 不把 Mock/缓存结果伪装成真实成功；降级结果必须标记来源。

教师不得虚构 verify-project.ps1、[PASS] 全量校验等课堂能力。实际运行什么，就展示什么证据。

## 四、90 分钟控场主线

| 时间 | 宏观阶段 | 教师动作 | 学员动作 | 阶段证据 |
| --- | --- | --- | --- | --- |
| 0—10 分 | **看见区别，建立模型** | 对比"泛泛问部门能不能用 Agent"vs"逐环节判断画选型图"；用城市规划比喻和融合图讲五个概念 | 回顾前八课，能说出自己的部门一条业务流程 | 知道本课成果与五者关系 |
| 10—25 分 | **教师完整示范** | 用统一案例串演 Task 1—5，只演方法，不让学员复现 | 观察"拆流程→逐环节评估→选层级→选范式→画三链"的完整动作 | 建立整体动作锚点 |
| 25—35 分 | **概念核对与准备** | 提问核对五张概念卡；确认学员想好了一条部门业务流程 | 口头回答卡片；完成流程准备 | 概念理解和流程就绪 |
| 35—80 分 | **学员实操** | 按 Task 1（约 8 分）→ Task 2（约 12 分）→ Task 3（约 8 分）→ Task 4（约 10 分）→ Task 5（约 7 分）巡视 | 完成流程拆解、逐环节评估、层级选择、范式选型和三链决策 | 部门 AI 机会与选型图 |
| 80—90 分 | **验收与闭合** | 指导主管验收选型图；检查通过证据；收取随堂题 | 主管验收、核对选型图完整性、核对答案 | 原型线和主管线分别判定 |

压缩顺序：先取消个别展示，再压缩教师示范；不得删除逐环节评估、范式选型或三链决策。5 道必答题分散在相应 Task 后完成，最后只检查提交。

## 五、逐 Task 示范、口令、巡视与降级

教师统一案例只走一条路径：以仓储管理为例，画出"收货→质检→上架→拣货→发货"的业务流程，逐环节判断 AI 机会。从拆流程 → 逐环节评估 → 选层级 → 选范式 → 画三链和 fallback。每个 Task 均按以下四项执教。

### Task 1：画出部门一条真实业务流程，拆成具体人工/系统动作

- **教师示范**："先把你的部门一条真实业务流程画出来。"展示如何画"收货→质检→上架→拣货→发货"流程，拆成具体动作（如"质检"拆成"检查外观→记录缺陷→决定是否合格"），每个动作标注输入和输出。
- **教师口令**："画出你部门的一条真实业务流程，拆成 6—10 个具体人工/系统动作。每个动作写清输入是什么、输出是什么、当前谁在做。不要想 AI，先画现状。"
- **巡视判断**：流程是一条完整的业务路径而非碎片；拆成了具体动作而非笼统环节；每个动作有输入和输出；没有开始想 AI。
- **失败降级**：流程不完整时帮助补齐；动作太笼统时拆细；只有环节没有输入输出时补写。

### Task 2：对每个动作记录输入、判断性质、可验证性、错误代价和数据风险

- **教师示范**："现在逐环节评估。"展示如何对"质检"动作评估：输入是商品外观和规格，任务性质是概率性（需要判断瑕疵），可验证性是中等（有标准但主观），错误代价是中等（漏检可能流入客户），数据风险是低（不涉及敏感数据）。
- **教师口令**：下发逐环节评估提示词模板（见学员指南 Task 2）。对每个动作记录输入、任务性质（确定性/概率性）、可验证性、错误代价和数据风险。
- **巡视判断**：每个动作有五项评估；任务性质区分了确定性和概率性；不只标"适合 AI"。
- **失败降级**：只标"适合 AI"时要求补五项；任务性质没有区分确定性和概率性时回指 L5 概念；可验证性太笼统时具体化。

### Task 3：选择 AI 介入层级，明确拒绝 AI/Agent 的环节及理由

- **教师示范**："逐环节选层级。"展示如何对"检查外观"选不用 AI（规则可判断），"记录缺陷"选 AI 辅助（语音转文字），"决定是否合格"选人工判断（责任重大），"拣货路径优化"选受控 Agent（多步调查）。明确拒绝"决定是否合格"用 AI 的理由。
- **教师口令**：对每个动作选择 AI 介入层级。明确写出拒绝 AI/Agent 的环节及理由。至少有一个"不使用 AI/Agent"的决定，拒绝理由引用你自己部门的具体业务约束，不是泛化套用教师案例的模式。
- **巡视判断**：有至少一个"不使用 AI/Agent"的决定，拒绝理由引用学员自己部门的至少一个具体业务约束（如特定风险、责任归属、法规要求或操作约束），不是泛化套用教师案例的模式；不是所有环节都选了 AI；拒绝理由基于任务性质和风险。
- **失败降级**：所有环节都选 AI 时追问"有没有能用规则的"；没有拒绝理由时补写；拒绝理由不基于风险时改写；拒绝理由只复述教师案例的泛化模式（如"责任重大所以不用 AI"）时，追问"你自己部门的具体风险或约束是什么——能用一个真实场景说明吗"。

### Task 4：对保留候选选择范式，补数据、工具、HITL 和停止条件

- **教师示范**："对选了 AI 的环节选范式。"展示如何对"拣货路径优化"选 ReAct（需要根据中间结果调整路线），补数据（仓库布局图）、工具（路径计算 API）、HITL（主管确认路径后执行）、停止条件（计算超过 3 轮或路径不可达时停止）。
- **教师口令**：下发范式选型提示词模板（见学员指南 Task 4）。对保留候选选择范式，补数据、工具、HITL、停止条件和 owner。
- **巡视判断**：选型说明了数据、工具、证据、HITL、停止和 owner；范式与任务性质匹配；单 Agent 足够时没有拆多 Agent。
- **失败降级**：范式与任务不匹配时回指 L5 概念；缺少 HITL/停止条件时补写；不必要拆多 Agent 时缩回单 Agent。

### Task 5：画三链责任与 fallback，选出一个优先候选和一个明确不做项

- **教师示范**："最后画三链和决策。"展示如何画三链（开发工具链：Claude/Playwright；业务 API 链：仓储系统接口；模型 API 链：AI 模型接口），标注每条链的 owner。对"拣货路径优化"写 fallback（Agent 失败时降为人工指派，来源标记"人工降级"）。选一个优先候选（拣货路径优化）和一个明确不做项（决定是否合格不用 AI）。
- **教师口令**：画三链责任与 fallback。选出一个优先候选和一个明确不做项，回写原型产品决策。更新 `PROJECT_STATE.md`。
- **巡视判断**：三链对象与凭证责任没有混淆；fallback 不伪装真实结果；有优先候选和明确不做项；决策回写了产品决策。
- **失败降级**：三链混淆时分开记录；fallback 缺来源标记时补写；没有明确不做项时补一个。

## 六、现场 Debug 与降级预案

| 问题类型 | 教师处置 | 禁止说法 |
| --- | --- | --- |
| 学员对所有环节都选了 AI | 追问"有没有能用规则解决的" | "部门全流程都可以用 AI" |

## 七、随堂测试、通过标准与课后任务

### 两条线分别通过

- **原型线**：把当前原型中的智能薄片放回完整业务流程，补充来源、失败显性化和责任边界。
- **主管线**：每个建议都对应具体业务节点；至少有一个"不使用 AI/Agent"的决定，拒绝理由引用学员自己部门的至少一个具体业务约束，不是泛化套用教师案例的模式；选型说明了数据、工具、证据、HITL、停止和 owner；三链对象与凭证责任没有混淆，fallback 不伪装真实结果。
- **PROJECT_STATE.md** 只作交接，不能抵消任何一条主线的未通过。

### 必答题（5 题）

1. AI 机会地图以什么为单位判断？为什么不以"部门想用 AI"为单位？
2. AI 介入层级迁移有哪几个程度？为什么不是所有环节都选最高程度？
3. Agent 范式选型的依据是什么？为什么多 Agent 不是成熟度象征？
4. 三链区分区分哪三条链？为什么 MCP 不等于业务 API？
5. Fallback 来源与失败责任要求什么？为什么不能把 Mock 结果伪装成真实成功？

参考要点：以真实业务流程节点为单位，不以部门为单位，因为"部门想用 AI"是空泛的，逐环节判断才能落地；不用 AI/辅助/建议/单步/受控 Agent/受控闭环，按风险与价值选最简单足够者；依据路径是否确定/是否需动态调查/是否需规划，单 Agent 足够时不拆，多 Agent 是复杂度响应不是成熟度；开发工具链/业务 API 链/模型 API 链，MCP 是工具调用标准不是业务接口；降级结果必须显示来源/原因/限制/owner，伪装真实成功会导致决策错误。
