Lesson 03 · 需求澄清与数据契约

把模糊想法变成可执行的业务契约
grill-me 澄清与 3 份契约冻结

🎯 本课目标：不要急着写代码！通过 `/grill-me` 逼平 6 大业务要素，标注敏感度脱敏规约，落盘并冻结 3 份业务与数据契约，通过 Task 3A 只读结构预览门禁。

01 本课背景与核心原理

记住核心法则：
需求模糊盲开会导致 AI 凭空脑补字段与数据幻觉。通过 `grill-me` 追问与三份契约（功能卡、TS 类型字典、Mock 模拟数据），锁定业务边界与测试验收标准。

02 💡 本课 4 大核心工程概念卡

📝 核心概念 1：grill-me 追问澄清机制与 6 大业务要素

1. 硬核工程定义AI 扮演资深产品架构师，通过连续多轮针对性提问，逼平业务模糊点并落盘功能契约的范式。
2. 底层运作机制依次解构 6 大要素：1. User & Problem, 2. Goal, 3. Boundary, 4. Risk, 5. Acceptance, 6. Stop / Escalation。
3. 具象业务比喻装修开工前的主材确认清单 📝。在敲墙前，业主和工长必须对齐瓷砖品牌、插座数量并签字。
4. IT 沟通场景“需求已通过 grill-me 完成澄清，落盘为包含 6 大要素的 BUSINESS_FEATURE_CARD.md。”

⚠️ 核心概念 2：工程拨乱反正卡：为什么假数据也要标记敏感度？

1. 硬核工程定义在原型阶段为 Mock 字段标注隐私等级（公开/内部/严禁发送AI），建立面向未来生产网关的脱敏规约。
2. 底层运作机制告知未来 IT 部门生产网关必须在物理层切断该敏感字段，禁止送入公共 LLM 模型。
3. 具象业务比喻演习炸药箱上的红字警示标签 ⚠️。即使装的是无害沙子，也必须贴好标签防止真打仗搬错。
4. IT 沟通场景“数据契约表标注了敏感等级，作为未来生产 API 网关脱敏过滤的交接规约。”

📦 核心概念 3：数据契约与海关报关单 (Data Contract TS Types & Mock)

1. 硬核工程定义使用 TypeScript Interface 强类型定义物理字段，配合 Mock 数据文件实现的前后端数据协议。
2. 底层运作机制在 `prototype-contract.d.ts` 声明类型，在 `prototype-data.ts` 填充静态测试对象。
3. 具象业务比喻海关进口商品的标准报关单海关编码 📦。功能卡是集装箱，TS 类型是标准海关报关单。
4. IT 沟通场景“我们冻结了 prototype-contract.d.ts 数据契约，保证前端界面与数据字典 100% 匹配。”

🛑 核心概念 4：Given-When-Then 验收标准与 Stop / Escalation 升阶条件

1. 硬核工程定义行为驱动开发 (BDD) 的结构化验收语法，配合异常越界时的自动停止与人工升阶响应机制。
2. 底层运作机制定义 Given 前置条件 ➔ When 触发动作 ➔ Then 预期结果；数据冲突时触发 Stop 熔断并上报。
3. 具象业务比喻工厂流水线的紧急拉绳熔断阀 🛑。组装顺畅时按流程运转，零部件开裂时拉绳停机并上报。
4. IT 沟通场景“功能卡包含了完整的 Given-When-Then 验收链条与 Stop / Escalation 升阶条件。”
