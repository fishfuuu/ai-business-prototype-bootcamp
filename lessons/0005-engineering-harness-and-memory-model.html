02 核心概念卡：四步公式解析三大工程概念

🏇 1. Engineering Harness (工程鞍具 / 物理护栏)

• 硬核定义：为了约束 AI Agent 行为边界而建立的物理配置文件与防火墙。
• 底层机制：在 Agent 发起系统调用或修改代码前，强制读取 Harness 物理规则。
• 业务比喻：赛马的鞍具与缰绳 🏇。戴上缰绳，骑手（主管）才能把控方向。
• IT 沟通：“项目部署了工程 Harness 护栏，物理锁定了包管理器与编码规则。”

🧠 2. 三分记忆模型 (3-Layer Memory Architecture)

• 硬核定义：解耦为长期物理记忆 (`CLAUDE.md`)、中期进度记忆 (`IMPLEMENTATION_PLAN.md`) 与短期对话缓存 (Context Buffer)。
• 底层机制：长期规则在每轮对话开始前物理挂载 Prompt 顶部；短期缓存用 `/compact` 提纯。
• 业务比喻：公司章程 (长期) + 盘点账本 (中期) + 电话临时记事本 (短期) 📝。
• IT 沟通：“建立三分记忆模型，有效防止了 AI Token 溢出与规则遗忘。”

🎮 3. S/L 存读档状态恢复机制 (State Save / Load Restore)

• 硬核定义：通过读取磁盘持久化的状态机文件，无缝重建注意力锚点并恢复断点任务。
• 底层机制：中断对话或关机重开后，下发恢复口令，Agent 1 秒读取磁盘 `current_waiting_step`。
• 业务比喻：单机游戏的 S/L 存档与读档 🎮。关机重开后 1 秒载入最新关卡！
• IT 沟通：“支持 S/L 存读档状态恢复，跨会话开发时 1 秒无缝接续实施进度。”

2. 💡 常见概念误区与正确理解 (3 栏对照表)

常见误区 (Misconception) 正确硬核理解 (Correct Engineering Reality) 如何纠偏与护栏防护 (Remedy & Guardrails)
误区 1
“把所有规则粘贴在聊天框里 AI 就永远记得”		 聊天框是短期记忆（Context Buffer），随对话轮数增多必然面临 Token 溢出与注意力衰减（AI 幻觉）。 实行三分记忆模型，长期红线落盘至 `CLAUDE.md`，中期计划落盘至 `IMPLEMENTATION_PLAN.md`。
误区 2
“`CLAUDE.md` 需要手动一行行从头撰写”		 官方原生 `/init` 指令会自动一键扫描目录架构并生成初稿，主管只需补充 4 大防错红线。 在 CLI 中输入 `/init` 自动生成初稿框架，消除对配置文件的恐惧感。
误区 3
“中断对话或断电后，只能重头向 AI 重新解释背景”		 实施计划与配置均保存在本地磁盘物理文件中，恢复会话只需要 1 秒读取磁盘状态。 下发 `请读取 IMPLEMENTATION_PLAN 恢复当前 Step 状态`，1 秒完成 S/L 存读档恢复。
