02 核心概念卡：最高规约、三分记忆与 S/L 机制

📜 1. 最高工程规约 (CLAUDE.md)

根目录下的系统级 Prompt 护栏，AI 每次对话前强制读取。
锁定包管理器 (npm)、UI 框架 (Vue 3 + Element Plus)、禁止修改核心配置与敏感安全红线。

🧠 2. 三分记忆模型 (3-Layer Memory)

• 工作记忆 (聊天窗口: 随用随清)
• 外部长期记忆 (PROJECT_STATE.md / 实施计划: 跨会话继承)
• 版本证据 (Git Commit 节点: 物理可追溯与 S/L 读档)

🧪 3. 解药 1：环境脱幻工具箱

修改代码或安装依赖前，强制要求 Agent 先主动读取工程实际文件与依赖版本（如运行 verify-project.ps1），严禁凭空盲猜。

💾 4. S/L 存档还原机制 (Save & Load)

• 存档 (Save)：三层验收通过后立即 Commit 入库；
• 读档 (Load)：当 Agent 产生幻觉或改坏代码时，下发指令要求其一键撤销并恢复至最近的稳定 Git Commit！

2. 💡 常见概念误区与正确理解 (3 栏对照表)

常见误区 (Misconception) 正确硬核理解 (Correct Engineering Reality) 如何纠偏与护栏防护 (Remedy & Guardrails)
误区 1
“让 AI 自由选择安装流行的第三方库效率更高”		 擅自安装未知依赖容易导致版本冲突、打包体积膨胀甚至引入恶意代码，生产环境物理禁止。 在 CLAUDE.md 中写入依赖禁令，触发护栏物理拦截未授权 install。
误区 2
“以为在聊天窗口里说过的规则 AI 永远记得”		 聊天窗口属于工作记忆，随着对话变长（Context 满溢），前面的规则会被自动挤出蒸发。 将项目规约写入 CLAUDE.md，将业务事实写入 PROJECT_STATE.md 外部长期记忆。
误区 3
“项目改坏了就不断发指令让 AI 尝试修复”		 在污染的错代码上继续修复会导致错误叠加，如同在流沙上建塔。 运用 S/L 存档机制，一键放弃错误尝试，还原回最近的稳定 Git Commit 基线。
误区 4
“CLAUDE.md 是给程序员看的说明文档”		 CLAUDE.md 是专门写给 AI Agent 看的系统级 Prompt 护栏，具有最高优先级的指令效力。 项目起手即配置 CLAUDE.md，死死约束 Agent 修改边界。

❓ 退出门禁题 1：为什么不能把项目规约只保存在聊天窗口里，而必须落盘到 `CLAUDE.md`？
参考答案解析：
聊天窗口属于“工作记忆”，会随对话变长或新开会话而蒸发丢失；落盘到 CLAUDE.md 属于物理工程护栏，Agent 每次对话前都会强制读取，能够跨会话保持最高约束力。
❓ 退出门禁题 2：当 Agent 产生严重幻觉或改坏工程配置时，最正确的处理动作是什么？
参考答案解析：
运用 S/L 存档机制，立即下发指令要求 Agent“放弃当前错误尝试，恢复至最近的稳定 Git Commit”，重新从干净基线开工，绝不在污染的代码上叠加修改。
