02 💡 IT 跨界沟通术语：Working Tree & 步骤状态机

🔪 IT 术语卡：Working Tree (工作区 / 工作树)

通俗类比：厨师切菜的“砧板”或画家的“画板”。
当你当前打开文件夹、修改代码、AI 写入文件的地方就是 Working Tree。未修改时为 Clean (干净)；写了未提交文件时变为 Dirty (有变动)。

🛡️ 契约交接门禁：Pre-Plan Gate

在生成计划前，Agent 自动核对第三课的 3 份契约资产。若发现字段名、数据类型或枚举冲突，输出 [契约冲突拦截] CONTRACT_ASSET_MISMATCH 拒绝生成计划！

实施计划 5 大步骤状态机枚举 (Step Status Enum)

实施计划 docs/LESSON_04_IMPLEMENTATION_PLAN.md 物理收扣 5 种状态：

  • PENDING：后续未开始步骤的默认初始状态（Step 2..N 初始状态）；
  • READY：前置步骤已完成，等待主管下发 授权执行 Step N；
  • IN_PROGRESS：已下发授权，正在 Working Tree 上编码执行中；
  • COMPLETED：三层验收通过且完成打包 Commit A / B 归档；
  • BLOCKED：校验失败或主管拒绝后，备份快照并清扫 Working Tree 恢复 Clean 后的阻断状态。

2. 💡 常见概念误区与正确理解 (3 栏对照表)

常见误区 (Misconception) 正确硬核理解 (Correct Engineering Reality) 如何纠偏与护栏防护 (Remedy & Guardrails)
误区 1
“让 AI 一口气写完页面所有功能效率最高”		 一口气修改 10 个文件会导致 Working Tree 一片狼藉，爆 Context 且报错时根本无法定位根因。 唤醒 incremental-implementation 护栏，强制按 3–5 步切片，每次仅授权执行 1 个切片。
误区 2
“只要静态编译通过 (Verifier PASS)，就代表切片做对了”		 Verifier 只是静态编译检查，无法替代人工物理点击页面以及主管对业务逻辑与交互美观度的裁决。 严格执行 三层递进验收 (Verifier PASS -> 人工点击 PASS -> 主管业务验收 PASS)，缺一不可。
误区 3
“混淆界面技术呈现状态与业务处理流程状态”		 将 Loading 或 Error 误当成业务对象的状态，导致逻辑混乱与调试失败。 强制前端植入 prototypeState 调试器，与业务处理流程状态标签物理解耦。
误区 4
“切片报错时直接多次下发指令让 AI 撞大运”		 在 Working Tree 堆积坏代码重试会导致残渣残留，后续 Git 提交误将坏代码打包入库。 系统自动备份快照补丁并清扫 Working Tree 还原 Clean 干净源码，下发 同意记录 Step 1 问题 归档。

2. 🎯 课后退场自测题 (Exit Ticket)

❓ 退出门禁题 1：当你向 IT 工程师说“请清扫 Working Tree 恢复 Clean 干净状态”时，是什么意思？为什么切片失败时必须执行这个动作？
参考答案解析：
意思是撤销 Working Tree (工作区) 中未提交的破损修改与未跟踪文件，将其物理还原至上一个稳定的 Commit 节点；切片失败时执行此动作可以清扫坏代码残渣，防止污染后续工程。
❓ 退出门禁题 2：回复 `确认完成 Step 1` 时，Agent 底层顺次执行了什么操作？
参考答案解析：
Agent 底层顺次自动执行了 Commit A 源码暂存提交、提取 Commit SHA 回填 Plan 状态，以及 Commit B 实施计划更新暂存，把 Working Tree 上的改动打包入库并恢复 Clean 状态。
三句话带走 (Key Takeaways)：
  1. 不要一口气盲开，先落盘 IMPLEMENTATION_PLAN.md 增量切片。
  2. Working Tree 是切菜砧板，做完切片随时恢复 100% Clean 干净状态。
  3. 解耦界面技术状态 (prototypeState) 与业务处理流程状态。
