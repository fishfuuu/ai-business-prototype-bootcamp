Lesson 04 · 受控 Agent 循环与 Working Tree 物理状态机

把大需求拆成连续的小成功

不要让 Agent 一口气完成整个功能！通过 Plan & Execute 增量薄切片、Working Tree 砧板状态机 与 【房产过户双节点比喻 (Commit A 源码交房 + Commit B 状态确权)】，掌控节奏，打造无损无痛可回滚的受控 Agent 研发流。

🎯 本课目标：① 使用自然授权口令 (`同意保存实施计划` / `确认完成 Step 1`) 控制 Agent 节奏；② 植入 `prototypeState` 调试器实现技术与业务解耦；③ 掌握买房交房 Commit A 与房管局过户 Commit B 的双 Commit 归档原理；④ 掌握代码报错时的补丁快照备份与 Working Tree 干净无损还原。

02 核心概念卡：四步公式解析四大工程概念

🔪 1. Working Tree (工作区 / 工作树)

• 硬核定义：Git 中当前物理磁盘上记录代码修改的工作镜像。
• 底层机制：修改代码标记为 Dirty，提交或还原后恢复 Clean 干净状态。
• 业务比喻：厨师切菜的砧板 🔪。砧板有脏菜是 Dirty，冲洗或装盘后恢复 Clean。
• IT 沟通：“请确保提交前 Working Tree 处于 Clean 干净状态。”

🧩 2. 增量实施与薄切片 (Thin Slices)

• 硬核定义：将大块需求拆解为独立可编译、可测试的最小粒度切片。
• 底层机制：通过 IMPLEMENTATION_PLAN.md 磁盘状态机驱动步骤流转。
• 业务比喻：预制件搭积木 🧩。一块一块榫卯搭接，随时可单独替换。
• IT 沟通：“我们采用薄切片范式开发，拒绝盲开大块代码。”

🚗 3. 状态解耦 (prototypeState)

• 硬核定义：将界面技术呈现容错 (Loading/Empty/Error) 与业务对象生命周期解耦。
• 底层机制：在组件内植入 prototypeState 开发期变量与可视化调试按钮。
• 业务比喻：新车风洞测试 🚗。在静态风洞中测试车门在暴风雪中的容错表现。
• IT 沟通：“前端植入了调试器，实现了界面技术状态与业务流程状态的物理解耦。”

🏠 4. 房产过户双节点比喻 (Dual Commit)

• 硬核定义：通过 git add -- 将“源码变动”与“计划状态更新”隔离为两次独立提交。
• 底层机制：Commit A 仅暂存源码；Commit B 仅暂存计划状态更新。
• 业务比喻：买房入住 (Commit A 交房) vs 去房管局过户登记 (Commit B 确权) 🏠！验收无误才去盖章过户。
• IT 沟通：“项目采用双 Commit 隔离提交，源码资产与进度解耦。”

2. 💡 常见概念误区与正确理解 (3 栏对照表)

常见误区 (Misconception) 正确硬核理解 (Correct Engineering Reality) 如何纠偏与护栏防护 (Remedy & Guardrails)
误区 1
“让 AI 一口气写完页面所有功能效率最高”		 一口气修改 10 个文件会导致 Working Tree 一片狼藉，爆 Context 且报错时无法定位根因。 唤醒 incremental-implementation 护栏，强制按 3-5 步切片，每次仅授权执行 1 个切片。
误区 2
“只要静态编译通过，就代表切片做对了”		 Verifier 只是静态编译检查，无法替代人工物理点击页面及主管对业务美观度的裁决。 严格执行三层递进验收 (Verifier PASS ➔ 人工点击 ➔ 主管业务盖章)，缺一不可。
误区 3
“混淆界面技术呈现状态与业务处理流程状态”		 将 `Loading` 或 `Error` 误当成业务对象的状态，导致逻辑混乱与调试失败。 强制前端植入 prototypeState 调试器，与业务处理流程状态标签物理解耦。
误区 4
“混淆源码 Commit A 与 状态 Commit B”		 误以为一次 Commit 可以同时包办源码与项目进度状态。 掌握房产过户双节点比喻，用 git add -- 独立暂存，先验房交房 (Commit A) 再过户确权 (Commit B)。

2. 🎯 课后退场自测题 (Exit Ticket)

❓ 退出门禁题 1：在双 Commit 物理归档机制中，Commit A 与 Commit B 分别代表什么比喻含义？
参考答案解析：
Commit A 相当于【买房验房拿到钥匙入住 (交房)】，代表物理源码完成构建与验收；Commit B 相当于【去房管局做过户登记 (落盘确权)】，代表在实施计划中记录进度状态流转。先交房验房无误，才去房管局过户确权。
❓ 退出门禁题 2：当你需要向 IT 工程师解释为什么要采取双 Commit 隔离提交时，你应该怎么说？
参考答案解析：
“我们采用了双 Commit 隔离提交，将源码资产与项目管理进度解耦，先做源码落盘再做状态确权登记，支持独立的差异审计，且确保 Working Tree 随时可无损退回 Clean 状态。”
三句话带走 (Key Takeaways)：
  1. 不要巨石盲开，用 `IMPLEMENTATION_PLAN.md` 把大需求切成连续薄切片。
  2. 记住房产过户双节点比喻：先验房交房 (Commit A) 再过户确权 (Commit B)。
  3. 代码改坏不慌张，下发救援口令备份 `.patch` 快照，秒级还原干净砧板 Clean。
