# 第六课教师教案——用事实找 Bug，在边界内修复

> **核心思想：排错不是让 Agent 反复试，而是从事实出发、限制轮次，在证据不足时停下来交给合适的人。**

## 一、课程元数据与定位

| 项目 | 本课设定 |
| --- | --- |
| 学员 | 已完成第五课、掌握智能机会卡与原型智能薄片 V1 的业务主管 |
| 时长 | 90 分钟硬上限：85 分钟主线 + 5 分钟机动 |
| 课堂主成果 | 诊断与修复/停止证据包：事实卡、一个主假设、最多两轮诊断、实际观察、修复结果或停止/升级理由、恢复责任人 |
| 主管判断成果 | 能区分事实、假设和模型编造，决定继续、重试、停止、升级或恢复 |
| 支撑成果 | `docs/LESSON_06_DEBUG_REPORT.md` 更新诊断与恢复记录，只作跨课交接 |
| 数据边界 | 只使用 Mock 或已脱敏数据；不使用真实敏感日志、完整抓包、Token 或密钥 |

本课用同一个个人原型串起两条学习线：原型线要求"对普通薄片或智能薄片中的一个预置故障完成诊断，并得到修复后的可见状态或明确停止记录"，主管线要求"区分事实、假设和模型编造，决定继续、重试、停止、升级或恢复"。两条线分别验收，不能相互抵分。

本课不做：同时排查多个故障、运行无范围恢复命令、把"自动修复"宣称为保证能力。

开场必须先制造一个可见区别：让 Agent 盲目反复修导致越改越崩 vs 从事实出发限制轮次后精准修复或明确停止。先让学员看见"有界排错"的价值，再解释五个概念。

## 二、逆向目标、证据与核心概念

### 2.1 目标—活动—证据

| 学习目标 | 课堂活动 | 通过证据 |
| --- | --- | --- |
| 学员能复现一个已脱敏故障，只记录可观察事实 | Task 1 复现与事实记录 | 事实卡只记录可观察现象，不含猜测或编造 |
| 学员能用五层诊断卡确定最可能的问题层，提出一个可证伪主假设 | Task 2 五层诊断与假设 | 诊断定位到一层，主假设可被验证或推翻 |
| 学员能让 Agent 读取最小证据并提出第一轮修复，主管先核对范围 | Task 3 一轮修复 | 修改范围没有扩散，主管在执行前核对了范围 |
| 学员能验证结果，必要时进行第二轮，否则停止 | Task 4 验证与二轮决策 | 有明确的通过或停止决定，不是"Agent 还想试" |
| 学员能记录修复后状态，或记录停止/升级原因和恢复责任人 | Task 5 证据包归档 | 证据包完整：事实卡+主假设+观察+结果/停止+责任人 |

概念分层：核心概念为事实/假设与生成错误、事实锚定排错、五层诊断、有界排错、停止/升级与恢复；扩展认识为重试预算/熔断、根因与表象。$diagnose Skill 名称、LESSON_06_DEBUG_REPORT.md、git 命令在实操中使用但不升级为核心概念。$diagnose 是排错的结构化工具，类似 L4 的 /incremental-implementation：主管在 Task 1 激活 Skill 后，Agent 按 Phase 1—6 执行全部技术诊断（复现、五层检查、假设、修复、回归、清理），主管在每个 Phase 边界做审查和决策——审查事实报告、选主假设、核对范围、验证结果、记录证据。主管不做机械操作，只做判断和授权。安全红线横向管理，不占概念名额。

### 2.2 四步概念解析公式

#### 事实、假设与生成错误

1. **是什么 / 不是什么**：实际观察、待验证解释和模型凭空补全必须分开记录；事实是看到的现象，假设是对原因的解释，生成错误是 AI 编造的不存在信息。三者不能混为一谈。
2. **机制**：遇到故障时先记录可观察事实（页面报什么、数据是什么），再提出待验证假设（可能是 X 层的问题），最后警惕生成错误（AI 声称"已修复"但实际没改或改错了）。
3. **类比 / 反例**：医院急诊分诊——体温 38.5 度是事实，"可能是感冒"是假设，"我觉得是绝症"是编造；三种信息在病历上分开记录，不能混在一起。
4. **交接价值**：回指 Task 1—2——学员复现故障时只记事实卡，五层诊断时标明假设，验收时核对 AI 没有编造结果。

#### 事实锚定排错

1. **是什么 / 不是什么**：从复现、输入、契约、日志和实际状态缩小原因，不先猜修复方案；不是看到报错就改代码，也不是让 Agent 天马行空地试。
2. **机制**：先复现故障并记录可观察事实，再用五层诊断卡逐层排查缩小范围，最后提出一个可证伪的主假设——如果能推翻就换，不能推翻就按假设修复。
3. **类比 / 反例**：医生开处方前的验血报告与病历归档——没拿到验血和 CT 证据并填写病历前，绝不盲目开药开刀；不能看一眼病人就说"先吃点抗生素试试"。
4. **交接价值**：回指 Task 1—3——学员先记事实卡，再五层定位，再读最小证据后才修复；诊断结论落盘到 LESSON_06_DEBUG_REPORT.md。

#### 五层诊断

1. **是什么 / 不是什么**：按环境/入口、数据、业务逻辑、界面交互、智能/外部依赖等层次定位问题，而不是到处乱改；不是从底层框架开始猜，也不是一次看所有层。
2. **机制**：口语化五层标签——Layer 1 环境"网页跑不起来"、Layer 2 数据"没数据或拿到 null"、Layer 3 状态"数据变了界面没动"、Layer 4 日志"控制台第一行红字"、Layer 5 契约"名字写错了配不上契约"。从上到下逐层排除，定位到最可能的一层。
3. **类比 / 反例**：汽车故障五级诊断仪——从轮胎电压（环境）、汽油品质（数据）、仪表盘显示（状态）、故障码（日志）到行驶安全标准（契约）逐级检查；不能一上来就拆发动机。
4. **交接价值**：回指 Task 2——学员用五层标签定位问题层，提出一个可证伪主假设，而不是同时排查多层。

#### 有界排错

1. **是什么 / 不是什么**：明确一个故障、一个主假设、修改范围和轮次上限；失败也必须留下证据。不是无限试错，也不是一轮失败就放弃。
2. **机制**：排错前先存 Checkpoint 存档，限定修改范围，设置最多两轮修复上限；第一轮按主假设修复，验证不通过则调整假设进行第二轮，仍未通过则停止。
3. **类比 / 反例**：单机游戏 Boss 战前的 Save Point——进战场前先存个档，打不过时只清扫本场坏试错（git restore），历史装备毫发无损；不能无限复活硬打。
4. **交接价值**：回指 Task 3—4——学员先存档再修复，每轮修改在范围内，两轮不通就停止而非继续盲目试。

#### 停止、升级与恢复

1. **是什么 / 不是什么**：证据不足、风险越界或两轮无进展时停止，由指定人员接管或按范围恢复；不是失败放弃，也不是让 Agent 继续试。
2. **机制**：停止时记录原因（证据不足/风险越界/两轮无进展）、新证据需求、恢复责任人；恢复时从 Checkpoint 存档回退，导出 .patch 快照备份，不无差别清空。
3. **类比 / 反例**：工厂异常停机与交接班——发现设备异常时拉绳停机，记录异常现象和初步判断，交给下一班的技术人员处理；不是一直让机器跑着等它自己好。
4. **交接价值**：回指 Task 5——学员停止时记录停止原因、新证据需求和恢复责任人，不是只说"修不好"就结束。

### 2.3 扩展认识概念卡

#### 重试预算/熔断（认识级）

次数、时间和风险达到阈值就不再自动继续。原版的"2 轮硬熔断"是具体实现：两轮不通则强制停止。教师用 2—4 分钟说明阈值的意义，不设独立通过门槛。

#### 根因与表象（认识级）

修掉页面报错不一定修掉业务或数据根因。比如改了字段名让页面不报错了，但如果数据源本身有空值，下次还会出问题。教师用 2 分钟举例说明，不展开。

讲解时将五张卡放在同一个医院急诊故事中：先区分体温/症状/编造（事实/假设与生成错误），再做验血和 CT 确认方向（事实锚定排错），接着按五层检查仪逐层定位（五层诊断），然后限定最多两轮治疗并先存档（有界排错），最后治不好就停机交班并记录（停止/升级与恢复）。总计控制在 10 分钟左右；不要逐字朗读。

## 三、教学准备与安全边界

### 课前预检

- 第五课原型可用：学员已有普通业务薄片和受控智能候选，试衣镜中原型可操作。
- 预置故障包可用：教师已为课堂预置一个可复现的脱敏故障（如字段名不匹配导致界面异常）。
- $diagnose Skill 可用：确认课程指定路径存在且可激活（类似 L4 确认 /incremental-implementation 可用）。
- `docs/PROJECT_STATE.md` 有智能机会候选状态和上一课输入。
- Working Tree 处于 Clean 状态：教师演示前先 `git status` 确认。
- 开发服务器可启动：双击 `start-project.bat` 或运行 `npm run dev`，试衣镜 `http://127.0.0.1:8888/` 可访问。
- 助教理解环境问题 3 分钟接管规则，知道学员粘贴敏感日志时的现场处置方式。

### 实操前只讲四条红线

1. 只用 Mock/已脱敏数据，不输入真实资料、密钥、Token 或账号；日志脱敏后再给 AI，所有敏感信息替换为 `<REDACTED>`。
2. 不同时排查多个故障；一次只诊断和修复一个故障。
3. 不运行无范围恢复命令；回退时从 Checkpoint 存档恢复，导出 .patch 快照后恢复 Working Tree Clean。
4. 不把"自动修复"宣称为保证能力；文字要求和主管确认是工作约束，不冒充运行时硬控制。

教师不得虚构 `verify-project.ps1`、`[PASS]` 全量校验等课堂能力。实际运行什么，就展示什么证据。

## 五、逐 Task 示范、口令、巡视与降级

教师统一案例只走一条路径：以工单看板为例，预置一个字段名不匹配的故障（`status_name` 应为 `status`），导致工单状态标签不显示。从激活 $diagnose 让 Agent 复现故障（Phase 1—2）→ Agent 五层诊断定位到契约层（Phase 3）→ 主管审查报告选主假设"字段名与契约不一致"→ 存 Checkpoint 后 Agent 读最小证据提出修复方案（Phase 4—5）→ 主管核对范围后授权 → 验证通过 → 记录证据包（Phase 6）。每个 Task 均按以下四项执教。

### Task 1：激活 $diagnose，确认故障现象，审查 Agent 的事实报告

- **教师示范**："先看一眼故障长什么样，然后激活 $diagnose 让 Agent 去复现和记录，你审报告。"展示主管打开预置故障页面看一眼——"工单状态标签确实空白"，确认故障存在。然后激活 $diagnose Skill，让 Agent 按 Phase 1—2 构建可重复的 PASS/FAIL 信号并复现故障。Agent 返回事实卡，上面只记录可观察现象："打开工单详情页，状态标签位置空白，控制台无报错"。主管审查事实卡：确认只记了现象，没有混入"可能是字段名错了"这类假设。确认无误后在事实卡上签确认。强调主管的动作是"看一眼 + 审报告 + 签确认"，不是自己打开控制台、自己逐行查。
- **教师口令**："看一眼你的预置故障确认它存在，然后激活 $diagnose 让 Agent 复现并生成事实卡。你审查事实卡，确认只有现象没有猜测。不要自己查控制台、不要让 AI 修改代码。日志中有敏感信息的先脱敏。"
- **巡视判断**：主管是否先看了一眼故障现象；是否激活了 $diagnose 而非自己手动排查；事实卡是否只记现象不含猜测；是否已经脱敏；是否同时排查多个故障。
- **失败降级**：学员自己查控制台时提醒"让 Agent 查，你审报告"；学员把猜测写进事实卡时，提醒"事实是看到的，假设是想到的，分开记"；无法复现时检查是否加载了正确的故障；同时排查多个故障时缩到一个。

### Task 2：审查 Agent 的五层诊断报告，选定一个可证伪主假设

- **教师示范**："Agent 已经在跑了，你看它五层查完的报告。"展示 $diagnose 按 Phase 3 自动跑五层诊断卡：Agent 逐层检查并报告——Layer 1 环境正常（PASS）、Layer 2 数据有值（PASS）、Layer 3 数据有但界面没显示（FAIL）、Layer 4 无报错（PASS）、Layer 5 字段名 `status_name` 与契约 `status` 不一致（FAIL）。Agent 定位到契约层，生成 3—5 个可证伪假设并排序，主假设"字段名与契约不一致"。主管审查这份报告：确认逐层排查没有跳层，确认定位到契约层是合理的，确认主假设可证伪（改字段名后能验证），然后选定这个主假设。强调主管的动作是"审报告 + 确认定位 + 选假设"，不是自己逐层查。
- **教师口令**：下发五层诊断提示词模板（见学员指南 Task 2）。让 Agent 逐层排查，你审查报告后选定一个可证伪主假设。不要自己逐层查。
- **巡视判断**：Agent 是否从上到下逐层排查而非跳层；主管是否审查了报告而非自己查；主假设是否可证伪（能被验证或推翻）；是否同时提了多个假设。
- **失败降级**：学员自己逐层查时提醒"让 Agent 查，你审报告"；Agent 跳层排查时提醒"从 Layer 1 开始逐层排除"；同时提多个假设时缩到一个；假设不可证伪时改写为可验证的形式。

### Task 3：存 Checkpoint，审查 Agent 的修复方案，核对范围后授权

- **教师示范**："动代码前先存档，然后看 Agent 的修复方案，你核对范围后才授权。"展示 `git commit -m "checkpoint: before lesson 6 debug"` 存 Checkpoint。$diagnose 已经在 Task 1 激活，Agent 自动进入 Phase 4—5：读取契约文件和页面代码（最小证据），确认字段名不匹配后提出修改方案——只改一个字段名 `status_name` → `status`，不碰其他文件。主管审查方案：改了什么文件、改了什么字段、改了几处。确认范围没有扩散后发送授权。强调 $diagnose 从 Task 1 激活后全程运行，这里不需要重新激活；主管的动作是"存档 + 审方案 + 核对范围 + 授权"。
- **教师口令**：下发一轮修复提示词模板（见学员指南 Task 3）。先存 Checkpoint，$diagnose 已在运行中，让 Agent 读最小证据提出修复方案，你核对范围后才授权。
- **巡视判断**：是否先存了 Checkpoint；是否只读了最小证据而非全部文件；主管是否核对了修改范围；是否在范围内修改。
- **失败降级**：未存 Checkpoint 时先补存；Agent 读太多文件时缩到最小证据；主管未核对就授权时退回核对环节；Agent 扩大范围时立即停止。

### Task 4：验证结果，必要时进行第二轮，否则停止

- **教师示范**："修改后刷新试衣镜看效果。"展示修复后状态标签正常显示——验证通过。强调 $diagnose 的 Phase 5 要求写回归测试，但在本课中回归测试由 Agent 自动完成，你只需确认原始故障不再复现。如果第一轮不通过：调整假设进行第二轮，仍未通过则停止。强调停止不是失败，是"证据不足时交给合适的人"。
- **教师口令**：验证修复结果。通过则进入 Task 5 记录；不通过则调整假设进行第二轮；两轮都不通则停止。
- **巡视判断**：验证是否基于可观察结果而非 AI 自称"已修复"；是否在范围内修改；第二轮是否调整了假设而非盲目重复；是否两轮不通就停止。
- **失败降级**：AI 自称"已修复"但学员没看到实际效果时，要求实际刷新验证；第二轮盲目重复第一轮时提醒"换假设或停"；学员想继续试第三轮时执行停止。

### Task 5：记录修复后状态，或记录停止/升级原因和恢复责任人

- **教师示范**："现在写证据包。"展示如何填写 LESSON_06_DEBUG_REPORT.md：事实卡（状态标签空白）、主假设（字段名不匹配）、诊断过程（五层定位到契约层）、修复结果（改了字段名，状态标签正常显示）、恢复责任人（学员自己）。强调这一步对应 $diagnose 的 Phase 6（清理 + 复盘）：Agent 清理调试日志和临时文件，你记录诊断结论和责任人。如果停止：记录停止原因（两轮无进展）、新证据需求（需要检查数据源是否有空值）、恢复责任人。
- **教师口令**：下发证据包归档提示词模板（见学员指南 Task 5）。记录事实卡、主假设、诊断过程、修复结果或停止/升级原因、恢复责任人。
- **巡视判断**：证据包是否完整（六项都有）；事实和假设是否分开记录；停止时有停止原因和恢复责任人而非只说"修不好"；修复结果是否可追溯。
- **失败降级**：证据包不完整时补齐缺失项；事实和假设混在一起时分开记录；缺少恢复责任人时追问"谁来接手"。

## 七、随堂测试、通过标准与课后任务

### 两条线分别通过

- **原型线**：对一个预置故障完成诊断，得到修复后的可见状态或明确停止记录；修改范围没有扩散。
- **主管线**：能区分事实、假设和模型编造；每轮动作、观察和判断可追溯；能基于证据选择继续或停止，而不是把"Agent 还想试"当理由。
- `LESSON_06_DEBUG_REPORT.md` 只作交接，不能抵消任何一条主线的未通过。

### 必答题（5 题）

1. 事实、假设和生成错误有什么区别？为什么排错时必须分开记录？
2. 五层诊断卡的五层分别是什么？为什么要从上到下逐层排除而不是到处乱改？
3. 有界排错要求明确哪四项？为什么不能无限试错？
4. 两轮诊断仍未通过时应该怎么做？为什么不能继续试第三轮？
5. 停止、升级与恢复分别是什么意思？停止时至少要记录哪三项？

参考要点：事实是观察现象/假设是待验证解释/生成错误是编造，分开才能追溯；环境/数据/状态/日志/契约五层，逐层排除缩小范围；一个故障/一个主假设/修改范围/轮次上限；停止记录原因而非继续盲目试；停止原因+新证据需求+恢复责任人。

### 拓展题（选做，2 题）

1. 重试预算/熔断的阈值应该怎么设？太高和太低各有什么风险？
2. 修掉页面报错不一定修掉根因，请举一个例子说明表象和根因的区别。

### 课后任务

10—15 分钟：在 `PROJECT_STATE.md` 中补齐诊断/恢复记录和下一课输入说明。不继续开发功能；第七课会让 Agent 用浏览器操作页面并留下验收证据。
