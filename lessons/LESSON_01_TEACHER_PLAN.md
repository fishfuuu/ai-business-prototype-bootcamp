# 第一课教师教案（预览稿）——从业务问题到第一个受控原型

> **核心思想：理解 LLM 大脑、Tools 手脚与 Agent 执行者的关系，并用这套协作关系建立第一个受控业务原型。**

## 一、课程元数据与定位

| 项目 | 本课设定 |
| --- | --- |
| 学员 | 不要求具备 AI、Agent、代码、Git 或信息化基础的业务主管 |
| 时长 | 90 分钟硬上限：85 分钟主线 + 5 分钟机动 |
| 课堂主成果 | 每位学员的一条可操作个人业务最小路径（个人业务原型 V1） |
| 主管判断成果 | 能区分 LLM、Tools、Agent，并说明主管在定义、范围和验收中的责任 |
| 支撑成果 | `docs/PROJECT_STATE.md`，只作跨课交接，不独立评分 |
| 数据边界 | 只使用 Mock 或已脱敏数据；不使用真实密钥、账号和业务接口 |
| 正式业务 AI 起点 | L5；L1 的 Agent 是制作原型的开发 Agent，不是原型中的业务智能功能 |

本课用同一个个人原型串起两条学习线：原型线要求“做出并操作一条路径”，主管线要求“看懂 Agent 如何做、知道自己何时判断”。两条线分别验收，不能相互抵分。

本课不做：判断业务 AI 机会、加入业务 AI 功能、完成整个业务系统、固定页面数量、连接真实接口、让学员复现教师案例，或深入讲 Workflow/HITL/Context/CLAUDE.md。

开场必须先制造一个可见区别：网页聊天框只能给出候选方案；开发 Agent 能借助 Tools 在本地预览中形成可操作路径。先让学员看见结果差异，再解释四个概念。

## 二、逆向目标、证据与核心概念

### 2.1 目标—活动—证据

| 学习目标 | 课堂活动 | 通过证据 |
| --- | --- | --- |
| 学员能把 LLM、Tools、Agent 对应到真实动作，并指出一个混淆反例 | Task 1—4 对照体验 | 随堂题正确 + 抽查时能解释动作差异 |
| 学员能从 A/B/C 中选择一个起点，说清使用者、场景、动作与结果 | 选型与范围裁决 | 一句话业务路径清楚，且本轮只有一个主要动作 |
| 学员能在课内制作并演示一条个人业务路径 | 实施、预览、一次微调 | 能打开、能操作、有结果、数据标识清楚 |

概念分层：核心概念为 LLM、Tools、AI Agent、业务原型；ReAct 只作扩展认识；Prompt、主管确认、Mock、本地预览在实操中使用；Workflow、HITL、Context、项目级 Agent 指令与约束仅作教师背景。

### 2.2 四步概念解析公式

#### 大语言模型（LLM）：大脑

1. **是什么 / 不是什么**：根据当前信息生成候选内容的概率模型；不是能直接操作电脑的完整 Agent，也不是天然了解部门事实的专家。
2. **机制**：根据 Prompt 和上下文生成后续内容；Task 1 只复述和规划。
3. **类比 / 反例**：总工程师能理解要求、画图纸；图纸完成不等于样板间完成。
4. **交接价值**：回指 Task 1——模型帮助解构需求，但业务事实仍需主管核对。

#### Tools（手脚）

1. **是什么 / 不是什么**：读取、修改、运行和取得结果的能力；不是 LLM 本身，也不代表权限无限。
2. **机制**：宿主环境执行工具调用并返回结果；Task 2 只读，Task 3 才修改和运行。
3. **类比 / 反例**：施工机械和测量工具让方案落地；有机械不等于施工自然安全合规。
4. **交接价值**：回指 Task 2/3——主管应追问用了什么工具、读了什么、改了什么。

#### AI Agent

1. **是什么 / 不是什么**：组织 LLM、当前信息与 Tools 完成多步工作的系统；不是能够自行承担业务责任的数字员工。
2. **机制**：接收目标、推演下一步、调用工具、观察结果，再继续、调整、停止或请求处理。
3. **类比 / 反例**：现场执行负责人能调度资源；不能在没有业务边界和验收时自行决定目标。
4. **交接价值**：回指 Task 1—4——Agent 负责执行，主管负责目标、范围和验收。

#### 业务原型（样板间）

1. **是什么 / 不是什么**：验证业务路径和需求表达的可操作模型；不是生产系统或全部需求。
2. **机制**：用 Mock/脱敏数据呈现一条最小路径，再由主管判断是否正确。
3. **类比 / 反例**：样板间可验证关键布局；不能当作已交付的整栋建筑。
4. **交接价值**：回指个人成果——主管能够说明哪条路径已经验证、哪些仍未实现。

讲解时将四张卡放在同一个建筑工程故事中，总计控制在 10 分钟左右；不要逐字朗读。ReAct 只在 Task 4 完成后命名。

## 三、教学准备与安全边界

### 课前预检

- 起点项目可用 `start-project.bat` 或课程指定方式打开本地预览。
- 开发 Agent 可用；记录真实授权方式，不假定所有工具都逐次确认。
- A/B/C 三个启动分支均已试跑；三个备用起点壳只用于失败降级。
- 教师案例可完成“查看异常 → 查看信息 → 记录处理决定”的一条路径。
- 助教理解环境问题 3 分钟接管规则，知道真实/敏感数据的现场处置方式。

### 实操前只讲四条红线

1. 只用 Mock/已脱敏数据，不输入真实资料、密钥、Token 或账号。
2. 文字要求和主管确认是工作约束，不冒充 Workflow/HITL、沙箱或运行时硬控制。
3. 工程检查通过不等于业务正确，ReAct 也不保证自动修复。
4. 不连接真实 API、数据库或模型；本课成果不是生产系统。

教师不得虚构 `scripts/verify-student-project.ps1`、`npm run verify`、`doctor`、`test:ui` 等课堂能力。实际运行什么，就展示什么证据。

## 四、90 分钟控场主线

| 时间 | 宏观阶段 | 教师动作 | 学员动作 | 阶段证据 |
| --- | --- | --- | --- | --- |
| 0—15 分 | **看见结果，建立模型** | 对比聊天回答与可操作原型；用建筑比喻和融合图讲四个概念 | 初选 A/B/C，能指出大脑、手脚、执行者和样板间 | 知道本课成果与四者关系 |
| 15—25 分 | **教师完整示范** | 用统一案例串演 Task 1—4，只演方法，不让学员复现 | 观察“推演—读取—裁决实施—验收微调” | 建立整体动作锚点 |
| 25—70 分 | **个人原型实施** | 按 Task 1（约 9 分）→ Task 2（约 7 分）→ 裁决与 Task 3（约 29 分）巡视；助教处理环境 | 完成个人业务输入、项目读取、范围裁决和核心路径 | 个人路径可打开、可操作、有结果 |
| 70—85 分 | **验收、微调与证据** | 指导 Task 4 四问验收，只修一个问题；同步交接单；收取随堂题 | 判断业务结果、完成一次微调、核对证据与答案 | 原型线和主管线分别判定 |
| 85—90 分 | **机动与闭合** | 处理卡点或个别展示，不增加新必做项 | 闭合主线或观看展示 | 未完成者获得明确降级出口 |

压缩顺序：先取消个别展示，再压缩教师示范；不得删除个人实施、业务验收或主管判断。5 道必答题分散在相应 Task 后完成，最后只检查提交。

## 五、逐 Task 示范、口令、巡视与降级

教师统一案例（业务异常预警与闭环处置工作台）只走一条路径：查看异常记录 → 打开异常信息 → 记录处理决定。每个 Task 均按以下四项执教。

### Task 1：LLM 只理解和推演

- **教师示范**：“现在只让模型复述和提方案，它还没有读项目。”展示模型如何标出不确定信息。
- **教师口令**：“只选择 A/B/C 中的一种；先核对它是否理解你的业务，不要急着让它做页面。”
- **巡视判断**：使用者、场景、动作、结果和不做项是否清楚；是否只有一条路径；是否把猜测写成业务事实。
- **失败降级**：不会选型时按主要动作判断；Agent 已调用工具时立即停止，列出真实动作后由教师决定恢复或继续。

### Task 2：Tools 只读取项目事实

- **教师示范**：“现在让工具看真实项目，模型的想象必须让位于读取结果。”展示存在与不存在文件的不同报告。
- **教师口令**：“只读完成本课所需的最小资料；看见证据以后再修订方案。”
- **巡视判断**：是否有真实读取结果；是否报告缺失文件；拟修改文件是否必要；是否无故扩张页面数量。
- **失败降级**：编造文件或已经修改时立即停止；入口不明时由助教帮助定位实际文件，不让学员猜路径。

### Task 3：主管裁决范围，让 Agent 实施

- **教师示范**：“我删掉多余范围，只保留这一条路径。”现场填写路径、字段/状态、不做项、允许文件和验收方法。
- **教师口令**：“先让 Agent 复述范围；确认无误后，才按这一个范围实施。”
- **巡视判断**：类型是否单一 → 路径是否够薄 → 数据是否安全 → 是否有可见交互 → 是否擅自扩张 → 学员能否按自己的方法验收。
- **失败降级**：环境超过 3 分钟由助教接管；生成过多页面时只保留核心路径；静态页面补一个必要交互；出现真实接口、业务 AI 或范围外文件时立即停止。

### Task 4：本地预览验收与一次微调

- **教师示范**：“页面能打开不等于业务正确。我先回答谁、何时、做什么、看到什么，再只修一个问题。”
- **教师口令**：“让 Agent 先说明原因和修改边界；确认后只修这一项，然后停止扩展。”
- **巡视判断**：四问是否成立；修正前后差异是否可见；核心路径是否仍能操作；实际检查与完成报告是否一致。
- **失败降级**：微调引发新错误或范围继续扩大时停止自动修改，保留当前证据并由教师/助教接管；路径通过后再同步 `PROJECT_STATE.md`，不另设写作任务。

## 六、现场 Debug 与降级预案

| 问题类型 | 教师处置 | 禁止说法 |
| --- | --- | --- |
| 选型或范围失控 | 按主要动作重选 A/B/C；只留一个使用者、动作和结果 | “页面越多越完整” |
| Agent 越阶段或编造项目事实 | 立即停止，要求列出真实动作和证据，再决定恢复或继续 | “一句禁止已形成硬门禁” |
| 原型静态、状态不变或业务路径错误 | 优先修核心动作与结果，一次只修一个问题 | “能构建就是业务通过” |
| 环境或验证超过 3 分钟 | 助教接管、换备用起点或记录未验证 | 虚构 `[PASS]` 或不存在的脚本 |
| 出现真实/敏感数据 | 立即停止传播与操作，按现场制度处置并替换 Mock | “AI 已自动脱敏” |

## 七、随堂测试、通过标准与课后任务

### 两条线分别通过

- **原型线**：能打开；一条路径可操作并看到结果；数据标识清楚；不按页面数、视觉精致度或需求完整度评分。
- **主管线**：能把 LLM、Tools、Agent 对应到真实动作，并说明主管负责定义、范围和验收。
- `PROJECT_STATE.md` 只作交接，不能抵消任何一条主线的未通过。

### 必答题（5 题）

1. LLM 本质上属于具有不确定性的什么模型？
2. Agent 读取文件或运行命令时，真正执行外部动作的是什么？
3. 实施前，除核心路径和修改范围外，主管还应确认什么？
4. Agent 声称检查 `[PASS]` 时，至少应展示哪两类真实证据？
5. Agent 在 Task 1 就修改文件违反了什么边界？应如何处理？

参考要点：概率生成/预测；Tools/工具接口；本轮不做项；真实命令与输出/日志；违反“只推演、不使用项目工具”，立即停止、查明动作、按实际状态恢复或继续。

### 拓展题（选做，2 题）

1. 用“大脑—手脚—执行者”解释生成代码与修改项目为何不同。
2. 一句话说明个人原型的 A/B/C 类型、问题和只做当前路径的理由。

### 课后任务

10—15 分钟：找一张视觉参考图，写一句下一课最想改善的视觉或使用问题。不继续开发功能。

## 八、教师备课质量自测 Checklist

- [ ] 开场先展示“聊天回答 vs 可操作原型”，再讲概念。
- [ ] 四个核心概念使用同一建筑比喻并回指真实 Task；ReAct 只作扩展认识。
- [ ] A/B/C 只在启动时分支，随后汇入统一四步流程；学员直接做个人原型。
- [ ] 五阶段时间预算不超过 90 分钟，个人实施和业务验收没有被压掉。
- [ ] 每个 Task 均准备了示范、口令、巡视判断和失败降级。
- [ ] 原型线和主管线分别验收；5+2 题与学员指南一致。
- [ ] 四条安全红线及五类 Debug 按真实环境能力表述，助教接管路径明确。
- [ ] 未固定页面数、添加业务 AI、虚构验证能力，或把文字确认冒充硬控制。
