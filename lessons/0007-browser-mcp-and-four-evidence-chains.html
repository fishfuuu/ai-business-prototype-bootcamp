02 核心概念卡：四步公式解析三大测试工程概念

🕵️‍♂️ 1. QA Subagent & Dual MCP Tooling

• 硬核定义：主 Agent 调度的只读沙箱子进程，协同 Playwright MCP（UI 操作）与 Chrome DevTools MCP（Console/Network 审计）执行端到端质量验收。
• 底层机制：QA Subagent 在隔离子进程中运行，调用 Playwright 驱动 DOM 交互，DevTools 捕获 0 报错与 127.0.0.1 请求，完结后自动销毁沙箱。
• 业务比喻：带专业仪器进场的外聘第三方 QA 审计员 🕵️‍♂️。检测完自动退场，不占用主桌。
• IT 沟通：“我们调度了 QA Subagent 挂载 Playwright 与 DevTools 双 MCP 进行了端到端自动化质量审计。”

⚖️ 2. Four-Category Evidence Chain & Index

• 硬核定义：由视觉截图 (`screenshot.png`)、行为脚印 (`action.log`)、工程体检 (`typecheck.log`)、范围存根 (`diff.patch`) 及汇总索引 (`LESSON_07_EVIDENCE_INDEX.md`) 构成的全方位客观审计证据集合。
• 底层机制：视觉 `照片` ➔ 行为 `脚印` ➔ 工程 `体检` ➔ 范围 `存根` + 4 行 YAML Header 索引总卡。
• 业务比喻：法庭举证的物证、足迹、体检报告与合同存根 ⚖️。四证合一，绝不凭口头凭空猜测。
• IT 沟通：“我们物理落盘输出了四类证据链与 EVIDENCE_INDEX 验收总卡，可供 100% 解析复核。”

🏎️ 3. Headed SlowMo vs. Headless Sandbox Lifecycle

• 硬核定义：支持前端交互可视化慢动作展示 (`headed: true, slowMo: 500`) 与后台高效静默落盘 (`headless: true`)，并在完结后销毁子进程的资源管理范式。
• 底层机制：Task 1 开启 Headed 慢动作建立信任；Task 2 开启 Headless 静默落盘证据；测试结束自动 Kill Subagent 进程。
• 业务比喻：无人驾驶车观摩演练 ➔ 封闭赛道高速全自动测试 🏎️。先看示范建立信任，再全自动跑数据。
• IT 沟通：“测试过程在只读沙箱中完成，测试完即刻销毁，保证主开发环境 Context 干净隔离。”

04 学员实操 Task 1 ~ Task 3 自然授权口令卡

Task 1 · 唤醒 QA Subagent 并开启 Playwright 视窗慢动作演示
在 CLI 窗口中下发唤醒 QA Subagent 慢动作演示口令：
唤醒 QA Subagent，开启 Headed 慢动作测试演示
原理：在隔离子进程中调出 Chrome 视窗，以 500ms slowMo 慢动作自动点击示范 DOM 交互。
Task 2 · 挂载 Chrome DevTools MCP 静默抓取并落盘四类证据与总卡
下发 Headless 双 MCP 静默测试与证据落盘口令：
同意执行 Headless 双 MCP 测试，落盘四类证据与 EVIDENCE_INDEX
验证：确认物理磁盘成功落盘 4 个证据文件及 docs/LESSON_07_EVIDENCE_INDEX.md。
Task 3 · 证据链复核与人在回路 (HITL) 签署归档 (销毁沙箱)
核对证据总卡全 PASS 后，下发最终签署归档与沙箱销毁口令：
复核四类证据链无误，同意签署第 7 课验收盖章
原理：在 PROJECT_STATE.md 中更新稳定 Commit，并自动 Kill 销毁 QA Subagent 沙箱。

常见误区 (Misconception) 正确硬核理解 (Correct Engineering Reality) 如何纠偏与护栏防护 (Remedy & Guardrails)
误区 1
“问问 AI 页面做好没有，AI 答做好了就能向 IT 交接”		 AI 的口头承诺是概率性的，缺乏物理证据的交付 100% 会被 IT 部门打回。 唤醒 `evidence-verification` Skill，强制要求落盘四类证据与总卡。

“测试只能在后台默默跑，看不见过程心里发虚”		 Task 1 支持 Playwright 视窗慢动作演示，可亲眼观看自动点击全过程。 下发 `开启 Headed 慢动作测试演示`，可视化建立信任感。

2. 🎯 课后退场自测题 (Exit Ticket)

❓ 退出门禁题 1：为什么“只读 QA Subagent 沙箱 + 测试后即刻销毁”是保持 AI 主会话长期稳定的关键机制？
参考答案解析：
沙箱隔离防止了测试过程中的冗余 DOM 节点与 DevTools 原始日志污染主会话 Context 空间；测试完即刻销毁释放了 Token 与内存，确保后续开发任务不受干扰。
❓ 退出门禁题 2：四类证据链中的“脚印日志 (`action.log`)”包含了哪些关键审计指标？
参考答案解析：
由 Chrome DevTools MCP 提取并脱敏打码 (``)，重点审计 DevTools Console 0 报错 以及 网络请求白名单仅限 127.0.0.1（无外部敏感数据外泄）。
三句话带走 (Key Takeaways)：
  1. 口说无凭，证据落盘；拒绝无证据交接，四证合一才算终点。

  3. 沙箱隔离不混淆，测试完即刻销毁子进程，落盘 EVIDENCE_INDEX 供 Codex 独立审查。
