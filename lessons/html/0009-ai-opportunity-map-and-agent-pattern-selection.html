01 从一个智能候选点到整条流程，怎么选？

第五课你选了一个智能候选点，但那只是"一个环节值得加 AI"的初筛。如果扩展到整条业务流程呢？哪些环节该用 AI、哪些不该、各用什么范式、数据从哪来、谁负责失败？第九课把这些判断从"一个点"扩展到"一条完整流程"。

记住这句话：
逐环节判断任务性质、可验证性、错误代价和数据风险，选择最简单足够的范式。至少要有一个"明确不用 AI"的有理由决定。

判断建立在前八课的业务契约、原型行为、失败、证据和评审之上，不是在第一课凭想象拍脑袋。

03 核心概念卡：本课必须掌握的概念

本课必须掌握的核心概念 (点击展开详情)：

操作方法：AI 机会地图、介入层级迁移、Agent 范式选型；核心概念是机会、介入层级、范式、三链和 Fallback 责任。

1. 业务流程 AI 机会
📌 【是什么】以真实业务流程节点为单位评估 AI 价值、可验证性、错误代价与责任，不搞大而化之的全面 AI 化。
⚙️ 【怎么用】以具体业务节点为单位做可行性初筛，挑选痛点明显且验证成本低的场景作为试点。
🚨 【避坑红线】严禁从“AI 能做什么”出发倒找场景，没有明确验证手段和责任人的环节坚决不建。
2. 全流程 AI 介入层级选型
📌 【是什么】将 L5 单点判断迁移至整个部门业务链，逐环节选择最低足够介入层级，明确拒绝不该用的环节。
⚙️ 【怎么用】针对每个业务动作的错误代价与确定性，匹配最低且足够的介入程度。
🚨 【避坑红线】牢记 Anthropic 核心原则：“能用固定规则或简单方法搞定的，绝不引入多余的复杂性。”
3. Agent 范式选型图
📌 【是什么】在 Prompt、Workflow、ReAct、Plan & Execute、Routing、Evaluator-Optimizer 中选择最简单足够者。
⚙️ 【怎么用】根据任务是否需要先定计划、是否需要反复调查、是否需要多角色独立评审来匹配最优模式。
🚨 【避坑红线】单 Agent 足够时严禁盲目拆分多 Agent，避免增加系统通信混乱与失控面。
4. 三条通道各归其位 (三链隔离)
📌 【是什么】把“写代码的工具通道”、“业务系统的数据通道”和“大模型的调用通道”彻底切开的管理机制。
⚙️ 【怎么用】不同通道分配不同凭据、明确不同责任人，确保开发调试不会污染真实数据。
🚨 【避坑红线】严禁把三条链路的权限与账号混用，绝不能把开发工具的临时配置带入业务系统。
5. 兜底降级与责任归属 (Fallback)
📌 【是什么】当 AI 接口超时、算不出或置信度低时，系统自动切入备用规则或人工处理的保底方案。
⚙️ 【怎么用】设计 3 种标准降级路径（规则兜底 / 缓存兜底 / 人工兜底），并在界面明确打上降级标签与第一责任人。
🚨 【避坑红线】严禁“静默失败”或用假数据伪装成“AI 实时计算成功”欺瞒用户与下游。

常见误区 (Misconception) 正确硬核理解 (Correct Engineering Reality) 如何纠偏与护栏防护 (Remedy & Guardrails)
误区 1
"部门所有环节都应该用 AI"		 逐环节判断任务性质，能用规则的不用 AI；至少有一个不做的 树立正确工程意识，严格遵循护栏规范。

"多 Agent 比单 Agent 高级"		 多 Agent 是复杂度响应不是成熟度象征；单 Agent 足够时不拆 树立正确工程意识，严格遵循护栏规范。

"三链都是 API 分不清"		 开发工具链、业务 API 链和模型 API 链是三条不同的链，对象和责任不同 树立正确工程意识，严格遵循护栏规范。
误区 5
"选了 AI 就不用写 fallback"		 每个候选环节都必须写 fallback 来源和失败责任人 树立正确工程意识，严格遵循护栏规范。

2. 🎯 课后退场自测题 (Exit Ticket)

❓ 退出门禁题 1：AI 机会地图以什么为单位判断？为什么不以"部门想用 AI"为单位？
参考答案解析：
以真实业务流程节点为单位判断。不以"部门想用 AI"为单位，因为"部门想用 AI"是空泛的，逐环节判断才能落地——不同环节的任务性质、风险和可验证性不同，不能一刀切。
❓ 退出门禁题 2：AI 介入层级迁移有哪几个程度？为什么不是所有环节都选最高程度？
参考答案解析：
不用 AI/辅助/建议/单步执行/受控 Agent/受控闭环。不是所有环节都选最高程度，因为能用规则的不用 AI，能用 Workflow 的不用 Agent；最简单足够优先。
❓ 退出门禁题 3：Agent 范式选型的依据是什么？为什么多 Agent 不是成熟度象征？
参考答案解析：
依据路径是否确定、是否需动态调查、是否需规划。多 Agent 不是成熟度象征，是复杂度响应——单 Agent 足够时不拆，只有专业分工、并行或独立性确有价值时才采用。
❓ 退出门禁题 4：三链区分区分哪三条链？为什么 MCP 不等于业务 API？
参考答案解析：
开发工具链（开发用的工具）、业务 API 链（产品运行时调的业务接口）、模型 API 链（产品运行时调的 AI 模型）。MCP 是工具调用标准协议，不是业务接口。
❓ 退出门禁题 5：Fallback 来源与失败责任要求什么？为什么不能把 Mock 结果伪装成真实成功？
参考答案解析：
降级结果必须显示来源、原因、限制和 owner。不能伪装真实成功，因为这会导致决策者以为系统正常工作，实际是降级运行，可能产生错误判断。
三句话带走 (Key Takeaways)：
  1. 逐环节评估任务性质与风险，明确给出至少 1 个“不用 AI”的确定理由。
  2. 范式选型坚持最简单足够，单 Agent 足够时不拆多 Agent。
  3. 三链责任划分清，降级 Fallback 显式标来源，选出优先候选与明确不做项！
