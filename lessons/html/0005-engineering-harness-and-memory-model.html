Lesson 05 · 第一次把 AI/Agent 融入业务

第一次把 AI/Agent 融入业务

学员已有原型、业务契约和薄切片，才有资格判断某个业务环节是否值得加入 AI。课堂只选一个低风险、可验证、可降级的智能机会，不要求一开始就画完整部门 AI 蓝图。

🎯 本课目标：① 逐环节判断不用 AI、AI 辅助、固定 Workflow 或受控 Agent，选择最简单足够的方式；② 选择 Workflow、ReAct 或 Plan & Execute，并写出数据、工具、HITL、停止和降级；③ 在原型中模拟智能行为的正常与不确定/失败结果，明确标记"模拟"，由主管验收。

01 什么时候该用 AI，什么时候不该？

你已经有了原型、业务契约和薄切片——但到目前为止，所有业务逻辑都是确定性程序：点击按钮、筛选数据、显示结果。现在要回答一个新问题：哪些环节值得加入 AI，哪些不应该？

记住这句话：
这是课程中正式开始教授业务 AI/Agent 融入的节点。课堂只选一个低风险、可验证、可降级的智能机会，不要求一开始就画完整部门 AI 蓝图。

先用一个候选点理解"判断要不要 AI"和"选什么范式"，后面六课才在这个候选点上学习排错、验收、评审和部门级扩展。

03 核心概念卡：本课必须掌握的概念

本课必须掌握的核心概念 (点击展开详情)：

1. AI 介入层级
📌 是什么 / 不是什么：不用 AI、AI 辅助/建议、单步执行、受控 Agent 多步执行、低风险受控闭环是不同程度；不是只有"用 AI"和"不用 AI"两个选项，也不是程度越高越好。
⚙️ 怎样运作：逐环节判断任务性质和错误代价，选择最简单足够的程度；能用规则解决的不用 AI，能用 Workflow 的不用 Agent。
🧭 当课操作例子与边界：Task 2 对每个业务动作选择最低足够的介入层级；能用规则解决的不用 AI，风险和证据不足时保留人工接管。
💡 帮助理解的类比（可选）：像车间自动化程度：手工、工具辅助、单机自动、产线自动、无人闭环——程度越高越要卡质检和停机权限。不是程度越高越好。
2. 确定性任务与概率性任务
📌 是什么 / 不是什么：规则清晰、结果唯一的工作是确定性任务；开放判断、语言理解等结果是概率性任务；两者不能混为一谈，也不能用概率性方法处理确定性工作。
⚙️ 怎样运作：确定性任务优先用程序规则处理，比模型更可靠、更可审计；概率性任务才可能需要模型辅助，但必须有人工验证和降级路径。
🧭 当课操作例子与边界：Task 1 给每个动作标注当前处理方式；规则清晰且结果唯一的动作不交给概率性模型，开放判断才考虑模型辅助。
3. Workflow 与 Agent
📌 是什么 / 不是什么：Workflow 走预先定义的路径，每一步都确定；Agent 会根据观察动态决定下一步；不能把所有自动化都叫 Agent，也不能用 Agent 做规则就能解决的事。
⚙️ 怎样运作：Workflow 适合步骤固定、路径明确的任务；Agent 适合需要根据中间结果调整路线的任务；选择时先问"路径是否预先确定"，是则用 Workflow，否则才考虑 Agent。
🧭 当课操作例子与边界：Task 4 先问路径是否预先确定；固定步骤用 Workflow，需要根据中间结果调整才考虑 Agent，二者都不能替代责任边界。
💡 帮助理解的类比（可选）：像固定流水线（每步确定）和质检巡检（看异常决定下一步）：固定步骤走流水线，要看情况才用巡检。不能用巡检做规则就能解决的事。
4. ReAct
📌 是什么 / 不是什么：根据当前目标选择动作、调用工具、观察结果再调整的循环；适合调查和动态取证，不适合无边界高风险动作；不是万能循环，也不能替代固定流程。
⚙️ 怎样运作：Thought（思考下一步）→ Action（调用工具或执行动作）→ Observation（观察结果）→ 回到 Thought 调整或停止；每一步都有明确动作和可观察结果，不是盲目反复修改。
🧭 当课操作例子与边界：Task 4 若选择 ReAct，要写清 Thought→Action→Observation 的每一步、停止条件和可观察结果；不能把它当作无边界试错循环。
💡 帮助理解的类比（可选）：像医生问诊：先看症状（观察）→思考可能病因（思考）→开验血检查（调用工具）→看化验单（新观察）→确诊开药。每一步依据上一步反馈动态决定，不是给所有病人按同一套固定处方。
5. 人在回路授权门禁（HITL）
📌 是什么 / 不是什么：人在指定节点批准、纠正、接管或停止；不是最后看一眼，也不是一句文字承诺就自动形成硬控制。
⚙️ 怎样运作：在智能行为的关键节点设置人工检查点——批准后才继续、发现偏差时纠正、出错时接管、风险越界时停止；检查点必须指向具体节点，不是"做完后审一下"。
🧭 当课操作例子与边界：Task 4 在候选机会卡中写明具体 HITL 检查点：谁在什么节点批准、纠正、接管或停止；一句“人工审核”不算检查点。
💡 帮助理解的类比（可选）：像关键工序必须质检员签字才能放行，不是最后扫一眼。一句“人工审核”不算签字点。

05 学员实操 Task 1 ~ Task 5 自然口令卡

Task 1：把第四课薄片拆成具体业务动作
请读取我的第四课薄切片原型和 docs/PROJECT_STATE.md， 把这个薄切片拆成 4—6 个具体业务动作。 每个动作写清： 1. 动作名称 2. 使用者在做什么 3. 当前处理方式（人工 / 规则 / 已有程序） 4. 输入是什么 5. 输出是什么 先不要建议加 AI，只如实拆解和标注当前处理方式。 不要修改任何代码。
🎯 预期输出：AI 输出了 4—6 个具体业务动作，每个有当前处理方式标注，但没有修改代码。
Task 2：对每个动作做 AI 介入初筛
请对我在 Task 1 中拆解的每个业务动作做 AI 介入初筛。 对每个动作回答： 1. 有固定规则吗？（是/否） 2. 结果唯一吗？（是/否） 3. 错了能恢复吗？（是/否） 4. 建议层级：不用 AI / AI 辅助 / Workflow / 受控 Agent 5. 理由 6. 错误代价（错了会造成什么后果） 原则：能用规则解决的不用 AI，能用 Workflow 的不用 Agent。 最简单足够优先，不要追求最高自主程度。 先不要修改代码，只输出初筛表。
🎯 预期输出：AI 输出了一张初筛表，每个动作有层级判断、理由和错误代价，但没有修改代码。
Task 3：选一个低风险、可验证、能人工接管的候选
请从初筛结果中推荐一个最适合的候选机会。 这个候选必须同时满足： 1. 低风险：错了能恢复，不会造成不可逆后果 2. 可验证：有明确的标准判断结果对不对 3. 能人工接管：AI 失效时人能接手处理 只推荐一个，并说明： - 候选环节名称 - 为什么低风险 - 怎样验证结果 - 出了问题人能怎么接管
🎯 预期输出：AI 推荐了一个候选，并写明了低风险、可验证、能人工接管三项说明。
Task 3 收尾：写下你的拒绝理由（2 分钟）

本步目的：把你的判断写下来，变成可存档的证据。用两句话写下为什么你选的这个环节不能只用确定性规则，或者为什么你拒绝的环节不应该用 Agent。写下来贴在你的智能机会卡上。

你应该做：用两句话写下你的拒绝理由，贴在智能机会卡上。不是口头说——是写下来。

本步检查：写下了至少一条拒绝理由；理由基于任务性质和错误代价；是写下来而非口头表达。

必须停止：如果只写了选的理由没写拒绝理由，追问"你没选的那些为什么不用 AI"。

🎯 预期输出：在本地预览中观察并验收结果。
Task 4：选择范式并写智能机会卡
请帮我为这个候选机会选择范式并填写智能机会卡。 候选环节：【填写 Task 3 选定的候选】 请回答以下内容： 1. 范式选择：Workflow / ReAct / 增量实施范式（Plan & Execute） - 选择理由（路径是否预先确定？任务是否需要动态调查？） - 如果选 ReAct，说明 Thought → Action → Observation 循环如何运作 - 如果选 增量实施范式（Plan & Execute），说明与第四课的 增量实施范式（Plan & Execute） 有什么不同 2. 智能机会卡： - 数据：需要什么输入数据（标明 Mock 来源） - 工具：需要调用什么工具或读取什么信息 - HITL 检查点：在哪个具体节点需要人批准、纠正或停止 - 停止条件：什么情况下停止智能行为 - 降级条件：AI 不可用时降为什么方式 先不要修改代码，只输出范式选择和智能机会卡。
🎯 预期输出：AI 输出了范式选择理由和完整的智能机会卡，五项都有明确答案。
Task 5：在原型中模拟正常与不确定/失败结果
请在我的原型中模拟一个智能行为。 候选环节：【填写】 选择的范式：【填写】 智能机会卡内容：【填写或粘贴 Task 4 的智能机会卡】 要求： 1. 在原型中添加一个标记为"模拟AI"的智能行为组件 2. 模拟正常结果（智能行为正常运作时的表现） 3. 模拟至少一种不确定/失败结果（如输入不完整、数据异常时） 4. 所有模拟结果必须明确标注"模拟"，不冒充真实 AI 能力 5. 保持原业务路径仍可操作 6. 不连接真实模型、业务 API 或生产数据 完成后报告：实际修改文件、模拟了哪些结果、如何验收、来源标签是否清楚。
🎯 预期输出：原型中有一个标记"模拟"的智能行为，正常和至少一种不确定/失败结果可展示，原路径仍可操作。

2. 🎯 课后退场自测题 (Exit Ticket)

❓ 退出门禁题 1：AI 介入层级有哪几个程度？为什么不是所有任务都需要最高程度的 AI？
参考答案解析：
不用 AI、AI 辅助/建议、单步执行、受控 Agent 多步执行、低风险受控闭环是不同程度。不是所有任务都需要最高程度，因为能用规则解决的不用 AI，能用 Workflow 的不用 Agent；最简单足够优先。
❓ 退出门禁题 2：确定性任务和概率性任务有什么区别？各举一个你业务中的例子。
参考答案解析：
规则清晰、结果唯一的工作是确定性任务（如查列表、改状态）；开放判断、语言理解等结果是概率性任务（如建议处理方式、判断异常原因）。确定性任务优先用规则，概率性任务才可能需要模型，且必须有人工验证和降级路径。
❓ 退出门禁题 3：Workflow 和 Agent 有什么本质区别？为什么不能把所有自动化都叫 Agent？
参考答案解析：
Workflow 走预先定义的路径，每一步确定；Agent 根据观察动态决定下一步。不能把所有自动化都叫 Agent，因为有些任务路径固定，用 Workflow 更可靠可审计。
❓ 退出门禁题 4：ReAct 适合什么类型的任务？为什么不适合无边界高风险动作？
参考答案解析：
ReAct 适合调查和动态取证类任务——需要根据中间结果调整路线的场景。不适合无边界高风险动作，因为每一步的不确定性可能放大错误，且没有固定停止条件。
❓ 退出门禁题 5：HITL 的含义是什么？为什么"最后看一眼"不算真正的 HITL？
参考答案解析：
HITL 是人在指定节点批准、纠正、接管或停止。"最后看一眼"不算 HITL，因为它没有在关键节点形成控制——没有批准才能继续、没有纠正偏差、没有接管或停止的权力。
