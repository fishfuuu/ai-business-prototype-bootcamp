Lesson 01 · 从业务问题创建第一个系统页面

从业务问题创建第一个系统页面
理解 LLM、Tools、Agent 与三类业务原型

理解 LLM 大脑、Tools 手脚与 Agent 执行者的关系，用这套协作关系建立第一个受控业务原型。A/B/C 是三种业务启动分支，不是三版指南。

🎯 本课目标：学完你能做到 ① 用工程语言向 IT 部门说出 Agent 与普通聊天机器人的物理区别；② 准确画出“思考 ➔ 行动 ➔ 观察 ➔ HITL盖章”循环；③ 在 90 分钟内跑出第一个受控业务原型雏形。

01 为什么要从这一课开始？

作为业务主管，你掌握 AI Agent 的核心目标是：用自然语言指挥 Agent 帮你快速生成高保真原型，并在无需写底层代码的前提下实现 IT 高效交接。

记住这句话：
Agent 不是更聪明的大语言模型（LLM），而是给大语言模型装上了“手脚和眼睛”（Tools），并嵌入了“工程防错护栏与公章门禁”（Workflow & HITL）。

先想清楚这台“自动化机器”的物理构造，你才能在后续课程中放心指挥它干活，而不必担心它出现白屏、死循环或篡改未授权的代码。

02 核心概念卡：本课必须掌握的概念

本课必须掌握的核心概念 (点击展开详情)：

1. 大语言模型（LLM）：大脑
📌 是什么 / 不是什么：根据当前信息生成文字、方案或代码内容的概率模型；不是能直接操作电脑的完整 Agent，也不是天然了解部门事实的业务专家。
⚙️ 怎样运作：根据 Prompt 与当前上下文生成候选内容；内容听起来合理，也可能遗漏或猜错事实。
🧭 当课操作例子与边界：Task 1 只让模型复述和规划；输出听起来合理不等于业务事实已核对，更不等于页面已经生成。
👁️ 今天怎样看见：Task 1 只让它复述和规划。主管应核对它是否真正理解了业务。
2. Tools：手脚
📌 是什么 / 不是什么：读取文件、修改项目、运行命令或取得结果的具体能力；不是 LLM 本身，也不代表权限无限或绝对安全。
⚙️ 怎样运作：Agent 请求调用工具，宿主环境实际执行，再把读取结果、运行输出或错误返回给模型。
🧭 当课操作例子与边界：Task 2 看真实读取结果，Task 3 看实际修改与运行；工具能做什么取决于授权范围，调用成功也不等于业务正确。
👁️ 今天怎样看见：Task 2 看真实读取结果，Task 3 看实际修改与运行。主管应问清读了什么、改了什么。
3. AI Agent（Agent）
📌 是什么 / 不是什么：把 LLM、当前信息和 Tools 组织起来，为一个目标完成多步工作的系统；不是永远正确、能够自行承担业务责任的数字员工。
⚙️ 怎样运作：接收目标，推演下一步，调用工具，观察结果，再继续、调整、停止或请求人工处理。
🧭 当课操作例子与边界：Task 1—4 组成一次完整制作过程；Agent 负责执行和反馈，主管仍负责目标、范围、授权和验收。
👁️ 今天怎样看见：Task 1—4 组成一次完整制作过程。开发 Agent 负责执行，主管负责目标、范围和验收。
4. 业务原型：样板间
📌 是什么 / 不是什么：用来验证业务路径、交互和需求表达的可操作模型；不是生产系统，也不代表全部需求已经完成。
⚙️ 怎样运作：用 Mock/已脱敏数据呈现一个使用者如何完成一件事，再由主管判断路径是否正确。
🧭 当课操作例子与边界：Task 4 的本地页面只证明一条个人业务路径在 Mock/脱敏数据下可操作；未实现和未验证部分要明确列出。
👁️ 今天怎样看见：你最终完成的一条个人业务路径，并能够说明哪些已经验证、哪些仍未实现。

04 三类业务原型选型（选择你的战场）

Task 1：只让 LLM 理解和推演
我要创建一个“A类：监控与决策型”业务原型。 我的业务输入： - 原型名称：【填写】 - 主要使用者：【填写】 - 关注的业务对象：【填写】 - 使用场景或触发条件：【填写】 - 需要看到的状态、指标或异常：【填写】 - 看到异常后要完成的一项动作：【填写】 - 希望看到的最终结果：【填写】 - 本轮明确不做：【填写】 请先不要读取项目文件，不要调用修改或运行工具，也不要创建任何文件。 请只完成以下内容： 1. 用业务语言复述使用者、场景、核心动作和结果； 2. 提出一条最小路径：查看状态或指标 → 发现对象 → 查看相关信息 → 记录一个判断或后续动作 → 显示结果； 3. 指出仍不确定、需要我确认的内容； 4. 列出本轮明确不做的内容。 不要假装已经看过项目结构，也不要自行补充真实业务事实。
🎯 预期输出：模型复述了你的业务、提出一条最小路径，并标出不确定信息，但没有声称已经看过项目。
Task 2：让 Tools 读取项目事实
现在请只读取完成本课原型所需的最小项目资料，不要创建或修改文件。 优先确认并读取：项目根目录说明或约束文件、DESIGN.md、 docs/COMPONENT_CATALOG.md、实际路由入口、实际布局或页面入口（存在时）。 要求： 1. 文件不存在就明确报告，不要编造； 2. 告诉我真实技术栈、可复用组件和页面入口； 3. 根据读取结果修订最小路径； 4. 列出拟创建或修改的文件及必要性； 5. 一个页面能完成就不要拆分； 6. 本步只读取和汇报，不创建、修改或运行项目。
🎯 预期输出：真实读取结果、存在与不存在的文件、可复用内容、修订后的路径和拟修改文件清单。
Task 3：主管裁决范围，让 Agent 实施
根据你的复述和项目读取结果，我确认本轮范围如下： 1. 必须完成的一条核心业务路径：【填写】 2. 必须保留的业务字段、状态或规则：【填写】 3. 本轮明确不做：【填写】 4. 允许修改的项目范围：【确认或删减 Agent 的真实文件清单】 5. 我的点击验收方法：【填写】 请先复述实施范围并指出矛盾或缺失。在我确认复述无误前，不要实施。
🎯 预期输出：Agent 只在确认范围内实施；原型可以打开，并至少发生一次可观察的点击、输入输出或状态变化。
Task 4：观察结果并只修一个问题
我在本地预览中发现一个最需要修正的问题：【填写】 请先说明问题原因、准备修改的内容，以及哪些已确认业务内容不会改变。 等我确认后只修这一项。完成后重新说明预览和验收方法，并如实报告 实际运行过的工程检查；不要声称不存在或未运行的脚本已经通过。
🎯 预期输出：Agent 先说明修改边界，只修这一项；重新预览后，问题得到改善且原业务路径仍可操作。这就是 ReAct 的入门体验。

2. 🎯 课后退场自测题 (Exit Ticket)

❓ 退出门禁题 1：LLM 根据当前输入和上下文生成候选内容，本质上属于具有不确定性的什么模型？
参考答案解析：
概率生成（或概率预测）模型。LLM 生成候选内容不是查表，而是基于上下文做概率预测。
❓ 退出门禁题 2：当 Agent 读取文件或运行命令时，真正执行外部动作的是宿主环境提供的什么？
参考答案解析：
Tools / 工具调用接口。宿主环境通过 Tools 让 Agent 读取、修改、运行并取得外部结果。
❓ 退出门禁题 3：实施前，主管应确认核心路径、修改范围和什么？这种确认不自动等于运行时硬门禁。
参考答案解析：
本轮明确不做的内容（非目标或停止范围）。主管确认的是范围与边界，不等于自动形成运行时硬门禁。
❓ 退出门禁题 4：如果 Agent 声称某项检查 [PASS]，你至少应看到真实的什么和什么？
参考答案解析：
实际运行的命令；对应的真实输出或日志。没有真实命令与输出，[PASS] 只是口头宣称。
❓ 退出门禁题 5：如果 Agent 在 Task 1 就修改了项目文件，它违反了什么阶段边界？你接下来怎样处理？
参考答案解析：
违反 Task 1"只推演、不使用项目工具"的边界。立即停止，要求 Agent 列出真实动作和改动，请教师根据实际状态决定恢复或继续。

06 本课小结 + 知识扩充 + 下一步

三句话带走 (Key Takeaways)：
  1. AI Agent = 模型（大脑）+ 工具（手脚）+ 循环（流程）+ HITL（公章门禁）。
  2. ReAct 循环 = 思考 ➔ 行动 ➔ 观察 ➔ 盖章，反复迭代直到完成；“观察 Observation”让 Agent 用真实编译与日志数据说话，不凭空捏造。
  3. 能固定的常规任务用自动化脚本，需要灵活决策与原型制作的任务才用 Agent。
