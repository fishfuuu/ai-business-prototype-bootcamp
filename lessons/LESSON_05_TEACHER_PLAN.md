# 第五课教师教案——第一次把 AI/Agent 融入业务

> **核心思想：不是给每个环节都塞 AI，而是逐环节判断需要什么程度的智能，并选择最简单足够的方式。**

## 一、课程元数据与定位

| 项目 | 本课设定 |
| --- | --- |
| 学员 | 已完成第四课、掌握可验证薄切片候选与两阶段版本记录的业务主管 |
| 时长 | 90 分钟硬上限：85 分钟主线 + 5 分钟机动 |
| 课堂主成果 | 智能机会卡 + 原型智能薄片 V1：记录候选环节、选择层级与范式、需要的数据/工具、人工确认、停止/降级条件，并在原型中模拟正常和至少一种不确定/失败结果 |
| 主管判断成果 | 写下了至少一条拒绝理由（基于任务性质和错误代价），而非仅靠巡视时口头抽查；范式与任务性质匹配 |
| 支撑成果 | `docs/PROJECT_STATE.md` 更新智能机会候选状态，只作跨课交接 |
| 数据边界 | 只使用 Mock 或已脱敏数据；不连接真实模型、业务 API 或生产数据 |
| 正式业务 AI 起点 | 本课正式开始，并且从此持续；但判断仍是"候选机会"，不是部门永久结论 |

本课用同一个个人原型串起两条学习线：原型线要求"在现有业务薄片中加入一个明确标记为 Mock/模拟的智能行为，保持原路径可操作"，主管线要求"逐环节判断不用 AI、AI 辅助、固定 Workflow 或受控 Agent，并选择最简单足够的方式"。两条线分别验收，不能相互抵分。

本课不做：对全部门流程完成 AI 选型、连接真实模型/业务 API/生产数据、追求自主程度最高。

开场必须先制造一个可见区别：给每个环节都塞 AI 导致混乱失控 vs 逐环节判断选最简单足够的方式。先让学员看见"不是所有环节都需要 AI"的价值，再解释五个概念。

## 二、逆向目标、证据与核心概念

### 2.1 目标—活动—证据

| 学习目标 | 课堂活动 | 通过证据 |
| --- | --- | --- |
| 学员能把第四课薄切片拆成具体业务动作，并标注当前处理方式 | Task 1 业务动作拆解 | 4—6 个具体业务动作，每个有当前处理方式标注 |
| 学员能对每个动作做 AI 介入初筛，说明理由与错误代价 | Task 2 逐项初筛 | 每个动作有层级判断、理由和错误代价说明 |
| 学员能选一个低风险、可验证、能人工接管的候选机会 | Task 3 候选选择 | 一个候选，符合低风险/可验证/可接管三项标准；学员写下了至少一条拒绝理由，说明为什么所选环节不能只用确定性规则（或为什么被拒绝的环节不应使用 Agent），理由基于任务性质 |
| 学员能选择范式并写出数据、工具、HITL、停止和降级条件 | Task 4 智能机会卡 | 智能机会卡五项完整，范式与任务性质匹配 |
| 学员能在原型中模拟正常与不确定/失败结果，标记"模拟" | Task 5 原型模拟 | 正常和至少一种不确定/失败结果可展示，来源标签清楚 |

概念分层：核心概念为 AI 介入层级、确定性任务与概率性任务、Workflow 与 Agent、ReAct、HITL；扩展认识为 增量实施范式（Plan & Execute） 迁移比较、Guardrail/护栏。智能机会卡、Mock 数据、prototypeState 调试器在实操中使用但不升级为核心概念。安全红线横向管理，不占概念名额。

### 2.2 四步概念解析公式（三段实战化设计）

#### AI 介入层级

1. **是什么**：任务接入 AI 的自治度梯度（不用 AI、辅助建议、固定流程、受控多步决策、低风险闭环）。
2. **怎么用**：针对每个环节的错误代价与确定性，选择“最低且足够”的介入程度，把风险与成本控制在最低。
3. **避坑红线**：牢记 Anthropic 核心原则：“能用固定规则或简单方法搞定的，绝不引入多余的复杂性。”
4. **交接价值**：回指 Task 2——逐环节选择最低足够的 AI 介入层级。

#### 确定性任务与概率性任务

1. **是什么**：规则清晰、结果唯一的是“确定性任务”；开放发散、语义理解的是“概率性任务”。
2. **怎么用**：确定性任务坚决用程序规则与代码固化；概率性任务才引入大模型辅助，并配备人工校对。
3. **避坑红线**：严禁把确定性计算交给大模型盲猜，绝不能用概率方法处理严密逻辑。
4. **交接价值**：回指 Task 1——给每个业务动作标注确定性还是概率性。

#### Workflow 与 Agent（判定黄金法则）

1. **是什么**：Workflow 走预先固定的步骤流水线；Agent 则根据中间结果动态决定下一步行动。
2. **怎么用**：步骤固定、流程标准的事项坚决建 Workflow；只有需要根据现场情况灵活应变的事项才考虑 Agent。
3. **避坑红线**：严禁盲目追求“全自动 Agent”，能用固定流程解决的问题绝不要引入多余的动态循环。
4. **交接价值**：回指 Task 4——路径固定用 Workflow，需动态调整才考虑 Agent。

#### ReAct 循环

1. **是什么**：AI 在“思考（Thought）→ 行动（Action）→ 观察（Observation）”之间不断循环的工作机制。
2. **怎么用**：用于需要边调查、边尝试、边根据反馈调整方向的探索性任务。
3. **避坑红线**：严禁放任无休止的循环试错，必须设置明确的最大尝试次数与主动停止条件。
4. **交接价值**：回指 Task 4——ReAct 循环必须具备可观察的停止条件。

#### 人在回路授权门禁（HITL）

1. **是什么**：在自动化流程的关键卡点上，由人工进行确认、纠偏、接管或叫停的责任门禁。
2. **怎么用**：在权限越界前（资金/高危）、方案落地前（契约终审）、异常失控时（连续排错失败）设置人工门禁。
3. **避坑红线**：严禁把“事后口头问一句”当成门禁；必须指向具体拦截节点与明确的责任签字人。
4. **交接价值**：回指 Task 4——HITL 必须落实到具体岗位与审批动作。

### 2.3 扩展认识概念卡

#### 增量实施范式（Plan & Execute） 迁移比较（认识级）

与 ReAct 对比，判断何时先固定计划、何时允许局部动态循环。第四课的 增量实施范式（Plan & Execute） 是"先出施工图确认每步改哪里再执行"，适合目标明确但步骤多的任务；ReAct 是"边观察边调整"，适合路径不确定需要动态取证的任务。教师用 2—4 分钟对比，不设独立通过门槛。

#### Guardrail/护栏（认识级）

文字指导、流程门禁和运行时拦截强度不同；本课只要求认识层级，不要求配置护栏。

讲解时直接沿 Task 1—4 的真实动作讲五张核心卡：先区分确定性和概率性动作，再选择介入层级、记录候选机会、选择范式并写明 HITL 检查点。总计控制在 10 分钟左右；不要逐字朗读。

## 三、教学准备与安全边界

### 课前预检

- 第四课薄切片可用：学员已有可验证薄切片候选，本地预览中原型可操作。
- `docs/PROJECT_STATE.md` 有薄切片候选状态和处置记录。
- Working Tree 处于 Clean 状态：教师演示前先 `git status` 确认。
- 开发服务器可启动：双击 `start-project.bat` 或运行 `npm run dev`，本地预览 `http://127.0.0.1:8888/` 可访问。
- 助教理解环境问题 3 分钟接管规则，知道学员选了高风险候选时的现场处置方式。

### 实操前只讲四条红线

1. 只用 Mock/已脱敏数据，不输入真实资料、密钥、Token 或账号。
2. 不连接真实模型、业务 API 或生产数据；模拟结果必须明确标记"模拟"，不冒充真实 AI 能力。
3. 不追求自主程度最高；能满足需求的最简单方式优先——能用规则的不用 AI，能用 Workflow 的不用 Agent。
4. 文字要求和主管确认是工作约束，不冒充 Workflow/HITL、沙箱或运行时硬控制。

教师不得虚构 `verify-project.ps1`、真实模型连接等课堂能力。实际运行什么，就展示什么证据。

## 四、90 分钟控场主线

| 时间 | 宏观阶段 | 教师动作 | 学员动作 | 阶段证据 |
| --- | --- | --- | --- | --- |
| 0—10 分 | **看见区别，建立模型** | 对比"给每个环节都塞 AI"vs"逐环节判断选最简单足够的方式"；用 Task 1—4 动作链和融合图讲五个概念 | 回顾第四课薄切片，能指出确定性和概率性动作的区别 | 知道本课成果与五者关系 |
| 10—25 分 | **教师完整示范** | 用统一案例串演 Task 1—5，只演方法，不让学员复现 | 观察"拆动作→初筛→选候选→写机会卡→模拟"的完整动作 | 建立整体动作锚点 |
| 25—35 分 | **概念核对与准备** | 提问核对五张概念卡；确认 Working Tree Clean 和原型可操作 | 口头回答卡片；完成环境检查和薄切片回顾 | 概念理解和环境就绪 |

| 80—90 分 | **验收与闭合** | 指导主管验收模拟结果；检查通过证据；收取随堂题 | 主管验收、核对范式匹配与来源标签、核对证据与答案 | 原型线和主管线分别判定 |

压缩顺序：先取消个别展示，再压缩教师示范；如果概念讲解超过 25 分钟，扩展概念（增量实施范式迁移比较、护栏）降为一句话认识级，保证学员实操有完整 45 分钟；不得删除候选选择、范式决策或原型模拟；写下拒绝理由与候选选择绑定，不可单独删除。5 道必答题分散在相应 Task 后完成，最后只检查提交。

## 五、逐 Task 示范、口令、巡视与降级

教师统一案例走一条主路径（工单看板），同时在巡视时针对三类业务原型（A.监控决策型、B.任务流程型、C.操作工具型）提供对应的业务动作链、初筛与拒绝标杆：

* **A. 监控与决策型（如 ROI 看板/履约预警）**：`1. 聚合多渠道消耗与业绩数据(规则)` → `2. 计算 ROI 并触发预警标红(规则)` → `3. [重点] 异动归因诊断分析(AI辅助/概率性)` → `4. [重点] 起草止损与调优策略建议(AI辅助+HITL)` → `5. 主管确认下发/锁定预算(规则)`。
* **B. 任务与流程型（如 工单看板/退款审批）**：`1. 查看工单列表(规则)` → `2. 打开工单详情(规则)` → `3. [重点] 提炼非结构化诉求与异常信息(AI辅助)` → `4. [重点] 起草处置方案与回复话术(AI辅助+HITL)` → `5. 改变工单状态(规则)`。
* **C. 操作工具型（如 营销文案生成/数据清洗）**：`1. 输入原始素材与目标参数(规则)` → `2. 参数校验与硬规则过滤(规则)` → `3. [重点] 批量发散生成多风格版本(AI/概率性)` → `4. [重点] 语义合规与质量初筛(AI/概率性)` → `5. 主管挑选润色并导出(人工)`。

每个 Task 均按以下四项执教：

### Task 1：把第四课薄片拆成具体业务动作

- **教师示范**："先别想 AI，先把你的薄切片拆成 4—6 个具体业务动作——使用者每一步在做什么、当前是人工做还是规则做。"展示如何把工单看板薄切片拆成"查看列表→打开详情→查看信息→记录决定→改变状态"五个动作，并标注当前处理方式。
- **教师口令**："把你的第四课薄切片拆成 4—6 个具体业务动作。每个动作写清：动作名称、使用者在做什么、当前处理方式（人工/规则/已有程序）、输入和输出。根据你的原型类型（A类监控看板 / B类任务流程 / C类操作工具）拆解出完整的**业务决策闭环**，严禁只拆解点击、筛选、数学计算等纯 UI 步骤。先不要建议加 AI，只如实拆解和标注。"
- **巡视判断**：动作是否具体到业务层面而非技术步骤；是否每个动作都标注了当前处理方式；是否拆得太碎（技术碎片如“点击下拉框”）或太粗（多个动作合一）。特别注意 A 类（监控/看板类）学员：是否把动作链延伸到了“看异常后的归因推断与策略建议”，若只拆到“算数画图”必须立即纠偏。
- **失败降级**：拆得太碎时合并为有业务意义的动作；拆得太粗时追问"这一步里使用者具体做了什么"；A 类学员只写了看数据时，追问“指标异常了之后，业务主管下一步要分析什么、做什么决定”；学员开始想 AI 方案时提醒"先标注现状，不急着想 AI"。

### Task 2：对每个动作做 AI 介入初筛

- **教师示范**："对每个动作问三个问题：有固定规则吗？结果唯一吗？错了能恢复吗？"展示如何用工单案例做初筛——"查看列表"有固定规则且结果唯一→不用 AI；"查看异常信息"需要理解自然语言→AI 辅助；"记录处理决定"需要开放判断→AI 辅助但人确认。强调"最简单足够"原则。
- **教师口令**：下发初筛提示词模板（见学员指南 Task 2）。对每个动作判断：不用 AI/AI 辅助/Workflow/受控 Agent，写理由和错误代价。
- **巡视判断**：理由是否基于任务性质（确定性/概率性）；是否考虑了错误代价；是否遵循"最简单足够"原则；是否所有动作都选了 Agent（过度自动化）；A 类学员是否把严密数学计算（如算 ROI）正确判定为“不用 AI”，把异常归因与策略建议判定为“AI 辅助”。
- **失败降级**：学员想给每个环节都加 AI 时，回到"这个动作有固定规则吗？结果唯一吗？"；不确定选什么时先从"不用 AI"开始排除；选了受控 Agent 时追问"为什么 Workflow 不够"。

### Task 3：选一个低风险、可验证、能人工接管的候选

- **教师示范**："从你的初筛结果中选一个候选——它必须是低风险、结果可验证、能人工接管的。"展示如何选择"AI 辅助建议处理方式"：低风险（建议错了人可以否决）、可验证（建议是否合理一看就知道）、能人工接管（AI 不建议时人自己判断）。
- **教师口令**："从初筛结果中选一个候选机会。写明：候选环节、为什么低风险、怎样验证结果、出了问题人能怎么接管。只选一个。"
- **巡视判断**：候选是否符合低风险（错了能恢复）；是否可验证（有明确的对错判断方式）；是否能人工接管（AI 失效时人能接手）；是否只选了一个。三类典型推荐候选：
  - **A 类**：异动归因分析与调优策略起草（分析错了主管一眼看出，不自动调预算）。
  - **B 类**：诉求提炼与处理方案建议（建议不妥人工可修改，不自动发外部）。
  - **C 类**：多版本文案生成与合规初筛（生成不满意可重新生成或人工改写）。
  学员还需完成 Task 3 收尾的拒绝理由写作才能通过本 Task——见 Task 3 收尾巡视判断。
- **失败降级**：选了高风险不可逆的候选时（如自动扣款、自动调投放预算），提醒换一个"错了能恢复"的；无法验证结果时，选一个有明确通过/不通过标准的；选了多个时缩到一个。

### Task 3 收尾：写下你的拒绝理由（2 分钟）

- **教师口令**：用两句话写下你拒绝其他候选的理由——为什么你选的这个环节不能只用确定性规则（或反过来，为什么被你拒绝的环节不应该用 Agent）。写下来，不是口头说。写完后贴在你的智能机会卡上。
- **巡视判断**：学员写下了至少一条拒绝理由；理由基于任务性质（确定性/概率性）和错误代价，不是"觉得不需要"；是写下来而非口头表达。三类标杆拒绝理由：
  - **A 类标杆**：*“拒绝在 ROI 计算中使用 AI，因为 ROI 是严密数学公式，属于确定性计算，大模型存在幻觉且成本高；选择在归因分析中使用 AI，因为多维指标交叉波动的原因分析属于开放概率性推断，规则无法穷尽。”*
  - **B 类标杆**：*“拒绝在工单状态流转中使用 Agent 全自动闭环，因为状态流转涉及业务责任确权，误判代价高，必须用固定状态机；选择在诉求提炼中使用 AI 辅助，因为客户口语化表达属于非结构化语言理解。”*
  - **C 类标杆**：*“拒绝在参数校验与违禁词过滤中使用 AI，因为黑名单与格式校验属于确定性布尔逻辑，正则与字典匹配更快更准；选择在文案生成中使用 AI，因为创意发散属于概率性生成。”*
- **失败降级**：只写了选的理由没写拒绝理由时，追问"你没选的那些为什么不用 AI"；理由不基于任务性质时，回指"这个动作有固定规则吗？结果唯一吗？"。

### Task 4：选择范式并写智能机会卡

- **教师示范**："现在选范式并写智能机会卡。"展示如何为"AI 辅助建议处理方式"选择 ReAct 范式（读取工单内容→提取关键信息→生成建议→人工确认），并填写智能机会卡：数据（工单内容 Mock）、工具（读取工单详情）、HITL（生成建议后人工确认才显示）、停止（工单内容为空时停止）、降级（AI 建议不可用时降为人工判断）。
- **教师口令**：下发智能机会卡提示词模板（见学员指南 Task 4）。选择 Workflow/ReAct/增量实施范式（Plan & Execute），并写清数据、工具、HITL 检查点、停止条件、降级条件。
- **巡视判断**：范式是否与任务性质匹配（A类看板推荐 Workflow 或单步 ReAct，B类流程推荐 ReAct，C类工具推荐 Workflow）；智能机会卡五项是否完整；HITL 是否指向具体节点而非"最后看一眼"（如 A 类严禁自动修改投放预算，必须由主管勾选确认）；停止和降级条件是否可执行。
- **失败降级**：范式与任务不匹配时重新检查确定性/概率性；HITL 太模糊时追问"在哪个动作后需要人确认"；缺少停止/降级条件时必须补写；选了 增量实施范式（Plan & Execute） 时追问"与第四课的 增量实施范式（Plan & Execute） 有什么不同"。

### Task 5：在原型中模拟正常与不确定/失败结果

- **教师示范**："现在在原型中模拟这个智能行为。"展示如何添加一个"模拟AI建议"组件：当用户查看工单详情时，显示一个标注"模拟AI建议"的建议框。展示正常结果（建议合理）和不确定结果（工单内容不完整时建议为空或不确定）。强调所有模拟结果必须标记"模拟"。主管验收：范式匹配吗？来源标签清楚吗？原路径还能操作吗？
- **教师口令**：下发原型模拟提示词模板（见学员指南 Task 5）。在原型中模拟正常和至少一种不确定/失败结果，所有模拟结果标记"模拟"。
- **巡视判断**：组件形态是否符合业务原型交互习惯（A 类看板推荐右侧抽屉/浮层【AI 异常归因与策略建议卡】；B 类流程推荐详情右侧【AI 处置助理】；C 类工具推荐右侧【AI 生成与合规审查比对区】）；模拟结果是否标记"模拟"；是否展示了正常和至少一种不确定/失败结果；Mock 是否冒充真实 AI；原业务路径是否仍可操作；主管是否做了验收。
- **失败降级**：只有正常结果时补展示不确定/失败场景；Mock 被当作真实 AI 时立即标记"模拟"；原路径失效时先修复路径再模拟；主管未验收时补做验收。

## 六、现场 Debug 与降级预案

| 问题类型 | 教师处置 | 禁止说法 |
| --- | --- | --- |
| A类学员拆解停留在UI与计算层，导致初筛全选“不用AI” | 引导学员跳出纯看数视角，追问：“看到 ROI 暴跌后，业务主管在脑中如何归因？接下来要拟定什么策略？”，将动作链延伸到“归因推断”与“策略起草” | “看板就是不能加 AI 的” 或 “让大模型帮你算 ROI” |
| 学员想给每个环节都加 AI | 回到"最简单足够"原则，先问"这个动作有固定规则吗？结果唯一吗？" | "AI 肯定比规则好" |
| 范式与任务性质不匹配 | 重新检查确定性/概率性，重选范式；路径确定用 Workflow，需动态调查用 ReAct | "Agent 总比 Workflow 高级" |
| 模拟结果被当作真实 AI 能力 | 立即标记"模拟"，强调来源标签；主管验收时核对标签 | "这就是 AI 的能力" |
| 停止/降级条件缺失 | 必须补写；不能只有正常路径，必须写出什么时候停、怎么降级 | "先跑起来再说" |
| 选了高风险不可逆的候选 | 换一个低风险、可验证、能人工接管的候选（如 A 类严禁自动改投放预算 API，必须设主管确认门禁） | "高风险才有价值" |

## 七、随堂测试、通过标准与课后任务

### 两条线分别通过

- **原型线**：原型中有一个明确标记"模拟"的智能行为；正常和至少一种不确定/失败结果可展示；原业务路径仍可操作。
- **主管线**：写下了至少一条拒绝理由（基于任务性质和错误代价），而非仅靠巡视时口头抽查；范式与任务性质匹配；数据、工具、HITL、停止和降级均有明确答案；模拟结果有来源标签，不把 Mock 冒充真实 AI。
- `PROJECT_STATE.md` 只作交接，不能抵消任何一条主线的未通过。

### 必答题（5 题）

1. AI 介入层级有哪几个程度？为什么不是所有任务都需要最高程度的 AI？
2. 确定性任务和概率性任务有什么区别？各举一个你业务中的例子。
3. Workflow 和 Agent 有什么本质区别？为什么不能把所有自动化都叫 Agent？
4. ReAct 适合什么类型的任务？为什么不适合无边界高风险动作？
5. HITL 的含义是什么？为什么"最后看一眼"不算真正的 HITL？

参考要点：不用 AI/AI 辅助/单步/受控 Agent/低风险闭环，最简单足够优先；规则清晰结果唯一是确定性，开放判断语言理解是概率性；Workflow 固定路径，Agent 动态决策；适合调查取证，不适合无边界高风险；指定节点批准纠正接管停止，不是最后看一眼。

### 拓展题（选做，2 题）

1. 用 增量实施范式（Plan & Execute） 和 ReAct 对比，判断何时先固定计划、何时允许局部动态循环。
2. Guardrail 的三个层级（文字指导、流程门禁、运行时拦截）强度有什么不同？本课只要求认识哪一层？

### 课后任务

10—15 分钟：在 `PROJECT_STATE.md` 中补齐智能机会候选状态和下一课输入说明。不继续开发功能；第六课会在智能薄片或普通薄片上找一个预置故障完成诊断。
